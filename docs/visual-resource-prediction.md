# 视觉资源自动预测与预读设计

[文档目录](README.md) · [引擎架构](engine-architecture.md) · [引擎性能验证](next-release-performance.md)

视觉小说最常见的卡顿来自“点下鼠标切背景/换表情的一瞬间才开始读盘解码”。本文档说明 Reel 如何在**不要求作者手写预加载指令**的前提下，通过编译期静态分析与运行期队列协同，在玩家读上一句台词的空档提前准备好下一幅画面。

> 现行运行时总契约以[引擎架构](engine-architecture.md)为准。设计过程中参考了 [Shin 图层加载](https://github.com/DCNick3/shin/blob/2405086f8a1d319c9df3605df38a4f0a6379a42d/shin/src/adv/command/layerload.rs#L135-L228)、[Shin 立绘](https://github.com/DCNick3/shin/blob/2405086f8a1d319c9df3605df38a4f0a6379a42d/shin/src/asset/bustup.rs#L87-L110) 以及 [Ren’Py 图片预测](https://www.renpy.org/doc/html/config.html#var-config.predict_statements)。与 Ren’Py 在玩家端运行时沿控制流搜图不同，Reel 将可提取的资源引用提前沉淀到构建产物中，避免每次剧情推进都消耗玩家端 CPU。

## 一、预测信息从哪来

### 1. 构建期提取剧情图片计划
构建游戏（开发运行与发行导出共用同一分析）时，Aside 仅提供通用的函数、基本块、常量和调用信息，由 **Reel 构建层** 理解 `image`、`layered_image` 与控件皮肤语义，并将静态可确定的图片计划写入 ASB 产物：

- **可穿透的常见写法**：含 `tr()` 翻译的对白、捕获了已知值的 `stage.transition` 回调、普通辅助函数转发、按键读取局部表，以及经验证为**只读的模块素材目录**（支持索引、`get`、`has_own`，跨导入和重导出指向同一目录）。
- **类型约束实例**：只有当已链接的全部可能接收者指向同一方法，或字段具有同一类型约束时才继续追踪。
- **保守降级**：一旦遇到写入、可变引用逃逸、无法确定的动态分派或超出分析预算，直接停止预测并在真正显示时按需加载，不影响正确性。

### 2. 计划体积与边界控制
- 按“可能挂起的调用位置”索引资源组合（不可等待的调用无需生成续接候选），相同的图层组合共享资源表并复用程序内字符串常量。
- 整个计划上限为 **1 MiB**；素材目录与类型分析各自使用独立构建额度，耗尽时仍从剩余调用处提取可确定图片。
- 遇到普通函数返回时继续沿外层调用位置查找；只预取已知路径上**最近的一组画面**。分支指向同一张图时可以预取，其余分支等路线选定后再加载。
- 预读只准备图片资源，**绝不提前执行**台词、随机数、存档、音频或页面构造等副作用。

## 二、菜单、内存额度与快进协同

### 1. 界面控件的候选资源
- **按钮与状态皮肤**：直接从 `image_skin` 读取悬停、焦点和按下状态用图。
- **导航与页面栈**：导航项获焦或指向时，读取目标页面构造函数里静态可确定的首屏素材；已挂载的隐藏模态菜单利用空闲容量准备打开后将显示的素材（普通未解锁图库等无法判断打开时机，不盲目预读）。
- **虚拟列表**：沿视口位置与滚动方向预备即将滚入的行。

### 2. 运行期队列与取消规则
- 候选图片以**低优先级**送入既有资源队列，使用独立预取份额，前台可见图片与媒体始终优先；复用当前平台、语言和资源版本下已在途或已驻留的图层。
- 命中预读时由可见请求直接接管；未命中时无缝退回正常加载与呈现。首版预读覆盖读取与解码，GPU 上传单独计时。
- **快进 / 改道 / 读档即时撤销**：连续快进时新位置直接替换尚未开始的旧预取；分支改道、关闭页面或读档时立即撤回失效请求，读档从恢复点重新计算候选。

## 三、对照验收方法

使用代表性真实场景校验两条路径（自动预读 vs 运行时动态按需加载）：以 DDLC 的背景切换、首次立绘与换表情验证剧情路径，以 Euphoria 设置页与海猫历史界面验证首次打开、重开与滚动。

验收在同一发行播放器中**交替开启与关闭内部预测**（输入和演出时长严格一致），覆盖首次换图、热缓存重放、连续快进和选项改道（冷读波动另用受控读取延迟单独复现），记录以下指标：
1. 换图指令到首次提交的延迟、当前对白或动画的帧间隔；
2. 实际读取字节、解码耗时、丢弃字节与内存峰值；
3. 构建耗时与包体增量。

验收标准：在静态可预测场景下尽量逼近手写预载的“换图时零读取、零解码”，同时不在上一句台词处引入新的帧时间尖峰；预测失败、素材缺失与读档恢复保持原有错误诊断与游戏状态语义。
