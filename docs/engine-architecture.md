# Reel 引擎架构

本文定义模块职责和跨模块行为。语言语义见 [Aside 规范](aside-language.md)，创作流程见[作者指南](guide/zh-CN.md)，接口参数与默认值由声明旁的英文文档提供。

## 创作模型

Reel 让创作者用代码表达画面、对白、UI、演出和嵌入的 2D 游戏。函数组织流程，节点组成画面，活动表达随时间发生的变化。页面、剧情与玩法使用同一套状态、输入和生命周期。

项目入口固定为 `src/main.aside` 的 `main`。入口配置作品、建立共享状态并开始流程；模块按章节、菜单、人物演出或小游戏组织。简单视图返回节点，等待交互的函数返回结果，需要持续操作的组件返回具有明确方法的对象。共享状态由调用方传入，局部状态由组件持有。

普通函数可以等待对白、活动和交互结果。`spawn` 创建并行任务，`sequence` / `parallel` 组合动作，`.then` / `.together` 提供对应的方法写法。`scope` 拥有临时节点与工作，`reading` 为局部剧情组合对白、选择、历史与阅读状态。

作者接口沿同一舞台模型表达位置、布局、图片、文字、样式、输入和特效。性能优化由引擎复用已准备的数据和资源，稳定画面沿失效信息跳过重复工作。

Aside 依赖语言与 Rust 基础库。窗口和 GPU 类型留在平台适配器；UI 向后端提供拥有数据与资源租约的可移植帧。`reel-engine` 当前直接依赖 `aside-compiler`，源码和 ASB 通过同一宿主注册与执行准入。

借用实现作为工作区 crate 维护，来源、许可证和必要版权信息随对应 crate 保存：UI 来自 Masonry，文字来自 Parley，混音来自 Kira，语法树来自 Rowan。Reel 按当前模块职责维护这些代码。通用算法优先复用锁定的 Rust 依赖，包括 Taffy、HarfRust、ICU、Symphonia、Lyon 和 WGPU。

## 执行、等待与调度

编译器和 VM 共用字节码模型。模块初始化完成后进入普通 `main`；宿主验证代码身份、native 签名、ABI、能力和实际支持的指令。错误保留作者源码位置。

编译器将可变指令缓冲转换为紧凑代码，并按模块释放分析数据。字节码文件、运行时和快照共同使用代码字偏移定位，跳转、异常范围与源码映射使用同一坐标。

指令按 32 KiB 分块压缩，已验证程序共享冷代码与有界热页缓存。VM 在当前页内直接取指，换页时解压；页面的全部持有者释放后归还驻留额度。加载按块验证，快照保存代码身份与执行位置。

VM 按指令、内部工作、分配和时钟额度推进。`BudgetYield` 保留执行位置和中间状态；宿主调用返回值、故障、继续执行状态或等待票据。长操作分片处理，成功后提交其约定的结果。用户回调已经发生的副作用按执行状态保留。

生成器按需在调用方任务内执行，`yield` 将暂停帧的局部值与故障上下文交给生成器对象持有。推进、关闭与快照复用同一执行器和 GC；不可达生成器释放其状态，显式关闭执行已进入的清理代码。

显式 `await` 是调度边界，已经完成的对象也会让其他任务获得运行机会。宿主等待通过稳定身份结算，完成消息匹配会话、所有者与代际后至多交付一次。共享活动的等待者各自持有订阅；取消一个等待者释放其订阅，活动按自身所有权继续运行。

主循环在有输入、活动、资源完成、GC 或退休工作时推进。时钟活动设置下次唤醒时间，稳定画面复用已接受帧。睡眠前先确认唤醒信号，再处理其来源并检查剩余工作。任务的局部最小预算不足时，根据实际报告安排下一片；宿主保留整个循环的工作边界。

会话时间使用单调时钟，宿主挂起期间冻结。舞台动画、阅读计时、音频内容位置和现实时间分别由对应时钟驱动。`std::time` 读取现实时间；持续玩法通过命名动作和时钟更新普通舞台节点。

## 所有权、取消与资源预算

会话、任务、节点、作用域和外部请求都具有明确身份。复制 VM 的 `Value` 只复制句柄；宿主持有跨执行片使用的值时，须登记相应 GC 根。寄存器、native 参数、继续执行状态、等待结果和故障引用进入同一根与快照系统。

所有者撤销先关闭新请求和业务等待，再取消任务、清理 VM 根并退休外部资源。物理释放完成后归还对应预算；所有记录义务结束后才允许复用所有者槽位。GC 负责不可达脚本对象，外部设备生命周期由所有者协调。

容器与缓冲按实际容量计量。增长前预留新旧存储重叠的额度，拥有数据随预算票据转移，最终物理释放归还额度。共享别名保持同一份存储与票据。分配和释放的不可分割成本单独测量。

后台 IO、解码和完成队列使用明确容量。请求接受前预留结果位置；拒绝时返回原请求及其所有权。消费者暂时占满队列时保留待处理工作，由释放或完成通知唤醒。过期结果沿原所有权路径释放。

预算分别覆盖 VM 堆、CPU 源与输出、解码工作区、GPU 驻留和临时目标。各账本记录其实际拥有的存储；进程 RSS、驱动和第三方解码器的内部工作区需要独立测量。详情见 [reel-core](../crates/reel-core/src/lib.rs) 与 [VM](../crates/aside-vm/src/lib.rs)。

## 舞台、布局与文字

每个舞台节点有一个逻辑父节点。构造返回未挂载节点，`add` 与 `stage.replace` 提交挂载，`remove` 退休节点，`move` 在同一父节点内调整顺序。节点身份承载回调、焦点、活动与资源引用。

固定画面使用 `stack` 和位置属性；行、列与网格使用 Taffy Flex/Grid。布局读取直属子节点和已有文字测量，尺寸或属性改变后沿失效路径更新。父级变换和裁剪同时作用于绘制与输入。

逻辑画布按 contain 映射到窗口，留边和缩放使用统一变换。画布尺寸定义作者坐标；离屏目标由实际绘制效果和物理输出需求分配。`camera` 把世界区域映射到视口，HUD 可放在相机外。

`list` 按 key 复用行组件；记录替换更新数据连接，稳定 key 保留组件身份。虚拟列表根据视口、行高和缓冲范围构建行，来源数据仍由调用方持有。`VirtualListNode.scroll_to` 等待目标行的位置与呈现；取消、过滤、尺寸改变和退休沿列表活动处理。

`bind` 连接可观察属性，`derive` 连接派生值。派生计算读取上游时先完成其待重算，以同一状态评价依赖和结果。写回、循环检测与取消使用共同属性协议。临时 `override` 与 `offset` 在作用域结束时撤销自身图层，保留底层业务值和动画。

文字由 `reel-text` 整形、换行与编辑。字体文件由作品提供；字体族、字重与回退参与同一次匹配。布局保留字形位置、字簇与源文字范围，绘制直接消费布局结果。逐字显现改变可见范围，颜色改变复用几何；文字或影响布局的样式变化触发重排。

富文本保存正文、样式、ruby、链接和句内时序。普通字符串按原文显示。竖排通过文字的逻辑书写轴布局，字形方向、注音、光标端点与命中位置使用相同几何。

文本编辑控件以同一事务处理键盘、输入法、选择、撤销和过滤；预编辑与已提交文本分别保存。单选组按共享属性身份组织导航，虚拟行通过所属列表解析目标。

属性和控件接口见 [Stage](../crates/reel-ui/src/stage)、[作者节点](../crates/reel-engine/src/aside/stage.rs) 与[文字](../crates/reel-text/src/lib.rs)。

## 输入与已呈现画面

布局和绘制产生候选画面及对应几何。后端接受该候选后，输入使用它的冻结几何；准备、提交或呈现失败时继续使用上一份已接受视图。一次输入固定使用同一几何快照，并核验节点当前存活、可见、启用和模态资格。

`input.on_pointer` 接收命中区域内的移动，以及主按钮或触摸开始的拖动。坐标相对输入节点；`event.dragging` 表示该节点的主按钮或触摸拖动仍在进行。悬停保持当前焦点，拖动捕获持续到释放或取消。

指针捕获属于当前手势和节点；隐藏、禁用、退休、失焦或模态范围改变会结束失效手势。键盘与手柄通过命名动作汇合，控件消费自身确认、方向和编辑输入，其余事件沿祖先传播。一次输入至多推进一次剧情。

弹出层和系统菜单参与同一层序、焦点与模态路由。窗口外点击、触摸滚动和指针取消按事件终态处理。几何查询和捕获引用已呈现帧，保证显示位置与交互位置一致。

公共呈现协调器管理候选身份、SurfaceEpoch、接受记录、重试与曝光重绘。表面尺寸变化和恢复使用新的 epoch；设备重建还更新设备 generation。临时资源压力等待完成通知，永久拒绝等待状态或尺寸改变。

## 绘制、转场与 GPU

UI 记录有序 `VisualLayerPlan`，每段保留绘制者、变换、组、裁剪和资源。`FrameBuild` 按命令、工作和字节额度生成拥有资源租约的不可变 `RenderFrame`。诊断指向实际命令和节点；取消释放尚未发布的候选。

图片、路径和字形沿同一坐标与裁剪体系绘制。变换使用前向组合，输入查询在需要时求逆。几何外延包括描边、抗锯齿和效果扩张，未知或溢出外延由后端按实际输出区域裁限。

默认 WGPU 后端使用图片与字形四边形、Lyon 路径网格和按相邻状态合批的提交。字形栅格复用 Swash；图集键包括字体、字号、字形、变体、描边和字形变换。图片、字形与管线缓存属于确定设备代际。

合成采用线性预乘颜色，输出时编码到表面。组先合成子内容，再应用一次组透明度和遮罩。`crossfade` 混合完整的前后画面；`subtract` 对线性预乘 RGB 计算 `max(dst - src, 0)`，保留目标 alpha。

普通绘制进入当前目标。独立组、遮罩和转场按实际需要使用离屏目标；目标池按尺寸、格式、采样数、resolve 和在途重叠计量。后端根据能力与预算选择质量档，目标复用前清空。资源租约和预算保持到 GPU 使用结束。

舞台转场冻结已接受内容，在普通脚本回调中构建目标。目标就绪后推进合成；存档保存恢复所需的画面描述和资源版本。粒子以批次配置、种子和时钟描述运动，绘制时采样；发射活动沿节点和作用域生命周期退休。

视频帧使用共享 YUV 平面与确定版本，在 GPU 采样时转换颜色。已接受帧和在途提交持有的纹理保持原内容，最终引用释放后复用存储。

图片和视频的 `alpha_layout` 默认为 `"native"`，保留资源透明度；`"top_bottom"` 将上半帧作为颜色、下半帧的编码红通道作为覆盖率，自然尺寸为原宽度与一半高度。`source_rect`、九宫格和平铺使用可见颜色区域的像素坐标。颜色沿原色彩空间解码后按覆盖率预乘；覆盖率直接使用编码通道值。GPU 复用原纹理采样两个区域，布局随节点属性和已保留画面保存。

绘制和设备接口见 [reel-ui](../crates/reel-ui/src/lib.rs) 与 [reel-render](../crates/reel-render/src/lib.rs)。

## 资源加载与媒体

资源通过 `AssetIo` 与后台工作服务读取。内容版本标识不可变资源，准备结果按版本共享。解码前读取头部并预留输出与工作区；首个场景的字体和图片准备完成后显示，场景换源期间保留上一完整画面。

普通图片按需解码，[分块图片](../crates/reel-core/src/prepared_image.rs) 根据实际视口选择层级和瓦片。预取优先让位于必需资源；画面与在途加载各自持有实际租约。资源归档挂载读取索引，内容通过范围 IO 获取。

`assets.read(path, owner: null)` 从同一资源根或归档异步读取数据，等待结果取得不可变 `Bytes`。请求沿现有后台队列、资源预算与所有者生命周期处理；完成数据按 VM 字节存储计量。存档保留已完成数据和在途请求的恢复状态，读取失败指向调用源码。

音频接口返回普通活动，统一管理播放、暂停、定位、循环、队列与音量。短声音预解码，长音轨使用有界 PCM 窗；作者按内容组织调用，宿主选择准备方式。音频队列在混音边界连接已准备片段，欠载时输出静音并保留内容位置。

`reel-media` 创建设备与混音供给。配置取得实际格式后构建 mixer；接受播放后，实时回调独占供给并使用预分配缓冲和有界队列。文件 IO、分配、线程等待和最终 PCM 释放由控制侧或后台服务完成。

停止与挂起先关闭供给入口并等待在途调用结束。挂起保留 mixer，恢复验证格式后继续；格式变化或设备失败报告实际状态。控制侧移交退休 Sound 及其预算票据，后台物理释放完成后归还额度。会话退出持续驱动退休工作，宿主最终关闭时 drain/join 清理服务。

音频完成表示混音器已消费内容。CPAL 后端的硬件呈现时钟精度为 `Unavailable`；字幕和演出使用媒体内容位置。有声视频跟随 PCM 消费，静音视频跟随会话时间。

接口与队列约束见 [reel-media](../crates/reel-media/src/lib.rs) 和 [reel-audio](../crates/reel-audio/src/lib.rs)。

## 对白、历史与阅读

对白在提交时建立完整行组并预留历史。推进先补全显现，再结束等待；选择保留由交互身份限定的业务 key。正文、富文本样式和历史内容通过只读模型交给作者组件。

`reading` 保持局部对白、选择、历史、自动阅读和暂停状态。切换 UI 保留上下文身份，嵌套阅读结束后恢复父上下文。历史按提交追加，清理可保留最近的实际行数和剩余行身份。

逐字显现按字素与句内时序推进。`ready` 表示正文及尾部停顿完成。已读身份根据剧情调用路径记录，译文切换沿用同一身份；正常推进完成后登记已读。

自动阅读在全文实际呈现后等待延时，在选择处等待玩家。快进沿普通控制流推进，并完成其策略覆盖的有限活动。暂停、模态界面、挂起和失焦按阅读协议更新计时与模式。自定义 UI 读取这些状态，决定按钮、光标和历史页的外观。

## 保存、恢复与系统数据

执行快照保存代码身份、任务栈、继续执行位置、对象图、绑定、活动、当前交互、舞台和媒体描述。不可变代码与资源通过共享身份引用；可变值保持快照时的数据与别名关系。

捕获固定会话状态，按对象、边和字节额度推进。需要改变会话的输入使当前捕获以 `CaptureBusy` 失败，原槽位保留；后台保存完成后原子发布。缩略图与快照属于同一次槽位发布。

恢复先在隔离候选中分配身份、连接图和重建宿主描述，验证完成后替换当前会话。代码或格式不匹配时报告错误。设备句柄由宿主重建，过期完成消息通过新会话身份失效。

`persistent` 独立保存业务数据，适合设置和解锁进度。读取返回普通数据副本；作者在启动和剧情恢复后应用当前系统数据。剧情槽位与系统数据各自原子发布。

快照与 ABI 格式保持 v1。内部结构变更同步当前编码、解码和验证路径；作品的执行存档使用匹配代码包。

## 项目、翻译与编辑器

`reel check` 检查实际导入图，`dev` 编译并运行，`build` 生成 ASB，`export` 组织完整作品。检查与源码运行复用已验证的编译结果，构建时按所选配置编码产物。源码位于 `src/`，资源位于 `resources/`，默认产物位于 `build/`。CLI 与播放器共用宿主接口注册和类型信息。

`dev` 在 `build/dev/` 缓存带源码映射的编译结果与内嵌翻译。工具和源码内容共同确定缓存身份，源码文件的增删和修改均参与检查；资源继续从当前项目读取。

原文与译文写在同一个 `tr` 调用中，编译器生成内部消息身份和语言目录。原文插值按顺序各求值一次，译文引用这些值。语言切换准备精确语言及基础语言后更新可观察状态；失败保留原语言。

Debug 包保留源码与指令映射，Release 剥离调试数据。发布时正文放入文本包，资源归档按完整条目分卷；ASB 内嵌分发清单。格式见 [ASB](../crates/reel-package/FORMAT.md) 和 [字节码](../crates/aside-vm/src/bytecode/FORMAT.md)。

LSP 使用同一编译器和宿主元数据提供诊断、类型、补全、悬停及导航。Rust 声明旁的英文文档生成可跳转 Aside 声明。源码范围使用 UTF-8 字节；协议按协商编码转换位置。未保存的编辑内容参与项目分析。

已知类型和签名支持静态诊断，动态字段沿运行时语义处理。编辑分析按模块和依赖缓存，文档变化使相关结果失效。格式化器由 CLI 与编辑器共用。

## 验证与维护

行为检查按语言、会话、UI、渲染、媒体和工具职责组织。输入、等待、取消、恢复、所有权和资源释放通过实际执行路径验证。CPU 布局检查、离线媒体和原生设备检查分别记录运行环境。

性能测量选择当前热点，记录实际工作量、分配、驻留和帧时间。缓存稳定性和退休后的释放是持续交互的重要边界。源码、测试及必要输入进入版本库；构建、日志与测量输出位于忽略的 `target/reel-artifacts/`。

命令入口见 [reel-dev](../crates/reel-dev/README.md)。协作规则见 [AGENTS.md](../AGENTS.md)。平台移植复用公共会话、舞台和资源合同，设备支持以对应适配器的实际运行结果为准。
