# Reel 引擎架构

本文定义模块职责和跨模块行为。语言语义见 [Aside 规范](aside-language.md)，创作流程见[作者指南](guide/zh-CN.md)，接口参数与默认值由声明旁的英文文档提供。

## 创作模型

Reel 让创作者用代码表达画面、对白、UI、演出和嵌入的 2D 游戏。函数组织流程，节点组成画面，活动表达随时间发生的变化。页面、剧情与玩法使用同一套状态、输入和生命周期。

项目入口固定为 `src/main.aside` 的 `main`。入口配置作品、建立共享状态并开始流程；模块按章节、菜单、人物演出或小游戏组织。简单视图返回节点，等待交互的函数返回结果，需要持续操作的组件返回具有明确方法的对象。共享状态由调用方传入，局部状态由组件持有。

视图用结构类型声明交给调用方的具名节点，菜单用字符串字面量联合声明可返回的结果。Aside 编译器和编辑器共享声明，VM 沿普通函数和绑定边界检查动态值。

普通函数可以等待对白、活动和交互结果。`spawn` 创建并行任务，`sequence` / `parallel` 组合动作，`.then` / `.together` 提供对应的方法写法。`scope` 拥有临时节点与工作，`reading` 为局部剧情组合对白、选择、历史与阅读状态。

作者接口沿同一舞台模型表达位置、布局、图片、文字、样式、输入和特效。播放器的舞台底色为黑色，未被节点覆盖的区域显示此底色。性能优化由引擎复用已准备的数据和资源，稳定画面沿失效信息跳过重复工作。

## 模块职责

| --- | --- |
| `aside-syntax` | 不可变语法树、源码范围与节点共享所有权 |
| `aside-compiler` | 词法、语法、语义分析、源码类型、格式化和字节码生成 |
| `aside-vm` | 动态值、集合与文本方法、执行栈、GC、宿主调用、等待、错误和快照 |
| `aside-host`、`aside-host-macros` | Rust 函数、属性、类型、文档及 ABI 元数据 |
| `aside-std` | 数学、曲线、随机数、时间和故障查询 |
| `aside-lsp` | 编辑文档、项目分析、诊断、补全、悬停和导航 |
| `reel-core` | 身份、拥有字节、预算、资源 IO、后台工作与时钟合同 |
| `reel-engine` | 会话、作者接口、对白、活动、作用域、存档请求和脚本适配 |
| `reel-ui` | 舞台树、布局、控件、输入、绘制记录和已呈现几何 |
| `reel-text` | Unicode 分析、整形、换行、文字布局与编辑 |
| `reel-render` | 帧编译结果的资源准备、GPU 合成、呈现与完成回收 |
| `reel-player` | 运行包加载、会话与 UI 的组装、资源加载、窗口、平台输入和主循环 |
| `reel-audio` | 混音、声音、轨道、效果及音频控制队列 |
| `reel-media` | 设备输出、音视频解码、流式供给和后台释放 |
| `reel-storage` | 文件存储的原子发布 |
| `reel-package` | ASB、文本包和资源归档 |
| `reel-cli` | 项目检查、运行、构建、导出与 Reel 语言服务入口 |
| `reel-dev` | 仓库检查、性能采集流程与报告分析 |

Aside 依赖语言与 Rust 基础库。窗口和 GPU 类型留在平台适配器；UI 向后端提供拥有数据与资源租约的可移植帧。`reel-engine` 当前直接依赖 `aside-compiler`，源码和 ASB 通过同一宿主注册与执行准入。

控件树由宿主 UI 线程持有，采用固定版本 `tree_arena` 的平铺节点存储与父子分离借用接口。跨线程传递使用拥有数据的帧和已呈现几何；控件树本身保持在线程内。输入路径容量只计量事件路由数组。

共用播放器通过 HAL 合同访问宿主、渲染、媒体、存储和输入。`reel-player::hal` 定义宿主生命周期与显示控制，渲染、解码和存储合同由对应 crate 维护。播放器负责会话推进、资源就绪、呈现接受、输入分派与挂起；平台组装负责创建设备和事件循环。

发行包由 `reel-player::distribution` 读取 ASB、文本池、语言索引和资源根，再交给共用会话执行。CLI 负责定位作者工程及编译、导出；平台入口直接加载发行包。

Vita 应用的固定启动素材位于所属 crate 的 `runtime/vita/`，由 `cargo-vita` 直接打包。启动器字体包及许可随素材维护；测试游戏与普通作品沿发行导出流程准备和部署。编译与 VPK 输出遵循 Cargo 的目标目录配置，清理编译缓存保留固定打包输入。

本机桌面目标、`desktop` 和自定义资源变体的发行导出默认附带工具包的宿主播放器。发行至其他桌面系统时指定 `--runtime` 或 `--data-only`。`--runtime` 保留指定运行时的文件结构，Vita 运行时目录须在根目录包含 `eboot.bin`。作品包写入导出根目录，运行时文件与作品包重名时报错。安装格式由对应平台的打包工具生成。

`reel::build` 的只读字符串 `target` 记录构建目标，由 `--resource-target` 同时选择源码常量与资源覆盖目录，默认使用宿主系统名称。编译缓存包含这个目标。作者用普通 `if build.target == "vita"` 选择效果配置；编译器消除未选分支的执行代码。`window.info().platform` 继续报告当前播放器的平台。资源收集沿目录覆盖和打包规则执行。

`reel export --release --data-only` 导出代码、文本和资源，供已安装的共享运行时加载。Vita 发行默认使用这一模式。Vita 启动器扫描 `ux0:/data/reel/` 下含 `game.asb` 的一级作品目录，使用共用舞台和输入呈现列表；每部作品在自己的 `saves/` 中保存进度。切换作品前完成当前会话、媒体和 GPU 提交的清理，游戏退出或执行错误返回启动器。

Vita 启动器进程持有一个原生事件循环和渲染设备，各播放器会话借用该设备。切换时先关闭并释放旧播放器及其媒体、字体、资产与捕获，再等待 GPU 完成并清空会话缓存；设备和已编译着色器保留到应用退出。应用退出显式关闭原生设备，清理失败报告原始原因并终止后续挂载。

启动器复用列表和设置页面，目录扫描与设置写入交给后台工作线程。主题、语言和上次选择保存在 `ux0:/data/reel/launcher.json`。加载提示完成呈现后，宿主开始读取作品包。

平台实现按渲染、媒体与宿主职责放在现有 crate 的模块内，`cfg` 在模块入口和目标依赖处选择实现。公共接口传递能力、资源描述与拥有数据，原生句柄由适配模块管理。各后端复用通用资源格式，生产实现保持 `forbid(unsafe_code)`。

Vita 宿主直接加载发行包，以固定物理屏幕映射作者画布，并将控制器、触摸和系统挂起事件交给共用播放器。原生调用通过固定 Git 提交的 `vita-native` 库使用，SDK 句柄与原生完成回收由该库封装，着色器接口和顶点布局由 Reel 适配层提供。WGPU 与 GXM 复用绘制规划、资源需求与缓存策略，设备适配负责程序、纹理存储、坐标约定、提交与完成回收；纹理准备按容器记录的块序上传。音频沿通用 Opus 解码与混音进入 AudioOut，视频通过 AvPlayer 工厂输出拥有数据的画面与 PCM。设备内存额度由平台组装提供，缓冲、队列和 GPU 驻留分别计量。

GXM 将上传的源图片与软件视频平面放入无 CPU 缓存的 MAIN 内存，字形图集、渲染目标与扫描输出放入 CDRAM。源图片保留一份物理存储，离屏效果继续采样 CDRAM 中的中间结果。离屏目标默认采用线性存储；启用 `gxm-tiled-targets` 后，无背景快照复制的帧中两轴至少 32 像素的 RGBA8 目标采用 32×32 tiled 存储。tiled 规划计入完整 tile 填充，背景快照帧保留线性 PTLA 路径，分配与缓存记录实际布局及字节；较小目标、Coverage8 和扫描输出保持线性。native 按实际内核块管理物理准入：CPU arena 与图形 MAIN 块共用进程账本，扫描输出与像素块共用 CDRAM 账本，视频连续内存独立准入。容量在初始化边界根据内核空闲量取得；CDRAM 在参数缓冲创建后初始化。每份块包含页对齐容量，最后使用者完成且物理释放成功后退账。池按生命周期和大小组织子分配，空闲保留量作为可回收缓存目标。

渲染器根据物理域容量规划画面，分别计量资源载荷、离屏目标和暂存数据；这些载荷统计用于工作集规划，物理页账本用于分配准入。当前帧、保留转场与在途读取者持有必需存储，可重建缓存使用剩余容量。分配压力先回收对应物理域的空闲块和渲染缓存，实际释放后重试；已有提交保持资源直到完成。上传队列和在途帧数限制并发工作，避免瞬时峰值。内核页分配耗尽进入同一回收路径，错误保留请求大小、已占用容量、可查询的内核空闲量和原始返回码。回收后仅在已有提交能够释放存储时等待完成；工作集仍无法容纳则拒绝当前帧。

着色器构建按后端生成程序：桌面 WGPU 使用 WGSL，GXM 使用 SDK 的 `psp2cgc` 离线生成 GXP。内置程序嵌入播放器，作者效果沿同一类型化表达式生成目标程序和参数绑定。设备复用已创建的程序及混合配置，离屏目标按实际覆盖区域分配。

节点的 `effect_resolution_scale` 指定其 `effect` 输出的计算分辨率，默认 `1.0`，取值为 `(0, 1]`。效果在缩小的栅格上计算，再线性放大到原输出区域；`Fragment` 的逻辑位置、尺寸和采样坐标保持原定义。子树和独立遮罩沿用各自的分辨率。游戏可用 `build.target` 为特定平台选择倍率；渲染器按显式倍率规划中间目标、预算和缓存。`reel::effect` 宿主接口和着色器 uniform ABI 保持版本 1。

编译器证明采样归约的一条坐标轴恒定时，可附带普通颜色输出的单轴 GXP 变体，将该轴的映射和边界裁剪移出循环。运行时在实际源映射为有限对角矩阵时选择它，保持采样次数、坐标表达式、累加顺序和量化边界。产物统一使用带独立代码段边界的 `REELSHD2` 封装，uniform ABI 为 1。所有代码段与运行时程序共用既有着色器大小和资源预算。

独立颜色效果按自身源命令、参数、纹理和实际栅格复用结果。转场替换或插入像素的命令范围与效果源相交时，按当前绘制重算。源内遮罩和混合参与准入判断，其他子树的遮罩和转场可独立更新。

Sony 编译使用精确数学及整数语义，默认采用 `-O3`。片元程序遇到 SDK 的 `D7203` 寄存器容量错误时，以相同输入和精度选项改用 `-O2` 重试一次；重试仍超限则保留两次编译诊断。该策略保持寄存器溢出为错误，编译缓存身份同时包含两种优化级别及重试规则。

合成需要背景快照时，共用规划为相同整数像素网格确定复制范围。同格式、单采样表面在目标首次使用且完整覆盖物理存储时使用纹理复制。局部首次写入将清屏与复制绘制合并在同一通道，避免清屏落存后再次写入相同像素；已有目标内容、多采样和需要坐标重采样的表面同样使用绘制。两个后端沿原合成顺序保存背景并读取快照；GXM 使用片元与传输依赖，WGPU 使用有序编码，两侧资源持有至复制和后续读取完成。

启用 `gxm-tile-destination` 后，GXM 在符合条件的单采样 RGBA8 表面上直接读取当前像素输出寄存器作为混合背景，省去背景纹理复制。共用规划与执行使用相同准入条件，源子树独立合成，保留量化边界和绘制顺序；附加遮罩、转场输入及其他表面继续读取快照。

GXM 的场景提交、片元完成通知与显示队列分别管理绘制、资源退休和扫描输出。提交保留所引用的缓冲、纹理与目标，宿主完成轮询逐项检查场景与传输通知并回收已完成租约；三个扫描输出缓冲各自持有显示同步对象，等显示队列释放后复用。离屏表面保留各自的像素存储，通过场景顺序和片元/传输同步标志建立依赖。兼容尺寸的表面共享调度目标，场景有效区域限定实际绘制范围。显示回调完成屏幕提交与扫描同步后唤醒宿主，完成状态先于唤醒发布；脚本、UI 和资源管理由宿主线程推进。唤醒对象由设备持有到显示队列排空。内核分配块、GPU 映射、上下文环形缓冲和渲染目标调度存储按各自实际容量记录。

同栅格、单一消费者的连续 RGBA8 离屏效果链可按 Sony 宏瓦片同步规则合为一个 GXM 场景，保留各阶段的采样、量化和逻辑尺寸。共用离屏计划先生产独立子树，再按原绘制顺序执行父目标上的合成与终端效果，保留其着色器、变换、裁剪和透明度。延迟消费的源目标计入完整存活期；预算决定生产窗口大小。窗口内布局相同的效果链可占用同一宏目标的连续单元，整份分配最多包含 16 个单元。渲染层按完整线性图集及带宏瓦片配置的调度存储准入；原生层提供按列排列的单元目标和独立 CLAMP 纹理别名，平移视口与裁剪，检查单调绘制和只读前置单元。别名共享像素所有者，缓存及在途读者保留实际分配。同队列的后续帧，以及最后一次父读取已结束的同帧链段，可复用布局和单元尺寸相同的整个图集；重叠使用期和持有效果缓存的图集继续独占。每次使用重新初始化各单元，只有该图集本帧的最后一次使用可以发布新的效果缓存。物理准入按同时存活的整图集峰值计量。遮罩、背景读取、分叉及捕获边界继续使用独立目标。

Vita 发行入口启动时请求 Sony 电源配置 Mode C 和 ARM CPU 444 MHz。Mode C 保留 WLAN 并提高 GPU 性能，限制屏幕亮度并停用相机。实际频率由系统和设备插件配置决定，性能记录包含时钟读数。

桌面通过 WGPU 场景宿主检查完整脚本流程、提交成本与内存占用。GXM 通过 Vita 目标构建和实机检查绘制、颜色、帧时间与资源回收。

可选的 `thread-profiling` 由平台适配器提供线程运行时钟，在完整呈现提交边界记录 VM 切片、渲染提交和呈现的原始 CPU／壁钟样本、查询开销与错误。平台先检查计数是否支持短区间观测；不可用状态和异常样本保留在报告中。VM 切片每 127 次取样，其余两阶段逐次取样；离线报告保留采样范围，普通构建擦除观测代码。

`profiling` 构建可为调用线程启用独占墙钟账本：每个区间只归入当前最内层阶段，未进入阶段和观测记录分别计量；跨呈现边界的活动阶段按边界切分。固定容量栈的溢出和次序错误随样本报告。逐帧版本 1 报告追加具名纳秒列，离线工具逐行核对阶段、未归属和丢失时间之和；驱动调用墙钟包含调用中的等待。报告保留最近 512 帧及更早记录中活动耗时最高的 64 帧，按提交顺序输出，随标签淘汰失效样本。探针通过同一构建的开关对照测量新增观测开销。

桌面采样将宿主事件循环交还系统后至下一轮事件开始的时间记为 `host_wait`。交换链取图和提交显示继续按各自调用计时。

借用实现作为工作区 crate 维护，来源、许可证和必要版权信息随对应 crate 保存：UI 来自 Masonry，文字来自 Parley，混音来自 Kira，语法树来自 Rowan。Reel 按当前模块职责维护这些代码。通用算法优先复用锁定的 Rust 依赖，包括 Taffy、HarfRust、ICU、Symphonia、Lyon 和 WGPU。

## 执行、等待与调度

编译器和 VM 共用字节码模型。模块初始化完成后进入普通 `main`；宿主验证代码身份、native 签名、ABI、能力和实际支持的指令。错误保留作者源码位置。可信注册的只读叶计算在 VM 切片内完成，沿用参数准备与返回提交并计入 VM 工作额度；曲线采样和标量数学与普通宿主入口共用计算实现。

编译器将可变指令缓冲转换为紧凑代码，并按模块释放分析数据。字节码文件、运行时和快照共同使用代码字偏移定位，跳转、异常范围与源码映射使用同一坐标。

指令按 32 KiB 分块压缩，已验证程序共享冷代码与有界热页缓存。VM 在当前页内直接取指，换页时解压；页面的全部持有者释放后归还驻留额度。加载按块验证，快照保存代码身份与执行位置。

VM 按指令、内部工作、分配和时钟额度推进。指令、工作和分配额度逐步检查；软时限在进入或恢复执行、宿主调用返回以及有界执行批次后检查。`BudgetYield` 保留执行位置和中间状态；宿主调用返回值、故障、继续执行状态或等待票据。长操作分片处理，成功后提交其约定的结果。用户回调已经发生的副作用按执行状态保留。

GC 的弱引用阶段遍历独立的弱引用队列，标记结束时固定本轮范围。队列容量在构造弱引用前计入堆预算；回收只读写已分配的存储。新弱引用留到下一轮，已清空或不可达的弱引用退出队列，存活判定继续使用同一标记截止点。清扫先使对象失效，再直接释放其值块，每块计入工作额度，实际释放后归还对应内存额度。

性能构建按提交间隔记录根扫描、标记、弱引用、对象清扫与释放的工作单位。同一间隔的 GC 总耗时由会话计时提供。

生成器按需在调用方任务内执行，`yield` 将暂停帧的局部值与故障上下文交给生成器对象持有。推进、关闭与快照复用同一执行器和 GC；不可达生成器释放其状态，显式关闭执行已进入的清理代码。

显式 `await` 是调度边界，已经完成的对象也会让其他任务获得运行机会。宿主等待通过稳定身份结算，完成消息匹配会话、所有者与代际后至多交付一次。共享活动的等待者各自持有订阅；取消一个等待者释放其订阅，活动按自身所有权继续运行。

属性活动按绑定的最终来源取得写入权。作者赋值、手动滚动与显式定位可以接管滚动位置；布局夹取和列表锚点反馈属于系统更新。滚动活动持有来源时，自动锚点补偿让出位置控制，范围夹取继续生效。

主循环在有输入、活动、资源完成、GC 或退休工作时推进。`game.configure(frame_rate: ...)` 设置补间、粒子、转场和原生控件动画的目标更新频率，接受 1–1000 Hz；0 为默认自动值，跟随宿主显示器刷新率，宿主未知时使用 60 Hz。定频采样点沿逻辑时钟排列，迟到时直接采样当前时间并跳过已过采样点。`"uncapped"` 在帧生产空闲时立即采样持续动画。已在排队的画面仍走同一套背压；显式时钟和对白使用各自期限，垂直同步由窗口设置控制，稳定画面复用已接受帧。睡眠前先确认唤醒信号，再处理其来源并检查剩余工作。Vita 主线程的重绘请求记录为本地状态，本轮消费后沿活动期限睡眠；渲染期间新增的重绘在睡眠前进入下一轮。IO、媒体、显示完成与电源事件继续通过保留的跨线程通知唤醒宿主。任务的局部最小预算不足时，根据实际报告安排下一片；宿主保留整个循环的工作边界。

原生控件与剧情持续动画同时运行时，共用剧情的下一个采样时刻。只有控件动画运行时，由控件自身的固定节拍唤醒；实际动画步长使用两次采样的时间差。

媒体、本地化和资源读取的外部完成在每轮宿主推进入口处理。该轮内部的 VM 切片和 native 重入继续执行本地调度；新的外部完成通过唤醒信号交给下一轮入口。直接使用 `SessionVm` 的宿主调用对应的 `maintain_*` 方法处理这些完成。

一次时钟更新及其派生计算可以跨越多个宿主时间片。脚本到达提交边界且派生批次完成后返回宿主，使完整画面获得发布机会；已请求的重绘先记录这份稳定投影，下一轮再继续就绪脚本。计时采样由活动截止和实际输入、资源完成驱动，维护时间片沿用当前时间批次。脚本等待时，活动继续按时钟推进。

播放器遇到 VM 硬容量阻塞时，完成一次垃圾回收后重试。仍无法继续时，报告源码位置与资源需求并结束本次运行。

会话时间使用单调时钟，宿主挂起期间冻结。舞台动画、阅读计时、音频内容位置和现实时间分别由对应时钟驱动。`std::time` 读取现实时间；持续玩法通过命名动作和时钟更新普通舞台节点。

## 所有权、取消与资源预算

会话、任务、节点、作用域和外部请求都具有明确身份。复制 VM 的 `Value` 只复制句柄；宿主持有跨执行片使用的值时，须登记相应 GC 根。寄存器、native 参数、继续执行状态、等待结果和故障引用进入同一根与快照系统。

节点子块构造本次挂载的子节点。`spawn` 和 `scope.spawn` 需要普通任务上下文，放在子块之后，通过 `owner` 或作用域管理工作生命周期。

`scope.wait()` 挂起拥有该作用域的任务。由输入回调调用 `finish(value)` 时，作用域正文退休，外层 `scope` 调用取得结果。取消沿同一任务退休路径清理等待。

根范围用代际身份和占用位图共同索引。增量 GC 每个扫描单位读取一个描述符、一个值或一个 64 槽占用字；空槽按块跳过，范围替换后从新代际的首个值继续。位图随描述符容量预分配并计入堆预算，回收切片只读取既有存储。

所有者撤销先关闭新请求和业务等待，再取消任务、清理 VM 根并退休外部资源。物理释放完成后归还对应预算；所有记录义务结束后才允许复用所有者槽位。GC 负责不可达脚本对象，外部设备生命周期由所有者协调。

容器与缓冲按实际容量计量。增长前预留新旧存储重叠的额度，拥有数据随预算票据转移，最终物理释放归还额度。共享别名保持同一份存储与票据。分配和释放的不可分割成本单独测量。

共用物理内存的资源域可以加入同一预算组。预留和调整同时满足域内额度与组总额度，失败保留原计账；最终释放同时归还两者。同组拥有缓冲可原子转移到另一资源域，校验目标额度时共享组的原票保持一次计量；失败保留原票与数据。组峰值记录各域实际同时持有的字节。

可重载图片与纹理的资源身份、版本、尺寸、格式、来源和覆盖率描述独立于 CPU 载荷。上传、存档及其他 CPU 读取者持有载荷读取租约；后端成功拥有相同版本后，在无读取者时可回收可重载载荷并归还原预算。动态生成或没有可靠重载来源的数据继续持有载荷。普通舞台图片以资源身份绘制，不因记录帧而额外保持像素 Blob。

播放器保留最近退出舞台的至多 64 个已回收 CPU 载荷的图片身份，重新显示时复用原身份与仍驻留的 GPU 纹理。GPU 缓存继续按原资源额度回收；缺失后沿精确版本重载路径恢复。会话关闭释放这些身份。

后端重建或缓存缺失需要已回收载荷时，播放器沿现有 Assets 请求异步按精确版本重载；同一资源的请求合并，版本和描述核验后安装到原身份。加载未完成时保留已接受画面；失败或取消保持现有资源和呈现，向原来源报告。快照对可重载资源保留来源，其他资源持有独立载荷租约。资源 source 冲突判断保持原注册身份，驱逐和重载不会改变 handle。

后端在候选帧缺少 CPU 像素时报告该候选、设备代次及精确资源租约的有界需求，容量计入既有准备预算；同一需求按资源身份和版本去重。Player 将需求交给现有 Assets 异步请求，保持候选 `Preparing` 和最后接受画面；完成后核验同一候选与设备代次，恢复原资源，再通知呈现协调器继续该候选。取消、会话切换、表面变更或设备重建取消对应需求，已提交 GPU 工作按原完成信号退休。GPU 后端只声明实际缓存缺失，读取、解码、请求合并、取消与错误由 Assets 管理；资源本身只保存描述和驻留或缺失的像素，不维护第二套加载状态。

后台 IO、解码和完成队列使用明确容量。请求接受前预留结果位置；拒绝时返回原请求及其所有权。消费者暂时占满队列时保留待处理工作，由释放或完成通知唤醒。过期结果沿原所有权路径释放。

Vita 使用统一 C/newlib/Rust 进程堆，CRT 从一个 1 MiB 缓存 MAIN arena 开始，按需创建独立系统 mspace 和内核块。额外 arena 全空后归还整块，释放失败保留 UID 与费用；首块供小分配复用。CPU arena、GXM ring、USSE、MAIN 纹理与缓冲及固件调度块共用实际 MAIN 提交账本，按含头部的完整页对齐容量计量一次，物理释放成功后归还。宿主启动图形及会话/媒体工作线程前，以内核剩余 MAIN 加已纳管提交量确定容量；SFO 扩展额度、已加载程序、线程栈和 SceLibc 堆分别核对，后续未纳管 SDK 分配仍可能导致内核分配失败。VM 和资源域保留各自准入，不将多个 VM 对共享验证代码的本地额度重复加入物理账。连续物理 MAIN 使用内核单独报告的剩余额度；视频块同时保留媒体本地额度与连续区物理票据，NV12 导入仅共享原块。普通区和连续区的剩余值分开记录，不假设它们互不重叠。

预算分别覆盖 VM 堆、CPU 源与输出、解码工作区、GPU 驻留和临时目标。Windows、Linux 与 macOS 的 WGPU 窗口默认分别提供 1 GiB 的 GPU 资源和离屏目标额度、64 MiB 渲染临时数据额度，每次图片准备最多上传 64 MiB 暂存数据；CPU 已解码资源默认上限为 512 MiB。预算按需占用，分片提交通过 `Preparing` 等待继续，分配压力按对应账本回收缓存。显式传入的预算和 Vita 配额保持原值。各账本记录其实际拥有的存储；进程 RSS、驱动和第三方解码器的内部工作区需要独立测量。详情见 [reel-core](../crates/reel-core/src/lib.rs) 与 [VM](../crates/aside-vm/src/lib.rs)。

来源复用使用弱租约与预算内的身份索引；索引命中后核验完整路径、版本和种类，退休资源不得新增租约。索引容量和增长重叠计入 Metadata，额度不足时退回来源表扫描；关闭服务释放索引。

归档索引使用紧凑记录和共享 UTF-8 路径区，条目借用索引存储。`Metadata` 账本按索引、挂载表和解析工作区的实际容量准入；`AssetOptions.metadata_bytes` 默认上限为 32 MiB。解析工作区在挂载后释放，索引与挂载表随 IO 工作线程释放，解码工作区使用独立账本。

## 舞台、布局与文字

每个舞台节点有一个逻辑父节点。构造返回未挂载节点，`add` 与 `stage.replace` 提交挂载，`remove` 退休节点，`move` 在同一父节点内调整顺序。节点身份承载回调、焦点、活动与资源引用。

`layered_image` 按数组位置组合图片。整组、单个位置和图片属性都可绑定。更新表情时保留同一位置的图片节点；位置取 `null` 暂时隐藏，缩短数组则退休尾部节点。构造器与普通 `image` 共用属性和默认值。

可见控件的 `image_skin` 已声明各交互状态的美术。播放器在当前画面就绪后用空余预取预算准备这些路径，同源的状态共享请求。未选中的状态不参与首屏就绪判定；固定尺寸图片沿用视口筛选。

`image_skin` 和 `appearance` 的 `highlight` 表示鼠标指向或导航焦点下共用的外观。分别指定 `hover`、`focus_visible` 时以专属样式为先。同一张图集中的状态可以直接写裁剪矩形，沿用基础图源。

舞台投影记录节点属性、共享效果和作用域覆盖层的弱依赖。VM 为已观察对象保留有界写入记录，宿主按受影响节点同步；拓扑或依赖变化时重建索引，记录溢出及快照恢复时完整同步。记录和索引计入堆预算，观察关系随对象退休失效。

固定画面使用 `stack` 和位置属性；行、列与网格使用 Taffy Flex/Grid。布局读取直属子节点和已有文字测量，尺寸或属性改变后沿失效路径更新。父级变换和裁剪同时作用于绘制与输入。绘制遍历向控件传递窗口视口和内容变换，按可见范围裁减内容的控件再换算局部视口。

逻辑画布按 contain 映射到窗口，留边和缩放使用统一变换。画布尺寸定义作者坐标；离屏目标由实际绘制效果和物理输出需求分配。`camera` 把世界区域映射到视口，HUD 可放在相机外。重复的相同物理尺寸和缩放通知保留呈现表面与已接受几何；实际尺寸或缩放变化、表面丢失与恢复会重新配置表面。

`list` 按 key 复用行组件；记录替换更新数据连接，稳定 key 保留组件身份。虚拟列表根据视口、行高和缓冲范围构建行，来源数据仍由调用方持有。`VirtualListNode.scroll_to` 等待目标行的位置与呈现；取消、过滤、尺寸改变和退休沿列表活动处理。

虚拟列表在可见范围两侧各准备四分之一视口的行，剩余缓冲低于八分之一视口时补充。焦点、活动导航和显式定位的行另外保留。冷页面因此按可见窗口附近的需求构建，实际行高反馈继续修正范围和滚动锚点。

虚拟列表通过普通容器取得最近滚动所有者的视窗，祖先裁剪的交集沿已有布局与局部变换映射到列表坐标；嵌套滚动节点建立新的所有者。反馈使用逻辑偏移，瞬时回弹不改变行窗口。空可见范围不构建普通行，显式导航和焦点保留行仍遵循各自生命周期。同一滚动所有者可以关联多个列表，手动输入取消定位及布局 clamp 对所有关联列表生效。视窗沿既有投影与 compose 传递，可见性摘要沿原投影构建，不为反馈再扫描整棵节点树。

滚动所有者关联使用节点索引维护，输入只访问该所有者的列表。缩放系数、可滚动上限和有效裁剪属于瞬时几何，恢复后由当前布局重新反馈；其变化不扩充持久列表续体。定位和滚动锚点使用同一坐标映射，尚未取得当前几何时继续等待反馈。

滚动回传发布用户输入、布局尺寸变化和越界修正。滚动视口把已接受的逻辑范围发布为只读可观察属性 `max_scroll_x` 和 `max_scroll_y`，以逻辑像素计。尚无布局、内容未超出视口或轴关闭时对应上限为零。虚拟列表随视口更新可见范围和锚点，同一行集合及布局批次复用已提交的行高和焦点保留结果。普通行窗口的内容高度、行身份和偏移相同时沿用已提交的几何版本。

滚动节点的 `overscroll` 默认为 `clamp`；`bounce` 为直接触摸拖拽提供边界阻尼和放手回弹。逻辑偏移、滚动条和虚拟列表反馈始终使用合法滚动范围，绘制与命中额外应用瞬时弹性位移。滚轮、手柄和作者位置写入沿原逻辑定位；定位、尺寸变化、隐藏与取消清除弹性。回弹使用 Rust UI 动画通道与播放器的单调时钟，按目标更新频率请求帧，结束后恢复休眠；不创建逐帧脚本任务。快照保存逻辑位置，恢复时重新开始瞬时交互状态。

`bind` 连接可观察属性，`derive` 连接派生值。派生计算读取上游时先完成其待重算，以同一状态评价依赖和结果。写回、循环检测与取消使用共同属性协议。临时 `override` 与 `offset` 在作用域结束时撤销自身图层，保留底层业务值和动画。

`appearance` 将绘制属性组织成不可变共享值。投影从基础外观开始，依次覆盖当前生效的 highlight、hover、focus_visible、pressed、disabled 属性，最后应用作用域 override。节点与绑定在状态切换时复用，快照恢复会清除瞬时交互状态并重新投影。属性范围与示例见[接口声明](../crates/reel-engine/src/aside/stage/interaction_appearance.rs)。

文字由 `reel-text` 整形、换行与编辑。字体文件由作品提供；字体族、字重与回退参与同一次匹配。布局保留字形位置、字簇与源文字范围，绘制直接消费布局结果。同字号、同宽度约束的测量复用已有换行结果，包括不可断词超出宽度的布局。逐字显现改变可见范围，颜色改变复用几何；文字或影响布局的样式变化触发重排。

富文本保存正文、样式、ruby、链接和句内时序。普通字符串按原文显示。竖排通过文字的逻辑书写轴布局，字形方向、注音、光标端点与命中位置使用相同几何。`stage.geometry` 返回完整文本末尾插入光标的边界 `text_caret`，用于按实际行高定位继续标记等局部控件。

文本编辑控件以同一事务处理键盘、输入法、选择、撤销和过滤；预编辑与已提交文本分别保存。单选组按共享属性身份组织导航，虚拟行通过所属列表解析目标。

属性和控件接口见 [Stage](../crates/reel-ui/src/stage)、[作者节点](../crates/reel-engine/src/aside/stage.rs) 与[文字](../crates/reel-text/src/lib.rs)。

## 输入与已呈现画面

`input(on_back: callback)` 将 Escape、指针次键和手柄 East 的释放事件接到返回动作。显式 `actions.back` 优先，生成的动作沿普通输入绑定和回调路径执行。

布局和绘制产生候选画面及对应几何。后端接受该候选后，输入使用它的冻结几何；准备、提交或呈现失败时继续使用上一份已接受视图。一次输入固定使用同一几何快照，并核验节点当前存活、可见、启用和模态资格。几何与输入配置稳定时，候选共享不可变几何存储，各自保留接受身份；存储额度保持到最后一个引用释放。

后端返回 `Preparing`，或暂时资源压力可随在途工作完成而解除时，协调器保留该候选，收到资源完成后继续准备同一帧。期间脚本和输入继续推进，后续变化在该帧被接受后生成下一候选。回收后仍无法继续、且没有待完成工作的请求按拒绝处理，后续状态变化可发起新候选；缺失像素按候选身份和设备代次恢复。切换会话、显示表面或挂起会取消未完成候选，已提交资源继续随 GPU 完成信号退休。

字形准备将 CPU 栅格化与设备图集分配、上传分开。CPU 阶段按缺失字形去重并生成有预算归属的覆盖位图；桌面按有界批次并行计算，设备阶段按原绘制顺序上传并保留实际墨迹边界。原生资源和提交仍由平台后端持有，准备完成后沿用同一候选的接受流程。

填充字形使用缩放后轮廓的控制点范围确定栅格区域。描边按展开后的轮廓取界。

截图使用独立的临时离屏目标，沿用设备共享预算。截图尺寸、捕获排除规则与读回生命周期归截图请求持有；正常画面的目标池、几何和效果缓存继续复用，在实际预算压力下按原回收规则释放空闲存储。

`input.on_pointer` 接收命中区域内的移动，以及主按钮或触摸开始的拖动。坐标相对输入节点；`event.dragging` 表示该节点的主按钮或触摸拖动仍在进行。悬停保持当前焦点，拖动捕获持续到释放或取消。

指针捕获属于当前手势和节点；隐藏、禁用、退休、失焦或模态范围改变会结束失效手势。键盘与手柄通过命名动作汇合，控件消费自身确认、方向和编辑输入，其余事件沿祖先传播。一次输入至多推进一次剧情。

`stage.focus(target, owner, visibility)` 返回可等待的 `FocusOperation`，结果为 bool；owner 默认当前作用域。请求等待包含调用时舞台变更的已接受帧，在当前输入与模态作用域内向可见、启用、可聚焦目标申请。成功返回 true；目标隐藏、退休或被模态遮挡返回 false 并保留原焦点；owner 退休取消未完成请求。`visibility` 默认为 `"show"`，交接时显示焦点提示；`"preserve"` 保留应用交接时的提示状态，随后方向或确认输入显示导航提示。焦点沿现有导航树与节点身份保存。

`stage.focus(null, owner)` 在画面接受后清除焦点、提示及尚未释放的确认输入。owner 的节点锚点须处于当前输入作用域；未绑定节点的请求使用当前舞台根。清除后，方向键、Tab、指针或显式交接重新选择控件，确认键沿页面输入处理。

按钮的 `focusable` 默认为 true。设为 false 后，方向导航、Tab 和显式焦点交接跳过该按钮；指针悬停、按压与点击沿用按钮交互。配合 `focus_on_pointer: false` 可在指针操作时保留其他节点的焦点。

`stage.input()` 返回只读可观察的最后输入方式与手柄按键布局。有效按键、指针移动和越过死区的手柄输入更新来源；连接、释放和导航重复保持当前来源。平台按设备标识提供可识别布局，未知设备使用通用布局，图标由作品选择。恢复存档后由当前宿主输入状态更新提示。

弹出层和系统菜单参与同一层序、焦点与模态路由。窗口外点击、触摸滚动和指针取消按事件终态处理。几何查询和捕获引用已呈现帧，保证显示位置与交互位置一致。

公共呈现协调器管理候选身份、SurfaceEpoch、接受记录、重试与曝光重绘。表面尺寸变化和恢复使用新的 epoch；设备重建还更新设备 generation。临时资源压力等待完成通知，永久拒绝等待状态或尺寸改变。

截图提交遇到临时资源压力时，继续持有已接受的原帧，等待后端释放提交容量后重试。后端拒绝或读回失败时将错误交给截图请求的等待者。

## 绘制、转场与 GPU

编译器为可证明的固定源采样偏移导出范围，并将其绑定到着色器内容身份。共用效果规划从输出所需区域反向计算各级效果需要读取的源区域，按原效果逻辑尺寸换算到原栅格，并包含双线性过滤的邻接像素。规划收缩实际绘制裁剪范围，保留原采样栅格、视口、坐标参数和每次绘制的量化行为。无法确定采样范围或变换边界时使用完整源域。

普通中间效果可在原栅格上使用从原点起的二分物理窗口；公共计划冻结每次输出的窗口及实际存储寿命，缓存仍以原逻辑栅格和有效区域标识内容，采样保留原存储换算与量化边界。

效果结果缓存沿用共同目标计划选定的质量和存储映射。绘制前已证明完整来源、采样网格与语义裁剪一致的缓存输入，其有效像素覆盖请求输出及编译器证明的采样邻域时，可替代独占效果链的源绘制。覆盖查询沿用既有内容身份，新物化输出仍按实际栅格建立精确身份；共同计划删除被替代临时目标的存活事件，并计入缓存输入的完整物理分配。多个视图共享的分配计费一次。选择超出预算时按物理所有者缩减候选，恢复相应的原始绘制，保持选定质量；目标分配与绘制消费同一选择。新物化输出在最终计划的剩余额度内延长寿命；整帧编码结束后，仍保持本次写入版本的临时目标可直接转为待提交缓存输出，沿用已有物理分配和在途寿命。下一帧准备时，未被选作输入的封口输出解除缓存持有，保留依赖元数据。GXM 在编码途中保留新的普通输出前，取得计划之外同尺寸、格式和布局的驻留目标补回临时池；缺少替换目标时保存依赖元数据，输出继续正常回收。宏瓦片已按完整图集准备，其单元留存沿用整份分配。首次出现的效果可留存输出；同一来源家族的依赖发生变化后，先随成功提交保存身份元数据，下一次相同依赖再次出现时恢复像素留存。连续变化的效果因此保持临时目标可复用，元数据沿用同一预算和冷却回收。单帧多次读取同一物理结果只持有一次局部目标额度。容量不足时按原质量重新计算并正常回收临时目标；共享压力回收保持已提交租约，只有实际释放容量后才进行一次关闭可选结果留存的重试。

稳定多图片子树可作为同一个效果结果的完整来源。来源身份保留有序绘制记录、各图片版本与采样参数、实际变换以及共同的无效果外层边界；查找借用当前帧，缓存发布时才保存计入预算的来源记录。缓存复用保留原始逐层混合与量化，并沿用输出目标的物理准入和提交寿命。

同一视口的桌面离屏目标按通道格式与采样数分别复用。整帧质量档切换保留其他档的空闲分配；所有档共用原有目标预算，压力回收按使用时间释放各档空闲目标，并保留当前档的本帧存活需求。已提交、保留结果和效果输出继续持有各自的物理租约。

桌面表面配置时，为能在剩余预算内共同驻留的既有质量档准备全屏临时目标及其缓存元数据。最高质量档的预算可容纳三个目标时，提前准备转场两侧和合成输出常用的三个分配；其余情况和较低质量档各准备一个。重复配置复用已有分配；准备目标继续参与正常压力回收。实际绘制仍按整帧需求选择质量档。

桌面上传缓存仅在设备的首次表面配置时准备两个已映射的暂存缓冲。每个缓冲按一张当前窗口物理尺寸的 RGBA16F 图片估算，并受单次上传工作额度和 GPU 资源预算八分之一的限制。大图按实际需要申请上传缓冲。提交完成且映射恢复后复用缓冲。压力回收释放空闲缓冲。后续窗口配置保留现有上传缓存。

上传暂存缓存按最小足够容量取用。普通图片的像素行和预制纹理的压缩块行可用同一提交中的多个复制区间，只为映射余量放不下的行分配新空间。同一帧先完成已开始的上传，再优先用暂存余量处理小图。新建纹理的有效范围不超过半幅高度，或整图本来就需要拆成多个复制区间时，只上传覆盖范围内的行，其余行由设备清零。复用旧纹理时写入全部行。槽位满时保留容量较大的可复用缓冲；空闲存储仍由原资源预算计量和压力回收。性能报告单独记录图片上传缓冲的分配。

性能记录的逐帧计数保存桌面准备实际选定的三种颜色目标质量档，重复准备也分别计数；质量选择与提交耗时分开记录。

文字布局的逐帧记录分别测量整形、换行与绘制范围索引。控件布局字段统计实际运行的布局，其余耗时包括尺寸求解、控件放置及段落构造。

同一图片的连续精灵以共享资源、采样与外部变换加有序实例记录。实例保留位置、尺寸、旋转和透明度；帧编译计入拥有存储，两后端使用共用几何展开并保持原绘制位置、裁剪和组混合。

UI 记录有序 `VisualLayerPlan`，每段保留绘制者、变换、组、裁剪和资源。节点共享不可变绘制记录及其局部元数据，变换由片段携带；变换、子树合成和局部装饰分别使对应阶段失效。重绘建立新记录，已有候选继续持有原内容。`FrameBuild` 按命令、工作和字节额度生成拥有资源租约的不可变 `RenderFrame`。诊断指向实际命令和节点；取消释放尚未发布的候选。

帧构建按即将分配的结构与载荷扩展预算票据，完成后释放构建临时存储的额度。共享帧池计量已接受帧、在途帧与候选帧实际并存的容量；字体和图片通过租约共享各自的资源存储。

图片、路径和字形沿同一坐标与裁剪体系绘制。变换使用前向组合，输入查询在需要时求逆。几何外延包括描边、抗锯齿和效果扩张，未知或溢出外延由后端按实际输出区域裁限。

图片、路径与字形的几何按原绘制顺序写入共用缓冲，索引宽度按顶点范围选择。相邻绘制的纹理、采样、着色器参数和裁剪状态一致时合并索引范围；两个后端共用合批规则，目标切换和合成保留提交边界。

稳定绘制记录在资源依赖连续一致后缓存不可变几何，并持有相应字形租约。两后端按有序几何段复用已完成的缓冲，只更新变化区间；连续变化的记录仅保留依赖信息。缓存容量计入资源额度，帧准入出现压力时释放缓存并恢复完整上传。

离线图集按 `resources.toml` 的显式规则划分共同驻留组；每个原逻辑图片保留自身路径、尺寸与页内内容区域，同一页由一份物理纹理和像素所有者共享。页及视图在离线准备时原子发布；每页只含基础层，各项边缘复制 gutter 并独占压缩块，图像坐标、局部裁剪、重复、九宫格、遮罩和效果采样均限制在该视图。运行时按页的资源身份合并读取、恢复、上传和物理计量；取消一个视图不取消其他视图的请求。快照保持各视图身份并共享页。

图集成员的整图重复以视图为周期，线性过滤在接缝按对应轴首尾 texel 混合，最近邻过滤按视图坐标回绕。显式 `source_rect` 使用原区域重复与边缘填充语义。覆盖整张物理纹理的 identity 视图使用原硬件采样；普通图集完整视图窗口可复用区域固定着色器。

普通图片按整图或区域采样选择固定着色程序，两后端共用分类。区域采样保留片元阶段的半纹素边缘限制，覆盖图集裁切和纹理填充；单层纹理的共用几何证明包含光栅采样偏移的纹理坐标始终处于限制内部时，可直接采样。程序分别保留 RGBA、BC1 和 BC3 的透明度语义。

纯色绘制直接输出线性预乘颜色。已证明输出完全不透明的纯色和普通图片使用覆盖写入；透明度、覆盖率和混合状态参与合批判断。图片注册保存有界的透明覆盖信息，绘制按过滤足迹裁减零输出区域，并按投影像素高度合并覆盖条带，保留全部非零采样且条带互不重叠；源纹理坐标沿用原变换。图片需求按来源、可见性与实际布局视口依赖失效，纯绘制更新复用需求与租约；资源完成和视口变化重新准备。

WGPU 的纯色与渐变绘制共用一个设备代际内的常量纹理，首次使用时完成队列初始化。后续帧复用同一个驻留纹理，在途候选持有资源租约。

舞台投影共享挂载资源索引，来源、可见性及弹出层资格变化时更新。索引保存图片、遮罩和效果的路径与使用节点；布局和视口查询只选择需要的条目，资源服务增量更新订阅。隐藏节点保留挂载身份，已接受画面继续持有其资源租约。

虚拟列表按挂载行和投影身份复用资源索引。视口就绪使用当下的布局、裁剪和绘制外延，卸载行时释放它的索引。

已挂载的定尺寸屏外图片在两次连续布局变化中都接近视口时，播放器根据近期移动距离预测短期入画，并以预取优先级读取、解码。预测使用当前裁剪后的视口，虚拟列表沿自身的行准备机制处理。可见需求与画面发布仍按实际视口判断。

播放器可预取当前可见页面直接拥有的隐藏模态界面。它沿打开该界面后会显示的子树收集图片和效果，仍隐藏的子页等实际选中。每个舞台图片订阅最多用源资源预算的四分之一保留预取载荷，按共享物理 backing 去重；字体和可见资源继续按源资源总预算计量。各订阅串行准备预取载荷，并在解码准入时同时受剩余预取份额和源资源总预算约束。可见需求变化时取消无关预取并释放需要回收的隐藏载荷。预取资源变为必需资源时，原请求及其共享图集页改用可见优先级，已经结束的预取失败可按可见预算重新请求。布局、字形与 GPU 上传仍在实际绘制时准备。节点移除或关闭会话释放所属请求与租约。

构建器沿普通调用、已知分支和有限数量的后续对白分析下一次 `image` 或 `layered_image`，将调用位置与图像常量编号写入 ASB。播放器在对白揭示、推进或等待有限演出完成时查表，遇到普通返回时继续查外层调用。对白路径优先，演出等待只检查最近八个，时钟的连续 tick 不参与。分析可读取已知的表字面量键、函数转发和 `stage.transition` 回调中的已知按值捕获。`layered_image` 跳过空槽和重复路径，一次最多选八层。选择、未知调用和无法确定的路径结束分析。候选与舞台皮肤共用预取份额，读取失败留到图片实际显示时按通常规则处理。存档只保留剧情状态，读档后按恢复的位置查询同一份计划。

[视觉资源自动准备提案](visual-resource-prediction.md)说明更复杂的图层、页面与分支的处理方向。

默认 WGPU 后端使用图片与字形四边形、Lyon 路径网格和按相邻状态合批的提交。窗口配置按尺寸和目标预算预热首选质量档，其他档位在帧计划首次选中时准备。同一质量档的网格、实例和覆盖绘制共用着色模块。同一遮罩表达式的混合变体共用生成的着色模块，帧所需的遮罩管线在画面接受前准备。字形栅格复用 Swash；图集键包括字体、字号、字形、变体、描边和字形变换。图片、字形与管线缓存属于确定设备代际。

WGPU 将完全不透明的 sRGB 解码图片直接上传为 8 位 sRGB 纹理，由设备在采样时转换为线性值。带透明度的解码图片在上传时转为线性预乘 RGBA16F，复用已有的非零透明度范围，并清零暂存缓冲中范围外的像素。普通线性采样画刷的绑定由对应纹理或图集页持有，同一管线布局下跨帧共用并沿用纹理寿命。动态外观、视频和其他采样状态按普通批次准备绑定。分配不足时，WGPU 按当前缺口回收可释放的退休图片及最久未用的空闲图片。

桌面设备在着色模块和绑定布局通过验证后，并行创建独立的基础管线组或遮罩混合变体。每条线程验证自己创建的管线，整组成功后才写入设备缓存。自定义效果的顶点输入和混合变体复用同一份 WGSL 模块、绑定布局和管线布局。

渲染准备收集本帧可见字形，复用已有栅格并在绘制前完成新增字形上传。合成组需要解析未知外延时，字形的实际栅格位置、尺寸和变换提供该边界。隐藏文字在进入可见绘制记录后准备。准备数据、图集区域和资源租约保持到最后一次 GPU 使用完成。

合成采用线性预乘颜色，输出时编码到表面。组先合成子内容，再应用一次组透明度和遮罩。`crossfade` 混合完整的前后画面；`subtract` 对线性预乘 RGB 计算 `max(dst - src, 0)`，保留目标 alpha。

只含一次矩形图片或纯色绘制的普通透明度组，可将透明度并入该次绘制。组内矩形裁剪在当前采样方式下可由 scissor 精确表达时一并折叠；重叠绘制、效果及保留转场或捕获边界保持原合成过程。GXM、WGPU 和目标准入共用这项规划。

纯裁剪覆盖且不携带效果、遮罩效果或延迟效果尾部时，独立目标只保存原覆盖通道；其他裁剪继续使用原颜色格式。WGPU 在格式支持渲染、过滤及所选采样数时，以 R8 UNORM 或 R16 浮点保持原颜色目标的通道精度；GXM 使用 U8 alpha 表面并以同值复制到 RGBA 的纹理视图供 alpha/red 消费。GXM 独立图片遮罩和转场表达式输出同样只保存标量覆盖。颜色与覆盖目标按独立物理类别规划与复用，格式不支持时沿用颜色目标。

`effect(function, params)` 将纯 Aside 函数编译为舞台效果。首个参数 `Fragment` 提供局部坐标、尺寸和子树采样；其余具名参数沿用绑定更新。float 结果作为覆盖率，四元组结果作为线性预乘颜色。效果作用于节点逻辑矩形，先处理子树结果，再应用组透明度、遮罩和混合。已物化的独立效果结果可在来源内容、效果参数和资源身份、采样网格、裁剪及输出格式均一致时复用；完整输入相同的效果保留内容版本，临时结果可将该版本传给后继；内容元数据与像素驻留分别管理。同栅格、单一消费者的串联效果在绘制前沿已提交内容版本查找现有物化结果，命中后跳过其源绘制与前置效果；各层原有裁剪、采样和量化边界参与身份判断。缓存像素持有原目标预算和在途租约，内存压力可以释放已缓存结果。稳定普通结果所需的替代临时目标在绘制前按剩余预算准备。同一效果节点与效果定义的结果新版本替换旧版本，串联效果通过来源家族延续替换；在途旧版本仍持有其原目标直至提交完成。直接合成到父目标的效果保持原有融合路径。WGPU 效果参数缓冲与绑定可按设备对齐容量复用，准备中的实例独占缓冲，提交完成后归还；取消及内存压力释放可回收所有者，缓冲和绑定引用的资源保留原预算与租约。编译产物随源码、ASB 和资源包传递；目标着色器由构建工具生成，运行时复用程序并更新参数。两个后端共用类型、坐标、颜色和资源生命周期，设备程序及其租约保持到在途使用结束。

普通组的颜色效果已声明不读取子树源时，共用准备计划跳过被完全替换的子绘制和原始源目标，图片、字形需求与两后端目标准入、执行共同消费该选择。效果自身的图片参数、数值、逻辑域和物理采样网格继续保留，输出沿用原有物化、量化与组透明度合成路径。标量覆盖率、源采样、裁剪、遮罩、滤镜、特殊组混合或反色继续准备原子树；含保留转场或捕获排除范围的绘图，以及捕获准备，保留完整依赖。消除只作用于绘制消费者，节点交互、更新和生命周期沿用舞台模型。

普通 source-over 命令段由共同计划逆序证明不透明覆盖，完全被后续内容覆盖的绘制同时退出图片需求、字形准备与两后端执行。覆盖集合有固定上限并保留矩形并集中的空洞；轴对齐或直角旋转的不透明矩形提供覆盖，分数边缘只提供保证全部采样点被覆盖的内部。精确矩形 scissor 可以参与证明；其他裁剪、隔离组、遮罩、效果、背景读取及保留或捕获边界截断证明。图片注册时保存完整 alpha 的证据，逐帧规划复用该元数据与既有不透明 RGB 格式契约。原坐标、混合、量化和交互生命周期保持原义；临时元数据额度不足时保留原绘制路径。

源码中可静态确定的纯遮罩构造使用同一效果 IR 和着色器产物。效果定义通过函数或遮罩模板绑定；模板以运算结构、采样方式和常量确定身份，图片路径与节点动态参数由实例提供。构造或修订时解析绑定，逐帧复用；运行时才能确定结构的遮罩沿用动态构图路径。

图像节点的 `sampling` 在 `linear` 与 `nearest` 间选择。过滤方式属于绘制状态，与解码、压缩纹理和驻留缓存的身份分离；两种方式沿用相同的缩放、图集窗口、分块 gutter 和打包透明度坐标。子树效果读取已按该方式绘制的源图，效果、遮罩、字形和内部合成各自保留既定采样方式。

效果函数的 `Texture` 参数接收 `texture(path)` 创建的图片来源。来源沿普通资源加载、平台覆盖和纹理转换路径解析，实例保存数值与图片绑定，编译定义保存静态运算和采样结构。图片采样返回线性预乘颜色；alpha 和灰度采样沿用遮罩通道语义。数值与图片使用各自的类型和绑定布局，资源就绪后发布候选画面。节点的 `mask` 可接受输出为 float 的效果，沿同一编译与资源准备路径生成覆盖率。

float 遮罩效果在完整局部域中一次生成子树颜色与覆盖率的乘积。后续仅需普通 source-over 时，投影直接写入父目标并应用一次组透明度与反色；裁剪、其他遮罩、背景读取和保留内容按各自依赖顺序处理。

普通绘制进入当前目标。独立组、遮罩和转场按实际需要使用离屏目标；目标池按尺寸、格式、采样数、resolve 和在途重叠计量。后端根据能力与预算选择质量档，目标在首次写入或读取前初始化。资源租约和预算保持到 GPU 使用结束。几何与上传缓冲在提交完成后进入复用池；退休图片在源租约及 GPU 读取者全部释放后，可按格式和存储尺寸复用。图片复用池按已接受提交更新闲置年龄，实际复用次数决定有界保留期。闲置容量继续计入资源额度，超出保留期或遇到压力时释放。

完整覆盖物理目标的替换合成可直接写入全部采样点，省去旧内容的初始化。共同规划核对视口、裁剪、存储尺寸和混合方式；GXM 选择不含裁剪丢弃的程序，WGPU 使用 `DontCare` 附件加载。完整物理目标上的独立效果可选择构建时生成的完整目标变体，将局部域外的丢弃改为透明输出；坐标计算保持相同，效果附件仍初始化后写入。局部覆盖、填充区域及未写入即读取的目标保持透明初始化。WGPU 的原生实例允许这项扩展；适配器中的单个 `unsafe` 授权点由完整覆盖证明约束。

几何批次保留有序片段，共享打包路径直接生成顶点和最终宽度的索引。WGPU 写入映射上传区，有空余预算时为复用缓冲保留少量额外顶点和索引容量。GXM 使用计入瞬时预算的 CPU 上传区。局部更新保持完整批次的顶点偏移与绘制顺序。

精灵的完整矩形输入可使用共同实例布局：每实例保留 CPU 按原精度计算的四个最终角点和颜色，批内共享 UV、采样窗口与四角索引。顶点程序只选择已有角点，片元、混合及实例顺序沿用普通绘制；相邻兼容实例段合并。分带支持、几何裁剪及特殊合成继续使用展开几何。实例与普通批的切换按实际上传成本和提交次数选择，小批保留合并机会；模板、实例、索引及上传存储计入原几何预算，并持有到最后一次 GPU 使用完成。

实例化首先用于独占普通绘制批的兼容连续精灵段：模板和索引摊销后上传字节至多为展开路径一半时选择实例。普通绘制在同批前后相接，或实例材质、采样模板及裁剪边界变化时，在准备后续几何前恢复原展开批，保留原 draw 与 render pass 合并机会；原批已达到字节或段数上限时仍可开始下一实例批。

几何完全位于裁剪区域内部时，两后端沿用视口裁剪并合并相邻绘制状态。GXM 在硬件 tile 与表面边界可精确裁剪时使用普通片段程序，其余区域使用精确裁剪程序。矩形合成将几何边界收缩到整数像素裁剪范围，纹理坐标保持原视口网格，省去片元裁剪；普通转场按有无遮罩选择固定程序。程序按实际使用创建并持有预算。

嵌套效果使用相同局部域和变换时，沿用已确定的采样网格和效果到源栅格的局部映射；源几何继续使用原帧坐标映射，效果坐标直接使用局部映射，避免重复逆变换抵消。单一效果子组与隔离父组使用完全相同的源尺寸和采样坐标，且父组独占该源目标时，子组结果直接交给父组继续处理，连续效果交替复用临时目标。图集中的父组持有区域使用权，子效果保留独立输入并将结果合成回该区域。组透明度、混合、裁剪及保留转场或捕获边界仍参与规划。

单采样效果的末级透明度与 source-over 可直接写入父目标，源子树仍完整保留。独立 alpha 覆盖可并入末级合成；只包含一个效果组的独立外层裁剪也可使用这一方式，并保留效果输出、透明度写入两处量化。源与覆盖纹理持有到提交完成，源尺寸按轴不超过被替换的目标。反色、背景读取、多采样及保留边界继续使用独立步骤。转换器生成普通与覆盖两个着色器变体，运行时按公共规划选择。

普通 UNORM 合成，以及颜色分量已证明处于 `[0, 1]` 的纯色与普通图片绘制，可使用半精度颜色运算。坐标、任意作者效果与宽范围颜色保留单精度；WGPU 按设备的半精度能力选择程序。

两后端共用离屏布局，分别记录逻辑绘制尺寸、物理存储尺寸、源内容区域及父目标中的覆盖区域。普通组按已知物理外延平移到源目标，合成时在顶点阶段映射源纹理坐标，恢复父像素位置和采样网格；效果采样保留完整局部源域。已知输出外延完全位于裁剪范围外的组，在目标准入前跳过；保留转场和捕获边界继续参与依赖规划。读取背景的混合保留绘制顺序，有限区域的背景副本只复制对应的父像素，公共规划根据物理成本和存活区间选择存储容量。源与背景保持相同的整数像素网格，坐标映射适配各自存储尺寸。未知外延和保留转场按完整依赖范围准备。目标准入与绘制消费同一布局，尺寸复用同时保留有效内容范围和透明边。

共享规划按存活区间安排不同尺寸源的存储复用，采用能降低总分配峰值的组合。绘制保留原视口和采样网格，采样坐标及边缘约束对应有效内容区域；显存计量包含物理存储、格式和多重采样层。帧输出保持输出表面的尺寸。标量效果需要从更大的存储读取局部源时，共用几何沿源纹素边界分片，在顶点阶段完成边缘夹取，片段阶段保留直接采样。

两后端的临时目标池在既有内存预算内保留已分配存储，提交次序用于选择压力回收的先后。普通裁切组按轴限制在父目标内。桌面多采样的大尺寸目标使用更宽的存储桶，为已在视口内的轴补齐时以视口为上限，保留逻辑尺寸和既有字节上限。较大的普通离屏源也可使用已有的空闲整屏目标，保留当前帧精确尺寸的同时使用数量，容许的存储面积至多为逻辑源的两倍。桌面转场缓存、已准备帧和已提交帧持有同一存储的读取租约，最后一个读取者释放后，该存储可再次用于暂存。新分配或物理内存压力按当前需求回收空闲目标；在途读取者和保留结果继续持有其存储。表面配置与会话切换沿既有生命周期清理缓存。

目标的初始化状态属于本次帧准备。首次写入清空目标，后续写入保留内容；读取尚未写入的源时先初始化为透明。GXM 的普通独占原始效果源可按共同 ROI 证明初始化本次消费者实际读取的物理范围，包含线性过滤邻接纹素、浮点坐标误差及可能回绕的存储边缘，再向外对齐 tile；纹理尺寸、视口和着色器坐标保持原值。原生 Framebuffer 的写入范围属于这次使用，场景有效区域限定右下边界，region clip 同时限定左上边界。宏目标、共享源、缓存结果及捕获或保留边界继续完整初始化。复用存储开启新的使用期并恢复完整写入范围，空画面、保留内容和在途提交沿用同一所有权约定。

捕获的 GPU 结果完成后，主线程按公共字节工作额度逐行复制到一份最终像素缓冲；一次至少处理一整行，尚未完成时唤醒后续推进，取消释放读回和输出。捕获读取结果显式标记像素编码。WGPU 输出 sRGB，GXM 输出线性 RGBA8；捕获服务在现有后台 PNG worker 内原位转换为不透明 sRGB，再编码并交付同一请求。转换持有原始载荷及其预算、不另分配整图缓冲，分块检查取消；直接消费捕获像素的调用方按编码完成同一转换。

GXM 的最终显示表面通过硬件写回将线性 RGB 编码为 sRGB，片元程序使用匹配的 half4 输出格式；离屏合成与捕获使用线性 RGBA8。

临时目标的相邻尺寸可共用容量档。普通目标的单份填充最多占原后端字节成本的八分之一。多重采样的颜色暂存目标使用更宽的容量档，填充最多为四分之一，减少动画中连续扩大的目标重复分配。容量档受整帧物理峰值预算约束。公共规划优先选择兼容格式中已驻留、数量足够的容量，统一确定逻辑尺寸到物理容量的映射及同时存活数量；两后端按该容量复用完整目标。原采样网格、输出尺寸和要求精确存储的源保持各自约束。预算紧时沿用精确尺寸。分配压力按年龄逐个回收可独立释放的目标，当前计划需要的数量及外部读者继续持有存储。

字形上传按图集页和相邻矩形组织批次。只合并能完整覆盖同批字形分配区的矩形，保留其他在用字形及各字形透明边；两后端使用同一合并规划。每批最多保留 64 个字形、64 KiB 覆盖率数据，单个大字形独立提交。准备完成后发布图集条目，在途上传持有其区域与存储。

字形栅格密度按实际物理变换的最大放大率向上取到相邻的 √2 倍档位，缩小显示也使用对应档位。相同档位复用图集，栅格密度至少覆盖实际显示密度；文字布局继续使用作者坐标。

预处理纹理分别保存作者使用的逻辑尺寸、可见内容的纹素尺寸和含边缘填充的存储尺寸。资源以线性预乘颜色提交。BC1 保存不透明颜色，BC3 保存颜色与透明度。纹理载荷是可上传的像素或 BC 块，发行归档使用独立 LZ4 块压缩这些字节。支持对应格式的后端直接上传压缩块，布局、裁剪与输入继续使用逻辑坐标。

纹理容器显式记录存储布局。Vita 转换在离线阶段排列 GXM BC 块，运行时直接复制到原生纹理存储。Vita 单层线性 RGBA8 默认将行宽对齐到八个纹素，并保留内容高度。`power_of_two` 可显式填充两轴。桌面转换保留线性块序。归档压缩继续作用于已转换的字节。WGPU 上传 Vita 资源时在有界条带内恢复线性块序。转换可显式生成完整 mip 链，逐级在线性预乘颜色中滤波并保留基级布局坐标。驻留与上传按全部层级的实际存储计量，纹理就绪后发布画面。

纹理、分块图和图集规则可用 `fallback = "rgba8"` 保留画质。离线工具比较 BC 候选与缩放后的 RGBA8 显示结果，超出误差时直接生成同一逻辑布局的线性预乘 RGBA8。分块图按瓦片选格式，图集按页选格式。回退保留缩放与 mip 选择，存储按最终格式计算。需要保留源文件的资源使用 `convert = "copy"`。

舞台转场冻结已接受内容，在普通脚本回调中构建目标。保留旧画面时，播放器可以低优先级读取和解码已声明的遮罩图，旧画面提交无需等待遮罩，实际合成接管原请求，取消转场后撤回无其他需求的请求。目标就绪并被后端接受后，以接受时刻为起点推进合成。正式剧情读档由当前 Root 根据 State 建立演出画面。粒子以批次配置、种子和时钟描述运动，绘制时采样；发射活动沿节点和作用域生命周期退休。

转场旧画面的 GPU 结果按冻结绘图、父画面依赖、坐标变换、裁剪、输出尺寸和质量档复用。首次准备按依赖分段提交；结果纹理从临时目标池摘除，由转场与在途提交持有，其余中间目标按同一 GPU 队列的执行顺序复用。准备期间保留已接受帧，GPU 完成信号继续推进候选帧。命中的旧画面仅要求结果纹理驻留；缓存与在途使用共同持有资源额度，依赖改变或使用结束后回收。

WGPU 在旧画面提交后即可将其结果交给同一队列的后续绘制，队列顺序保证先写后读。宿主获得一次资源就绪通知；几何、上传区与目标租约继续由原提交持有，直到实际完成后回收。在途提交沿用同一准入额度。

文字记录沿段落的行范围与行内绘制边界筛选可见内容，完全移出视口的段落保留排版结果，重新进入后恢复记录。边界包含字体外伸、合成字形、装饰和注音。图片按内容绘制框跳过视口外记录，效果源域沿原有视口规则处理。

粒子的尺寸曲线以归一化年龄采样，节点 `size_scale` 默认为 1，以有限非负倍率缩放所有存活及后续粒子的当前尺寸。倍率可绑定或动画，保留粒子位置、速度和批次时钟。出生角度与径向速度使用独立随机序列，阻尼按连续时间计算。预热直接设置发射时间偏移，按当前存活区间采样。曲线数据按批次共享，暂停、跳时和恢复沿同一采样公式处理。

绘制消费者可复用粒子出生常量，缓存随当前存活区间滚动，每个节点最多占用 64 KiB CPU 输出预算。超出缓存的粒子直接采样，批次替换后重新建立缓存；快照继续保存配置、种子和时钟。

视频帧使用共享的平面 YUV420 或 NV12 存储，逐平面记录行距，在 GPU 采样时转换颜色。生产者保留存储所有权，上传读取有效行与色度布局。已接受帧和在途提交持有的纹理保持原内容，最终引用释放后复用存储。

桌面视频与静态图片共用上传缓冲池。缓冲驻留期间持续计入 GPU 资源预算。

GXM 对无区域窗口、平铺、附加外观及上下透明度布局的 NV12 绘制使用直接采样程序。程序按帧元数据保留 YUV 矩阵与传递函数，沿共用颜色和混合语义输出线性预乘颜色；其他视频绘制继续使用通用程序。

共享帧可携带平台可导入的只读存储，普通后端仍读取相同平面。Vita 将 AvPlayer 输出复制到有界自有 NV12 池，封存后交给 GXM 映射采样；映射保持至片元完成，最后读者释放后复用块。物理容量和元数据由生产者的预算票据保持至对应存储释放。 PCM 输出的向量和预算票据由解码器一起交给播放队列，队列消费后将两者归还解码器；等待、取消和终止时由当前所有者释放，单一分配只计一次。

视频播放器使用解码器工厂，在后台以资源流、CPU 预算和停止标志创建解码器。新的打开、跳转、循环和恢复请求等待本会话正在退出的解码线程完成清理后再准入；等待期间保留请求位置、暂停状态和已接受画面，控制线程继续处理取消。软件与平台解码器交付相同的帧、音频和内容时间，播放队列、定位、终态与混音消费时钟由共用播放器管理。软件解码依赖按功能选择。

视频工作线程按画面与 PCM 队列各自的剩余容量请求解码。单轨满载时继续供给另一轨；尚未发布完的 PCM 包持有预算并分批写入，全部发布后才通知音频流结束。解码器区分暂未就绪与全部结束，暂停与取消沿同一有界队列处理。

PCM 发布完成后，工作线程可将输出块及其预算票据归还解码器复用。暂未就绪的轮询、定位修剪和队列分批写入保持同一块；实时混音线程消费预分配队列。

图片和视频的 `alpha_layout` 默认为 `"native"`，保留资源透明度；`"top_bottom"` 将上半帧作为颜色、下半帧的编码红通道作为覆盖率，自然尺寸为原宽度与一半高度。`source_rect`、九宫格和平铺使用可见颜色区域的像素坐标。颜色沿原色彩空间解码后按覆盖率预乘；覆盖率直接使用编码通道值。GPU 复用原纹理采样两个区域，布局随节点属性和已保留画面保存。

绘制和设备接口见 [reel-ui](../crates/reel-ui/src/lib.rs) 与 [reel-render](../crates/reel-render/src/lib.rs)。

## 资源加载与媒体

播放器与离线资源工具接受 PNG、JPEG、静态 WebP 和 sRGB QOI。图片按文件内容识别，资源转换保留逻辑路径。每通道最多 8 位的 PNG 只含有界附加块时，播放器根据图头、调色板和透明块直接预留解码空间。桌面可在同一预算内并行解码这些图片。其他 PNG 沿用完整的解码额度。最终解码任务持有编码输入，完成时归还其容量。桌面发行包可用 `webp` 或 `qoi` 规则无损重编码 8 位图片。`qoi` 规则只接受 `match` 和 `convert`，保留解码后的 RGBA8 样本和原有路径。其输出使用 sRGB 和直通 alpha，与播放器处理普通图片时一致。QOI 没有 ICC 等元数据块，播放器会拒绝标记为线性色彩的 QOI。Vita 的纹理、瓦片和图集规则直接读取上述源格式并生成设备所需的纹理数据。

资源通过 `AssetIo` 与后台工作服务读取，运行期间使用固定资源。后台首次读取散文件时确定可用的目标目录，之后只在这些目录和公共目录中查找。散文件按来源路径确定标识，归档使用打包索引中的内容摘要。准备资源时可从无散文件覆盖的挂载索引直接取得长度和版本，并交由后台读取内容。修改素材后重新启动游戏。准备结果按资源标识共享，各消费者释放自身租约，最后一个持有者释放后回收。解码前读取头部并预留输出与工作区，首个场景的字体和图片准备完成后显示，场景换源期间保留上一完整画面。性能报告在后台读取总耗时内分别记录文件定位与打开、内容读取与归档解压的耗时。

QOI 与只含单个有损 VP8 块的 WebP 通过固定文件头提供尺寸，在桌面与有界 PNG 共用并行解码队列。QOI 直接写入预留的 RGBA8 输出。WebP 沿用同一解码器校验并读取像素，只有足以预留有界解码工作区时才跳过后台探测。图片尺寸已知时，播放器可在像素解码期间计算布局，并开始读取视口内其他定尺寸图片。提交画面仍等待需要显示的资源准备完成。

媒体解码线程通过 `AssetIo::background_reader` 独立提交和接收读取，同一适配器的读取端共享 IO 线程、请求身份与有界队列。完成结果由所属读取端消费；每条流在创建时预留一个可复用的完成槽。关闭主适配器取消在途工作，IO 线程结束后释放文件与索引。未实现后台读取的适配器在创建媒体流时报告能力缺失。

最近上传的图片标识由当前资源挂载持有，可用于同一游戏读档或重开后的 GPU 图片复用。缓存仅保留已释放 CPU 像素的标识，复用仍受渲染缓存预算限制。关闭资源挂载时释放这些标识。

普通图片按需解码，GPU 上传按每次工作额度续传，等待期间保留已接受画面。[分块图片](../crates/reel-core/src/prepared_image.rs) 根据实际视口选择层级和瓦片。预取优先让位于必需资源；画面与在途加载各自持有实际租约。资源归档挂载读取索引，内容通过范围 IO 获取。纯归档挂载在一个读取请求的后续工作片中复用首次解析的条目。归档条目保留逻辑长度与内容身份，原样数据直接读取，压缩数据按独立块定位和解压。块目录按需读取，解压工作区按固定容量预留并复用，取消在块间生效。

媒体读取使用实际解码缓冲时长发布软截止时间，同优先级按最早截止时间调度，实时与普通请求沿既有比例交替推进。暂停清除期限，恢复后根据新缓冲更新；共享期限与请求持有同一预算生命周期。归档可在现有编码工作区合并相邻压缩块，临近媒体期限时停止新预读，块间保留取消点。

资源 IO 按有界块续读，输出容量预留一次，块间释放文件锁。续传保留请求身份、完成槽和取消状态，归档游标与解压区计入后台工作预算。预取变为可见需求时，已排队的读取和解码升到可见优先级，正在读取的请求在下一个块使用新优先级。音视频流在队列和输入总额度内保留容量；输入准入从可容纳的流式请求中优先选择最早的消费期限，同期限按到达顺序处理。最早等待者被后续请求越过四次后，保留下一次足够的容量给它。IO 调度优先处理实时块，并定期推进普通资源，避免大型图片读取阻塞音视频补充。

逐帧计时单独记录共享资源队列的推进、图集解析与音频活动维护，资源队列可以从界面或媒体流程推进。

未压缩图片的透明范围按四个像素一组查询，范围端点精确到原像素。已解码图以 alpha 判断覆盖，预制纹理保留非零颜色通道的覆盖。

`assets.read(path, owner: null)` 从同一资源根或归档异步读取数据，等待结果取得不可变 `Bytes`。请求沿现有后台队列、资源预算与所有者生命周期处理；完成数据按 VM 字节存储计量。存档保留已完成数据和在途请求的恢复状态，读取失败指向调用源码。

音频接口返回普通活动，统一管理播放、暂停、定位、循环、队列与音量。短声音预解码，长音轨使用有界 PCM 窗；作者按内容组织调用，宿主选择准备方式。控制线程按入队需求分配片段队列，容量计入描述符预算。音频队列在混音边界连接已准备片段，欠载时输出静音并保留内容位置。

音频活动以正数 `rate` 控制内容播放速率，音高随重采样共同变化；位置、循环端点与 cue 始终使用素材秒数。活动内的队列共享速率，暂停冻结速率渐变，快照保留当前速率和剩余渐变。

Ogg Opus 沿软件解码接口提供单声道与双声道内容，时间线扣除编码预跳过和尾部填充，并应用头部增益。定位包含解码预热，循环使用同一可听帧坐标。编码、容器解析与解码在工具侧或后台执行，复用有界缓冲并计入 CPU 预算。

`reel-media` 创建设备与混音供给。桌面后端首次配置复用创建时取得的默认设备和格式能力，后续显式配置重新查询默认设备。配置取得实际格式后构建 mixer，并准备未启动的原生输出流，首次播放复用它。准备阶段的供给入口保持关闭，停止、重新配置或销毁时释放未使用的流。接受播放后，实时回调独占供给并使用预分配缓冲和有界队列。文件 IO、分配、线程等待和最终 PCM 释放由控制侧或后台服务完成。

桌面播放器持有音频端点。新剧情和读档候选用已协商的格式准备各自的 mixer，只有当前会话能向设备供给 PCM。替换会话时先暂停输出并归还旧 mixer。Linux 和 macOS 复用暂停的流。Windows 端点会保留已排队的采样，因此新会话首次请求播放时，由后台关闭旧流并准备一条空的新流。设备就绪后唤醒播放器，播放器核对路由再接入当前 mixer。退出时回收端点和在途准备工作。

停止与挂起先关闭供给入口并等待在途调用结束。挂起保留 mixer，恢复验证格式后继续；格式变化或设备失败报告实际状态。控制侧移交退休 Sound 及其预算票据，后台物理释放完成后归还额度。会话退出持续驱动退休工作，宿主最终关闭时 drain/join 清理服务。

音频完成表示混音器已消费内容。CPAL 后端的硬件呈现时钟精度为 `Unavailable`；字幕和演出使用媒体内容位置。有声视频跟随 PCM 消费，静音视频跟随会话时间。已排队视频帧的时间戳可以缩短常规媒体等待，提前唤醒后继续由实际播放时钟决定是否显示该帧。

接口与队列约束见 [reel-media](../crates/reel-media/src/lib.rs) 和 [reel-audio](../crates/reel-audio/src/lib.rs)。

## 原生页面与标签

`slider(track: Node | null, thumb: Node | null, thumb_width: 20)` 接收可选的轨道和滑块节点。轨道使用滑块的内容区，滑块沿水平方向移动，`thumb_width` 同时决定它的布局宽度和指针映射。作者可用滑块节点的 `y` 和 `align_y` 调整竖直位置。两个槽分别替换默认绘制，普通子节点可以继续作为覆盖层。

`image_skin` 可作为 `image` 的 `source`。每个状态可以指定资源路径、编码图片或 `{source, source_rect}`，也可以只给基础图的裁剪矩形。图片按 disabled、pressed、focus_visible、hover、highlight、base 的顺序选取第一个适用的外观。省略裁剪时沿用图片的 `source_rect`。图片通过依赖索引订阅控制节点，两者各自保留身份和资源生命周期。

`list(items, key, build)` 的原生声明将 `items()` 的已知元素类型传给编辑器中的内联 `key(item)` 和 `build(row)`。`row.value` 使用元素类型，`row.index` 使用 int。显式回调参数类型仍由作者的标注决定。

`page_stack(value: null, items: [{key, build}])` 在公共舞台中保留按稳定 key 标识的页面。外层规格在构造时复制并检查唯一 key；首次选中时运行无等待工厂，离开页面后保留其节点，重开复用。工厂沿普通 VM 预算让出。空值隐藏全部页面，未知 key 报错并保留已准备投影。内部 wrapper 控制页面的显示与布局，保留作者内容上的 `visible` 和绑定；页面工作与作用域继续按既有所有权管理。

`get(key)` 同步取得已构建节点或 null；`ensure(key)` 返回已有 Task 协议，等待结果取得页面节点，同 key 的并发请求共享一次生产且不改变选中值。等待者退出只解除等待；显式调用返回 Task 的 cancel 沿既有语义取消生产，组件退休同样取消生产。取消或失败结算后可以重新请求构建。`evict(key)` 退休未选中的已构建页并返回 true，未构建返回 false，选中页报错。items 的动态增删通过重建组件表达，页面内容仍可使用 model、bind 和 derive。

`select(key)` 返回页面栈拥有的 Task，和 `ensure` 共享页面构建。最近一次请求在目标就绪后写入页面栈的 `value`，并返回页面节点。被后来请求取代的任务返回 null，取消选择任务时构建仍可用于其他等待者。

已挂载且可见的页面栈等待选中页准备完成；隐藏或未挂载页面的 ensure 不新增页面呈现门控。工厂仍是普通 Task 的同步构建事务，执行与预算让出遵循引擎既有提交边界，准备期间保留上一份完整投影。

`tab_bar(value, items: [{key, label}], build: null, orientation: "horizontal", activation: "automatic")` 提供独立分组的标签选择、焦点、方向键与无障碍语义，与 page_stack 共享同一个可写选中值。方向可为 horizontal 或 vertical；automatic 随焦点切换，manual 由确认输入激活。可选工厂 `build(item)` 构建内容，item 提供只读可观察的 key、label、selected，以及只读 control 引用；control 是拥有输入、焦点与无障碍语义的原生 RadioNode，作者可用其交互反馈与 appearance 自定义标签。组件实现使用 Rust，作者可分别组合标签、页面与其他舞台内容。

标签栏和页面栈可共享同一组 `{key, label, build}` 记录，各自读取所需字段。

`tab_bar(on_select: |event| ...)` 将新的选择请求交给作品，`event.value` 为候选 key。回调由触发的标签控件持有，可以等待页面准备，再写入绑定的选中值。每次选择请求独立派发，作品可以使用现有的作用域、任务取消和 enabled 绑定安排准备流程。

`tooltip(placement: "bottom-start", offset: 0) { ... }` 是交互控件的子节点。控件悬停或显示键盘、手柄焦点时，提示框通过公共弹出层定位。焦点和悬停都离开后收起。提示内容可以组合普通绘制节点，提示层不参与焦点、指针命中或模态路由。

### 原生滚动条

`scrollbar(viewport, axis: "vertical", min_thumb_size: 16, thumb_size: null, step: 40, inset_start: 0, inset_end: 0)` 返回可组合的 `ScrollBarNode`。viewport 是已有 ScrollNode，滚动条借用其逻辑偏移和实测内容/视口尺寸。axis 为 vertical 或 horizontal；thumb_size 为空时按可见比例计算，数值指定固定逻辑长度，最终长度限制在轨道内。公开只读 viewport、track 与 thumb 引用；track/thumb 是稳定内容槽，内部 wrapper 控制其位置和尺寸，作者组合槽内外观。组件退休只回收自身节点。

Rust UI 处理滑块抓取偏移、轨道点击、滚轮、键盘/手柄与无障碍范围操作；主轴方向按 step 移动，翻页按视口长度，Home/End 到边界。`scroll_by(delta)` 和 `scroll_to(offset)` 复用目标偏移的普通写入与限幅路径。输入以已接受几何为准，隐藏、禁用、失焦、目标退休或输入几何失效时取消抓取；释放沿目标 scroll 既有合同处理。逻辑偏移继续由 viewport 保存，瞬时抓取和几何不进入执行快照。滚动条不生成 NodeScroll 尺寸反馈，也不启动逐次移动的 Aside 回调任务。

`viewport.reveal_child(node, margin_start: 0, margin_end: 0, duration: 0, easing: "out", owner: null)` 等待一帧呈现并让最近滚动视口中的目标进入可见区域。边距沿视口启用的轴计算。默认立即写入偏移，非零时长返回普通动画 Activity。默认由视口持有请求和动画，已更新的滚动偏移优先于旧帧的定位请求。

### 原生进度条

`progress_bar(value: 0, max: 1)` 显示完成度。两项均可绑定，`max` 必须为有限正数，显示和无障碍读数将有限的 `value` 限制在 0 到 `max`。`background` 设置轨道，`color` 设置填充，普通 children 叠加文字或其他内容。Rust UI 按已布局的尺寸绘制填充，值变化走普通投影和重绘，无需重建节点或运行逐帧脚本。

## 对白、历史与阅读

对白在提交时建立完整行组并预留历史。推进先补全显现，再结束等待；选择保留由交互身份限定的业务 key。正文、富文本样式和历史内容通过只读模型交给作者组件。

`reading` 保持局部对白、选择、历史、自动阅读和暂停状态。切换 UI 保留上下文身份，嵌套阅读结束后恢复父上下文。历史按提交追加，清理可保留最近的实际行数和剩余行身份。

逐字显现按字素与句内时序推进，从当前对白首次呈现后计时；同一对白的光标等动画重绘沿用阅读计时。图片准备期间暂停计时，包含准备结果的画面呈现后恢复。`ready` 表示正文及尾部停顿完成。已读身份根据剧情调用路径记录，译文切换沿用同一身份。声明了完整 `flow` 和 `point` 路径的对白跨代码更新沿用稳定身份，其他对白按当前代码的调用路径正常播放和登记。正式存档在捕获时验证完整的稳定路径。

追加对白复用已解析的样式、注音和时序片段，只合并文本及调整后段偏移。字素边界保留已完成前缀，从原末尾字素重新分段；新增组合字符延伸已显示字素时，整个字素继续可见。新文本、边界及历史全部准备完成后一起发布。

自动阅读在全文实际呈现后等待延时，在选择处等待玩家。快进沿普通控制流推进，并完成其策略覆盖的有限活动。暂停、模态界面、挂起和失焦按阅读协议更新计时与模式。自定义 UI 读取这些状态，决定按钮、光标和历史页的外观。

快进的可跳过台词先补全文字，再提交首帧；画面接受后才推进剧情。对白结束后，主任务仍可立即继续时合并句间提交；下一交互、实际等待和显式呈现请求仍通过正常呈现流程处理。受保护台词保留逐字节奏与完整画面确认。

## 保存、恢复与系统数据

剧情存档保存稳定流程、等待与返回身份、持久业务对象、活动、当前交互、舞台和媒体描述。恢复使用当前代码定义，业务值保持保存时的数据与别名关系。

宿主属性验证器与回调由当前类型和视图定义重建。

捕获固定会话状态，按对象、边和字节额度推进。媒体播放描述在捕获开始时取样，保存当时的位置、队列和暂停状态；实时媒体输出继续运行。需要改变会话的输入使当前捕获以 `CaptureBusy` 失败，原槽位保留；后台保存完成后原子发布。缩略图与检查点属于同一次槽位发布。列表逐项枚举逻辑存档并打开所选提交代次，解析与文件打开位于同一提交边界；已打开文件保持旧代次读取所有权，缩略图载荷按需读取。

恢复先在隔离候选中分配身份、连接图和重建宿主描述，验证完成后替换当前会话。就绪的恢复步骤共享宿主时间片，等待资源或耗尽时间片后交回调度。代码更新通过稳定身份匹配当前定义；字段类型或恢复点合同冲突时报告具体位置。设备句柄由宿主重建，过期完成消息通过新会话身份失效。

`persistent` 独立保存业务数据，适合设置和解锁进度。读取返回普通数据副本；作者在启动和剧情恢复后应用当前系统数据。剧情槽位与系统数据各自原子发布。

Vita 存储通过不可变数据代际和提交记录实现逻辑文件发布，读取与枚举经过同一存储接口。完整提交后回收旧代际；中断写入保持上一份已提交内容。

正式剧情存档采用单一逻辑格式。切换时删除旧执行快照的保存、读取和格式分支；存储服务继续负责后台编码、缩略图与原子提交。

阅读历史按页保存。采集按预算共享历史页，活会话修改共享页时取得自己的副本。磁盘检查点仍以原有顺序编码历史条目。

作品可以从 Root 调用 `saves.track_history(true)`。播放器在实际呈现的对白等待处尝试采集，单次采集使用固定工作额度。内存窗口最多保留 64 个位置和 2 MiB 的逻辑状态。历史菜单以条目的 `group_id` 查询和请求恢复。点击后复用读档候选与会话替换流程，接入截至该条目的阅读历史，并丢弃后续回退点。

### 跨版本逻辑检查点设计

以下为跨版本恢复的实现合同。本轮直接替换正式播放器的剧情存档流程，并同步更新作者接口与验收用例。

- 持久业务数据采用可检查的类型、稳定字段身份和纯数据默认值。类与静态协议声明提供约束，编解码及新增字段补值由引擎生成。协议不占用作者的基类位置；具体调用形式以直观表达和组合能力为准。
- 普通剧情函数继续组织条件、调用与并行工作。编译器记录稳定等待位置、调用返回位置和所需业务绑定；恢复接入当前代码，已经完成的业务前缀不重放。
- 公共舞台节点、活动和时钟由引擎保存逻辑描述与图内引用，恢复后连接新句柄。自定义长期操作声明 State、当前视图、更新和结果生命周期；视图内部旧帧与回调由当前定义重建。对白、动画、计时和小游戏各自拥有状态并可同时运行。
- 每个槽位保存一份逻辑记录。候选恢复数据与操作，建立当前视图、绑定和等待，并恢复暂停的媒体。候选 Root 可读取系统数据和槽位元数据，磁盘写入请求返回失败。界面可呈现后一次替换当前会话并恢复媒体输出。
- 候选 Root 可以读取当前窗口信息。窗口尺寸和指针移动由活动会话控制，候选准备期间的请求返回失败。需要当前画面才能执行的操作可以在独立任务中等待 `stage.presented()`。
- 逻辑记录的压缩、文件 IO、解码与缩略图使用同一后台通道和原子槽位发布，捕获期间不额外复制完整 VM 编码。

首条验收链路包含两层剧情调用、普通图片和补间、自定义对白视图及同屏运行的状态计数玩法。A 包保存后，B 包修改文案、视图、后续逻辑与更新函数并增加默认字段；恢复应保持对象引用与进度，正确返回调用方，且不重复先前的奖励、历史和媒体开始命令。

### Root、State 与业务执行边界

作者接口表达持久数据、流程身份和普通游戏行为。编译器区分交互等待与流程返回；候选会话、恢复注入、资源重连和帧布局由引擎处理。新游戏和读档共用当前视图与业务定义，作者不编排加载游标或设备句柄。

作者在模块级用 `std::resume::state(GameState, "game.state", fields: {points: "score"})` 声明持久数据类，用 `std::resume::root(start_story, "game")` 声明作品恢复入口。入口的唯一形参指定 State 类型。两者沿已解析的 intrinsic 身份生成编译元数据，并消除声明调用。State 的稳定字符串身份与当前代码索引分开；字段 key 默认取名称，覆盖项保留改名后的身份。继承字段由声明它的基类 State 拥有。当前 ASB 提供类的静态 global、描述符和 nominal 类型位置，初始化后按声明表分片建立一次 Registry。

State 字段复用现有数据类型合同，允许 any、array 和 table，其实际内容在图捕获边界检查。静态可确定的可执行值和弱引用报声明错误。显式字段默认值必须属于纯数据配方；效果性初始化写在普通 init。无默认值的必需字段可以声明，发布基线会指出新版本增加此类字段产生的合同冲突。

恢复入口使用普通默认参数，例如 `fn start_story(state: GameState = model(GameState()))`。`game.start(start_story)` 零参启动新游戏并求值默认表达式；读档按 RootKey 调用当前同一个入口并传入已恢复模型，跳过默认表达式。入口负责配置、系统偏好、Reading/Scope、当前视图和并发操作的建立；业务从 `run_flow(entry, state)` 进入已声明的普通 flow。作品的标题或桌面仍由普通 main 启动，剧情恢复直接进入已声明的故事入口。剧情保存要求 Root/State 合同，独立 UI 和无存档玩法仍可使用普通入口。

`run_flow` 是唯一的原生业务执行边界。新游戏通过普通 CallScript 调用 entry；读档在同一个当前 ticket.task 中建立已验证的业务帧，首帧返回当前 NativeFrame，后续帧使用普通寄存器返回。恢复继承当前 owner、context 和 effects；正常返回、故障与取消沿现有原生回调终态处理。捕获只记录此边界以上的业务 continuation，当前 main、视图闭包和外层原生上下文由当前代码建立。

需要当前界面服务的正文使用 `run_flow(entry, state, context: scene)`，entry 普通接收 `(state, scene)`，嵌套 flow 继续显式传递 scene。context 是当前 Root 建立的对象。它及其直接别名在活绑定中记录当前上下文标记，读档连接当前 Root 的同一对象。多个服务通过显式 table 命名，例如 `context: {scene: scene, poem: poem, page: poem.page, selection: completion}`。捕获按冻结时 table 的字符串 key 索引直接对象成员。对应活绑定及别名记录成员 key，同一对象使用 table 顺序中的第一个 key。读档从当前 Root 同 key 取得对象，缺失或非对象成员报告具体 key。成员索引和匹配按预算推进，只发生于存读档。成员内部的界面与回调由当前 Root 定义，Root 按 State 重建操作及其终态。正文中未显式列入 context 的独立成员值遵循普通持久数据或原生资源合同。未提供 context 时 entry 只接收 State。

唯一检查点的共享类型图包含独立 RootState 根、操作状态和业务绑定。操作描述保留协议与实例身份、图内 State 引用、逻辑 owner/parent、阶段与已结算结果；最末 point 连接其既存操作实例。当前 Reading、历史与 Speech 状态恢复后接回新 WaitId，保留已有历史条目。可恢复正文的内容身份使用稳定流程、point 与逻辑调用路径。持续更新在一次回调完成后的提交边界捕获，当前操作定义重新登记视图与更新函数。

Reading 的纯显示页、显现进度和历史作为同一记录中的逻辑描述保存。恢复候选在当前 Root 启动前为已保存的交互代次保留空间，当前代码建立 Reading/Scope 和可观察视图；到达已验证的 point 后，连接保存的交互与新 ticket，继续显现或等待输入。当前 scope 的暂停和自动阅读条件保持当前定义；恢复不再次提交台词或追加历史。

### 普通场景与资源图

内置资源使用同一类型图的对象身份与字段边。资源 header 标识当前协议种类，Node/Activity/Clock 的状态通过字段连接进入共同对象表；资源 key 不另编码一棵状态树。恢复分为当前身份壳分配、图内字段连接、绑定和 owner 连接、采用后继续计时。需要 Vm 的原生壳由引擎准入阶段按预算建立并强根化，图恢复复用这些当前值。

普通 Node 从作者宿主属性重建，不保存投影后的临时 scope override、焦点或几何。children 逐边连接，parent 不反向带入旧 UI。直接 bind 保留源对象和稳定字段/公开属性身份以及可写性；PropertyRef 在当前字段地址就绪后连接，并保持图内别名。derive 与回调由当前视图定义重建，持久 Node 上无法重建的可执行字段报告具体属性路径。

Tween 保存原始起点、终点、duration、easing 与 elapsed，恢复取得当前字段的 claim 和版本，跳过重新 Activate。Clock 保留 tick 数和余相位。候选准备期间冻结计时，采用时统一校准；字段、子边、活动叶、字符串块和待连接记录沿同一内存与工作预算推进。

## 项目、翻译与编辑器

Reel 的项目根模块 `game` 对应 `src/mod.aside`。编译诊断使用实际加载的相对文件名，编辑器按同一映射提供定义跳转和未保存源码的分析。

`reel check` 检查实际导入图，`dev` 编译并运行，`build` 生成 ASB，`export` 组织完整作品。检查与源码运行复用已验证的编译结果，构建时按所选配置编码产物。源码位于 `src/`，资源位于 `resources/`，编译产物与转换缓存位于 `build/`，完整导出默认位于 `dist/目标/配置/`。`reel clean --resources` 删除 `build/resources/`，`reel clean` 删除整个 `build/`。CLI 与播放器共用宿主接口注册和类型信息。构建与导出在翻译、效果和资源卷名称确定后一次写入 ASB，直接使用本次编译得到的已验证程序。

资源路径相对公共 `resources/`。`resources/@目标/` 按相同相对路径覆盖公共资源，目标内独有的资源也参与选择；其他目标目录从结果中排除。开发读取与导出使用同一选择规则，发行包保存选定资源的普通逻辑路径。资源目标默认使用宿主平台名，工具允许显式选择资源目标以在当前播放器中预览另一平台的素材。人工维护的覆盖文件保留在源码工程，自动转换产物位于 `build/`。

桌面发行目标准备直接复制的 MP4 时，复用播放器的容器、AVC 和音轨检查。自定义资源变体沿用桌面发行目标的媒体和着色器准备，`vita` 使用 Vita 目标。无声 MP4 与单声道或立体声 AAC-LC 采用同一播放契约。导出诊断报告逻辑资源路径、出错的媒体配置和 `convert = "video"` 转换规则。

发行归档将带标准 `ftyp` 文件头的 MP4 直接写入连续条目，保留原字节与内容身份。播放器可按媒体请求直接读取文件范围。其他资源沿用普通归档压缩。

可选的项目根 `resources.toml` 通过 `[[targets.目标]]` 定义有序转换规则。`match` 匹配逻辑路径，首个匹配规则的 `convert` 选择 `texture`、`atlas`、`tiles`、`webp`、`qoi`、`opus`、`video`、`font` 或 `copy`；未匹配文件保持原内容。先选择平台覆盖，再转换选定来源。纹理缩放改变纹素密度并保留逻辑尺寸、裁剪与输入坐标。分块转换保留原逻辑路径，以内容头识别清单；`first_level` 指定首个存储层级，视口需求限制在已存储层级内。视频转换通过 PATH 中的 FFmpeg 和 FFprobe 生成 H.264/AAC MP4，保持帧率与音画时长，按 `size` 等比缩放；`alpha_layout = "top_bottom"` 保留上下排列的颜色与透明度区域。转换每次处理一个文件或显式图集组，视频子进程限制线程并检查工作内存估算，实际子进程内存由编解码器分配。

`reel prepare-resources` 显式准备，`dev`、`run` 与 `export` 在使用作者工程时准备所选目标。缓存由源内容、转换参数、对应转换实现与依赖版本共同确定，视频和字体还包含外部工具身份。准备与导出命令原子发布完整资源索引。开发播放直接用内存中的映射，并与导出共享已转换的资源。源码资源保持原位置。

字体默认保留原有字符覆盖。`convert = "font"` 显式选择裁剪，`unicode` 指定玩家输入等用途所需的字符区间，`text` 选择包含剧情及翻译的 UTF-8 文件；二者并集决定保留字符。转换通过 FontTools 保留字体族、样式、布局特性及集合中的全部字体。字体缓存同时依赖字符集合和工具身份，裁剪工作内存采用子进程估算。

`dev` 在 `build/dev/` 缓存带源码映射的编译结果与内嵌翻译。工具和源码内容共同确定缓存身份，源码文件的增删和修改均参与检查；资源继续从当前项目读取。

原文与译文写在同一个 `tr` 调用中，编译器生成内部消息身份和语言目录。原文插值按顺序各求值一次，译文引用这些值。语言切换准备精确语言及基础语言后更新可观察状态；失败保留原语言。

Debug 包保留源码与指令映射，源码按文件压缩编码，映射在磁盘与运行时共用带稀疏索引的紧凑差分数据；定位查询只解码所在短块。加载按展开后的源码字节数与实际映射容量准入，诊断继续提供文件与准确字节范围。Release 剥离调试数据。发布时正文放入文本包，资源归档按完整条目分卷；ASB 内嵌分发清单。格式见 [ASB](../crates/reel-package/FORMAT.md) 和 [字节码](../crates/aside-vm/src/bytecode/FORMAT.md)。

LSP 使用同一编译器和宿主元数据提供诊断、类型、补全、悬停及导航。Rust 声明旁的英文文档生成可跳转 Aside 声明。源码范围使用 UTF-8 字节；协议按协商编码转换位置。未保存的编辑内容参与项目分析。

具名参数的字面值补全复用宿主校验的选项表。补全按已解析的构造器身份选择参数。

已知类型和签名支持静态诊断，动态字段沿运行时语义处理。编辑分析按模块和依赖缓存，文档变化使相关结果失效。格式化器由 CLI 与编辑器共用。

## 验证与维护

行为检查按语言、会话、UI、渲染、媒体和工具职责组织。输入、等待、取消、恢复、所有权和资源释放通过实际执行路径验证。CPU 布局检查、离线媒体和原生设备检查分别记录运行环境。

性能测量选择当前热点，记录实际工作量、分配、驻留和帧时间。缓存稳定性和退休后的释放是持续交互的重要边界。源码、测试及必要输入进入版本库；构建、日志与测量输出位于忽略的 `target/reel-artifacts/`。

性能采集由正式播放器的可选 `performance` 构建能力提供，运行时通过开发请求开启。`reel-dev perf` 负责从当前工具构建、重新导出作品、部署、启动、收集到分析的流程；测试游戏只提供普通作品负载。未开启采集的会话沿普通运行路径执行，采集缓冲和输出由会话持有并在关闭时结算。底层颜色、像素和设备契约由独立硬件校验程序维护。

资源读取报告中的 `read_open` 包含资源定位和已打开文件的查找。散装文件首次打开时，`file_open` 与 `file_metadata` 分别计量系统打开文件和查询文件信息的调用。两项均计入 `read_open`。

发布验收通过 `reel-dev perf verify` 检查同一次目标导出和普通运行记录。作者策略声明目标、运行环境及需要验收的唯一场景标签，可设置有效提交间隔样本数、P95、最大间隔和 VM、GPU 峰值额度。按场景核对完整提交间隔，除入场首帧外须有可对应的样本。结果保留导出和播放器诊断、观测值、超额项与已有阶段归因。帧率验收使用提交间隔，显示刷新和 GPU 完成继续按各自测量能力报告。

`perf run --policy` 在同一次运行结束时生成验收报告。播放器或设备启动失败时，报告保留该次运行错误。

桌面使用 `REEL_DIAGNOSTIC_TRACE` 开启实时脚本进度日志。普通帧时间采集通过报告保存运行指标。

`reel-dev debug` 通过源码开发入口启动普通桌面窗口，作者手动复现问题。诊断会话默认使用本次记录的独立存档目录，可指定已有存档目录。退出后复查窗口日志、源码定位和已采集的帧，脚本故障也保留退出前的采样。工具复用桌面播放器的性能采集和开发缓存。

开发请求使用版本 1 JSON：`version`、`package`、`saves`、`output` 指定协议版本、ASB、测试存档和报告目录；`vm_timing` 默认关闭，`source_atlas` 默认沿引擎策略，`frame` 可选。Vita 正式入口消费 `ux0:/data/reel/performance.json`，桌面正式运行路径读取 `REEL_PERFORMANCE_CONFIG` 指向的请求。输出包含普通会话的 `frames.tsv` 和记录运行、完成或错误的 `status.json`；支持固定帧的后端另写 `frozen.tsv`，不支持的模式在执行边界报错。`reel-dev perf report` 生成详细报告和 `summary.json`；摘要保留呈现间隔、固定帧批处理、串行归因的不同口径及采样缺口。请求与产物保留在本次运行目录。

报告中的版本 2 `loop` 时间线从首个宿主回调开始连续记录，包含脚本、派生计算、活动、图片与 GC 的回调结束状态。相邻且状态相同的维护回调合并计量，每次投影发布和呈现各自保留边界。区间同时记录回调墙钟与回调外经过时间，后者包含宿主睡眠、调度及异步工作期间的间隔。固定容量按段保留标题并统计淘汰的回调数，冷页面构造沿同一时间线观察。

固定帧通过标题和已接受帧序号选取，保留不可变帧及资源租约。普通批处理和显式逐通道串行诊断分别记录模式与缓存策略；诊断结束后关闭会话。可选 `frame.save_frame` 在测量后将逻辑/物理尺寸和现有 `SavedRetainedScene` 流式写入 `frame.postcard`，供同版本开发工具离线分析，资源像素共享原不可变 backing。帧、准备尝试、通道、目标请求和提交使用关联身份，记录实际尺寸、有效区域、缓存来源及失败状态。事件缓冲有固定容量，测量结束后输出保留量和丢失量。阶段墙钟、有效线程运行时钟、显式等待、GPU 完成首次观测分别报告；完成观测包含排队和轮询延迟。VM 工作计数与阶段耗时在同一呈现边界取差，缺失能力和不完整区间进入报告。

命令入口见 [reel-dev](../crates/reel-dev/README.md)。协作规则见 [AGENTS.md](../AGENTS.md)。平台移植复用公共会话、舞台和资源合同，设备支持以对应适配器的实际运行结果为准。
