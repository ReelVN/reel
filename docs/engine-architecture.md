# Reel 引擎架构

本文定义模块职责和跨模块行为。语言语义见 [Aside 规范](aside-language.md)，创作流程见[作者指南](guide/zh-CN.md)，接口参数与默认值由声明旁的英文文档提供。

## 创作模型

Reel 让创作者用代码表达画面、对白、UI、演出和嵌入的 2D 游戏。函数组织流程，节点组成画面，活动表达随时间发生的变化。页面、剧情与玩法使用同一套状态、输入和生命周期。

项目入口固定为 `src/main.aside` 的 `main`。入口配置作品、建立共享状态并开始流程；模块按章节、菜单、人物演出或小游戏组织。简单视图返回节点，等待交互的函数返回结果，需要持续操作的组件返回具有明确方法的对象。共享状态由调用方传入，局部状态由组件持有。

普通函数可以等待对白、活动和交互结果。`spawn` 创建并行任务，`sequence` / `parallel` 组合动作，`.then` / `.together` 提供对应的方法写法。`scope` 拥有临时节点与工作，`reading` 为局部剧情组合对白、选择、历史与阅读状态。

作者接口沿同一舞台模型表达位置、布局、图片、文字、样式、输入和特效。性能优化由引擎复用已准备的数据和资源，稳定画面沿失效信息跳过重复工作。

## 模块职责

| --- | --- |
| `aside-syntax` | 不可变语法树、源码范围与节点共享所有权 |
| `aside-compiler` | 词法、语法、语义分析、源码类型、格式化和字节码生成 |
| `aside-vm` | 动态值、集合与文本方法、执行栈、GC、宿主调用、等待、错误和快照 |
| `aside-host`、`aside-host-macros` | Rust 函数、属性、类型、文档及 ABI 元数据 |
| `aside-std` | 数学、曲线、随机数、时间和故障查询 |
| `aside-lsp` | 编辑文档、项目分析、诊断、补全、悬停和导航 |
| `reel-core` | 身份、拥有字节、预算、资源 IO、后台工作与时钟合同 |
| `reel-engine` | 会话、作者接口、对白、活动、作用域、存档请求和脚本适配 |
| `reel-ui` | 舞台树、布局、控件、输入、绘制记录和已呈现几何 |
| `reel-text` | Unicode 分析、整形、换行、文字布局与编辑 |
| `reel-render` | 帧编译结果的资源准备、GPU 合成、呈现与完成回收 |
| `reel-player` | 运行包加载、会话与 UI 的组装、资源加载、窗口、平台输入和主循环 |
| `reel-audio` | 混音、声音、轨道、效果及音频控制队列 |
| `reel-media` | 设备输出、音视频解码、流式供给和后台释放 |
| `reel-storage` | 文件存储的原子发布 |
| `reel-package` | ASB、文本包和资源归档 |
| `reel-cli` | 项目检查、运行、构建、导出与 Reel 语言服务入口 |
| `reel-dev` | 仓库检查与专项测量命令 |

Aside 依赖语言与 Rust 基础库。窗口和 GPU 类型留在平台适配器；UI 向后端提供拥有数据与资源租约的可移植帧。`reel-engine` 当前直接依赖 `aside-compiler`，源码和 ASB 通过同一宿主注册与执行准入。

共用播放器通过 HAL 合同访问宿主、渲染、媒体、存储和输入。`reel-player::hal` 定义宿主生命周期与显示控制，渲染、解码和存储合同由对应 crate 维护。播放器负责会话推进、资源就绪、呈现接受、输入分派与挂起；平台组装负责创建设备和事件循环。

发行包由 `reel-player::distribution` 读取 ASB、文本池、语言索引和资源根，再交给共用会话执行。CLI 负责定位作者工程及编译、导出；平台入口直接加载发行包。

Vita 应用的固定启动素材位于所属 crate 的 `runtime/vita/`，由 `cargo-vita` 直接打包。启动器字体包及许可随素材维护；探针的私有作品包由外部工程导出后放入忽略的内容目录。编译与 VPK 输出遵循 Cargo 的目标目录配置，清理编译缓存保留固定打包输入。

发行导出默认附带当前工具包的播放器；`reel export --release --runtime 目录` 改用指定平台的运行时目录，保留其文件结构并在根目录写入作品包。资源目标独立选择；运行时文件与作品包重名时报错。平台安装格式由对应打包工具生成。

`reel::build` 的只读字符串 `target` 记录构建目标，由 `--resource-target` 同时选择源码常量与资源覆盖目录，默认使用宿主系统名称。编译缓存包含这个目标。作者用普通 `if build.target == "vita"` 选择效果配置；编译器消除未选分支的执行代码。`window.info().platform` 继续报告当前播放器的平台。资源收集沿目录覆盖和打包规则执行。

`reel export --release --data-only` 导出代码、文本和资源，供已安装的共享运行时加载。Vita 启动器扫描 `ux0:/data/reel/` 下含 `game.asb` 的一级作品目录，使用共用舞台和输入呈现列表；每部作品在自己的 `saves/` 中保存进度。切换作品前完成当前会话、媒体和 GPU 提交的清理，游戏退出或执行错误返回启动器。

Vita 启动器进程持有一个原生事件循环和渲染设备，各播放器会话借用该设备。切换时先关闭并释放旧播放器及其媒体、字体、资产与捕获，再等待 GPU 完成并清空会话缓存；设备和已编译着色器保留到应用退出。应用退出显式关闭原生设备，清理失败报告原始原因并终止后续挂载。

启动器复用列表和设置页面，目录扫描与设置写入交给后台工作线程。主题、语言和上次选择保存在 `ux0:/data/reel/launcher.tsv`。加载提示完成呈现后，宿主开始读取作品包。

平台实现按渲染、媒体与宿主职责放在现有 crate 的模块内，`cfg` 在模块入口和目标依赖处选择实现。公共接口传递能力、资源描述与拥有数据，原生句柄由适配模块管理。各后端复用通用资源格式，生产实现保持 `forbid(unsafe_code)`。

Vita 宿主直接加载发行包，以固定物理屏幕映射作者画布，并将控制器、触摸和系统挂起事件交给共用播放器。原生调用通过固定 Git 提交的 `vita-native` 库使用，SDK 句柄与原生完成回收由该库封装，着色器接口和顶点布局由 Reel 适配层提供。WGPU 与 GXM 复用绘制规划、资源需求与缓存策略，设备适配负责程序、纹理存储、坐标约定、提交与完成回收；纹理准备按容器记录的块序上传。音频沿通用 Opus 解码与混音进入 AudioOut，视频通过 AvPlayer 工厂输出拥有数据的画面与 PCM。设备内存额度由平台组装提供，缓冲、队列和 GPU 驻留分别计量。

GXM 将上传的源图片与软件视频平面放入无 CPU 缓存的 MAIN 内存，字形图集、渲染目标与扫描输出放入 CDRAM。源图片保留一份物理存储，离屏效果继续采样 CDRAM 中的中间结果。资源总额度跨物理域共同计量，原生池分别记录实际保留容量；CDRAM 准入为参数缓冲和扫描输出预留空间。

着色器构建按后端生成程序：桌面 WGPU 使用 WGSL，GXM 使用 SDK 的 `psp2cgc` 离线生成 GXP。内置程序嵌入播放器，作者效果沿同一类型化表达式生成目标程序和参数绑定。设备复用已创建的程序及混合配置，离屏目标按实际覆盖区域分配。

GXM 的场景提交、片元完成通知与显示队列分别管理绘制、资源退休和扫描输出。提交保留所引用的缓冲、纹理与目标，宿主完成轮询逐项检查场景与传输通知并回收已完成租约；三个扫描输出缓冲各自持有显示同步对象，等显示队列释放后复用。离屏表面保留各自的像素存储，通过场景顺序和片元/传输同步标志建立依赖。兼容尺寸的表面共享调度目标，场景有效区域限定实际绘制范围。显示回调完成屏幕提交与扫描同步后唤醒宿主，完成状态先于唤醒发布；脚本、UI 和资源管理由宿主线程推进。唤醒对象由设备持有到显示队列排空。内核分配块、GPU 映射、上下文环形缓冲和渲染目标调度存储按各自实际容量记录。

桌面通过 WGPU 场景宿主检查完整脚本流程、提交成本与内存占用。GXM 通过 Vita 目标构建、模拟器和设备验证，设备帧时间由目标硬件测量。

借用实现作为工作区 crate 维护，来源、许可证和必要版权信息随对应 crate 保存：UI 来自 Masonry，文字来自 Parley，混音来自 Kira，语法树来自 Rowan。Reel 按当前模块职责维护这些代码。通用算法优先复用锁定的 Rust 依赖，包括 Taffy、HarfRust、ICU、Symphonia、Lyon 和 WGPU。

## 执行、等待与调度

编译器和 VM 共用字节码模型。模块初始化完成后进入普通 `main`；宿主验证代码身份、native 签名、ABI、能力和实际支持的指令。错误保留作者源码位置。

编译器将可变指令缓冲转换为紧凑代码，并按模块释放分析数据。字节码文件、运行时和快照共同使用代码字偏移定位，跳转、异常范围与源码映射使用同一坐标。

指令按 32 KiB 分块压缩，已验证程序共享冷代码与有界热页缓存。VM 在当前页内直接取指，换页时解压；页面的全部持有者释放后归还驻留额度。加载按块验证，快照保存代码身份与执行位置。

VM 按指令、内部工作、分配和时钟额度推进。指令、工作和分配额度逐步检查；软时限在进入或恢复执行、宿主调用返回以及有界执行批次后检查。`BudgetYield` 保留执行位置和中间状态；宿主调用返回值、故障、继续执行状态或等待票据。长操作分片处理，成功后提交其约定的结果。用户回调已经发生的副作用按执行状态保留。

GC 的弱引用阶段遍历独立的弱引用队列，标记结束时固定本轮范围。队列容量在构造弱引用前计入堆预算；回收只读写已分配的存储。新弱引用留到下一轮，已清空或不可达的弱引用退出队列，存活判定继续使用同一标记截止点。

生成器按需在调用方任务内执行，`yield` 将暂停帧的局部值与故障上下文交给生成器对象持有。推进、关闭与快照复用同一执行器和 GC；不可达生成器释放其状态，显式关闭执行已进入的清理代码。

显式 `await` 是调度边界，已经完成的对象也会让其他任务获得运行机会。宿主等待通过稳定身份结算，完成消息匹配会话、所有者与代际后至多交付一次。共享活动的等待者各自持有订阅；取消一个等待者释放其订阅，活动按自身所有权继续运行。

主循环在有输入、活动、资源完成、GC 或退休工作时推进。时钟活动设置下次唤醒时间，稳定画面复用已接受帧。睡眠前先确认唤醒信号，再处理其来源并检查剩余工作。 Vita 主线程的重绘请求记录为本地状态，本轮消费后沿活动期限睡眠；渲染期间新增的重绘在睡眠前进入下一轮。IO、媒体、显示完成与电源事件继续通过保留的跨线程通知唤醒宿主。任务的局部最小预算不足时，根据实际报告安排下一片；宿主保留整个循环的工作边界。

媒体、本地化和资源读取的外部完成在每轮宿主推进入口处理。该轮内部的 VM 切片和 native 重入继续执行本地调度；新的外部完成通过唤醒信号交给下一轮入口。直接使用 `SessionVm` 的宿主调用对应的 `maintain_*` 方法处理这些完成。

一次时钟更新及其派生计算可以跨越多个宿主时间片。脚本到达提交边界且派生批次完成后返回宿主，使完整画面获得发布机会；已请求的重绘先记录这份稳定投影，下一轮再继续就绪脚本。计时采样由活动截止和实际输入、资源完成驱动，维护时间片沿用当前时间批次。脚本等待时，活动继续按时钟推进。

播放器遇到 VM 硬容量阻塞时，完成一次垃圾回收后重试。仍无法继续时，报告源码位置与资源需求并结束本次运行。

会话时间使用单调时钟，宿主挂起期间冻结。舞台动画、阅读计时、音频内容位置和现实时间分别由对应时钟驱动。`std::time` 读取现实时间；持续玩法通过命名动作和时钟更新普通舞台节点。

## 所有权、取消与资源预算

会话、任务、节点、作用域和外部请求都具有明确身份。复制 VM 的 `Value` 只复制句柄；宿主持有跨执行片使用的值时，须登记相应 GC 根。寄存器、native 参数、继续执行状态、等待结果和故障引用进入同一根与快照系统。

根范围用代际身份和占用位图共同索引。增量 GC 每个扫描单位读取一个描述符、一个值或一个 64 槽占用字；空槽按块跳过，范围替换后从新代际的首个值继续。位图随描述符容量预分配并计入堆预算，回收切片只读取既有存储。

所有者撤销先关闭新请求和业务等待，再取消任务、清理 VM 根并退休外部资源。物理释放完成后归还对应预算；所有记录义务结束后才允许复用所有者槽位。GC 负责不可达脚本对象，外部设备生命周期由所有者协调。

容器与缓冲按实际容量计量。增长前预留新旧存储重叠的额度，拥有数据随预算票据转移，最终物理释放归还额度。共享别名保持同一份存储与票据。分配和释放的不可分割成本单独测量。

共用物理内存的资源域可以加入同一预算组。预留和调整同时满足域内额度与组总额度，失败保留原计账；最终释放同时归还两者。同组拥有缓冲可原子转移到另一资源域，校验目标额度时共享组的原票保持一次计量；失败保留原票与数据。组峰值记录各域实际同时持有的字节。

可重载图片与纹理的资源身份、版本、尺寸、格式、来源和覆盖率描述独立于 CPU 载荷。上传、存档及其他 CPU 读取者持有载荷读取租约；后端成功拥有相同版本后，在无读取者时可回收可重载载荷并归还原预算。动态生成或没有可靠重载来源的数据继续持有载荷。普通舞台图片以资源身份绘制，不因记录帧而额外保持像素 Blob。

后端重建或缓存缺失需要已回收载荷时，播放器沿现有 Assets 请求异步按精确版本重载；同一资源的请求合并，版本和描述核验后安装到原身份。加载未完成时保留已接受画面；失败或取消保持现有资源和呈现，向原来源报告。快照对可重载资源保留来源，其他资源持有独立载荷租约。资源 source 冲突判断保持原注册身份，驱逐和重载不会改变 handle。

后端在候选帧缺少 CPU 像素时报告该候选、设备代次及精确资源租约的有界需求，容量计入既有准备预算；同一需求按资源身份和版本去重。Player 将需求交给现有 Assets 异步请求，保持候选 `Preparing` 和最后接受画面；完成后核验同一候选与设备代次，恢复原资源，再通知呈现协调器继续该候选。取消、会话切换、表面变更或设备重建取消对应需求，已提交 GPU 工作按原完成信号退休。GPU 后端只声明实际缓存缺失，读取、解码、请求合并、取消与错误由 Assets 管理；资源本身只保存描述和驻留或缺失的像素，不维护第二套加载状态。

后台 IO、解码和完成队列使用明确容量。请求接受前预留结果位置；拒绝时返回原请求及其所有权。消费者暂时占满队列时保留待处理工作，由释放或完成通知唤醒。过期结果沿原所有权路径释放。

Vita 使用统一 C/newlib/Rust 进程堆，CRT 从一个 1 MiB 缓存 MAIN arena 开始，按需创建独立系统 mspace 和内核块。额外 arena 全空后归还整块，释放失败保留 UID 与费用；首块供小分配复用。CPU arena、GXM ring、USSE、MAIN 纹理与缓冲及固件调度块共用实际 MAIN 提交账本，按含头部的完整页对齐容量计量一次，物理释放成功后归还。宿主启动图形及会话/媒体工作线程前，以内核剩余 MAIN 加已纳管提交量确定容量；SFO 扩展额度、已加载程序、线程栈和 SceLibc 堆分别核对，后续未纳管 SDK 分配仍可能导致内核分配失败。VM 和资源域保留各自准入，不将多个 VM 对共享验证代码的本地额度重复加入物理账。连续物理 MAIN 使用内核单独报告的剩余额度；视频块同时保留媒体本地额度与连续区物理票据，NV12 导入仅共享原块。普通区和连续区的剩余值分开记录，不假设它们互不重叠。

预算分别覆盖 VM 堆、CPU 源与输出、解码工作区、GPU 驻留和临时目标。桌面 WGPU 宿主默认提供 512 MiB 的 GPU 资源额度，显式传入的预算保持原值。各账本记录其实际拥有的存储；进程 RSS、驱动和第三方解码器的内部工作区需要独立测量。详情见 [reel-core](../crates/reel-core/src/lib.rs) 与 [VM](../crates/aside-vm/src/lib.rs)。

来源复用使用弱租约与预算内的身份索引；索引命中后核验完整路径、版本和种类，退休资源不得新增租约。索引容量和增长重叠计入 Metadata，额度不足时退回来源表扫描；关闭服务释放索引。

归档索引使用紧凑记录和共享 UTF-8 路径区，条目借用索引存储。`Metadata` 账本按索引、挂载表和解析工作区的实际容量准入；`AssetOptions.metadata_bytes` 默认上限为 32 MiB。解析工作区在挂载后释放，索引与挂载表随 IO 工作线程释放，解码工作区使用独立账本。

## 舞台、布局与文字

每个舞台节点有一个逻辑父节点。构造返回未挂载节点，`add` 与 `stage.replace` 提交挂载，`remove` 退休节点，`move` 在同一父节点内调整顺序。节点身份承载回调、焦点、活动与资源引用。

舞台投影记录节点属性、共享效果和作用域覆盖层的弱依赖。VM 为已观察对象保留有界写入记录，宿主按受影响节点同步；拓扑或依赖变化时重建索引，记录溢出及快照恢复时完整同步。记录和索引计入堆预算，观察关系随对象退休失效。

固定画面使用 `stack` 和位置属性；行、列与网格使用 Taffy Flex/Grid。布局读取直属子节点和已有文字测量，尺寸或属性改变后沿失效路径更新。父级变换和裁剪同时作用于绘制与输入。

逻辑画布按 contain 映射到窗口，留边和缩放使用统一变换。画布尺寸定义作者坐标；离屏目标由实际绘制效果和物理输出需求分配。`camera` 把世界区域映射到视口，HUD 可放在相机外。

`list` 按 key 复用行组件；记录替换更新数据连接，稳定 key 保留组件身份。虚拟列表根据视口、行高和缓冲范围构建行，来源数据仍由调用方持有。`VirtualListNode.scroll_to` 等待目标行的位置与呈现；取消、过滤、尺寸改变和退休沿列表活动处理。

`bind` 连接可观察属性，`derive` 连接派生值。派生计算读取上游时先完成其待重算，以同一状态评价依赖和结果。写回、循环检测与取消使用共同属性协议。临时 `override` 与 `offset` 在作用域结束时撤销自身图层，保留底层业务值和动画。

`appearance` 将通用绘制属性按交互状态组织成不可变共享值。投影按 base、hover、focus_visible、pressed、disabled 选择外观，作用域 override 保持最高优先级。状态选择复用节点、绑定和输入身份；快照恢复清除瞬时交互状态后重新投影。属性范围与示例见[接口声明](../crates/reel-engine/src/aside/stage/interaction_appearance.rs)。

文字由 `reel-text` 整形、换行与编辑。字体文件由作品提供；字体族、字重与回退参与同一次匹配。布局保留字形位置、字簇与源文字范围，绘制直接消费布局结果。逐字显现改变可见范围，颜色改变复用几何；文字或影响布局的样式变化触发重排。

富文本保存正文、样式、ruby、链接和句内时序。普通字符串按原文显示。竖排通过文字的逻辑书写轴布局，字形方向、注音、光标端点与命中位置使用相同几何。`stage.geometry` 返回完整文本末尾插入光标的边界 `text_caret`，用于按实际行高定位继续标记等局部控件。

文本编辑控件以同一事务处理键盘、输入法、选择、撤销和过滤；预编辑与已提交文本分别保存。单选组按共享属性身份组织导航，虚拟行通过所属列表解析目标。

属性和控件接口见 [Stage](../crates/reel-ui/src/stage)、[作者节点](../crates/reel-engine/src/aside/stage.rs) 与[文字](../crates/reel-text/src/lib.rs)。

## 输入与已呈现画面

布局和绘制产生候选画面及对应几何。后端接受该候选后，输入使用它的冻结几何；准备、提交或呈现失败时继续使用上一份已接受视图。一次输入固定使用同一几何快照，并核验节点当前存活、可见、启用和模态资格。几何与输入配置稳定时，候选共享不可变几何存储，各自保留接受身份；存储额度保持到最后一个引用释放。

后端返回 `Preparing` 时，协调器保留该候选，收到资源完成后继续准备同一帧。期间脚本和输入继续推进，后续变化在该帧被接受后生成下一候选。普通资源压力重试最新状态；切换会话、显示表面或挂起会取消未完成候选，已提交资源继续随 GPU 完成信号退休。

`input.on_pointer` 接收命中区域内的移动，以及主按钮或触摸开始的拖动。坐标相对输入节点；`event.dragging` 表示该节点的主按钮或触摸拖动仍在进行。悬停保持当前焦点，拖动捕获持续到释放或取消。

指针捕获属于当前手势和节点；隐藏、禁用、退休、失焦或模态范围改变会结束失效手势。键盘与手柄通过命名动作汇合，控件消费自身确认、方向和编辑输入，其余事件沿祖先传播。一次输入至多推进一次剧情。

`stage.focus(target, owner, visibility)` 返回可等待的 `FocusOperation`，结果为 bool；owner 默认当前作用域。请求等待包含调用时舞台变更的已接受帧，在当前输入与模态作用域内向可见、启用、可聚焦目标申请。成功返回 true；目标隐藏、退休或被模态遮挡返回 false 并保留原焦点；owner 退休取消未完成请求。`visibility` 默认为 `"show"`，交接时显示焦点提示；`"preserve"` 保留应用交接时的提示状态，随后方向或确认输入显示导航提示。焦点沿现有导航树与节点身份保存。

`stage.focus(null, owner)` 在画面接受后清除焦点、提示及尚未释放的确认输入。owner 的节点锚点须处于当前输入作用域；未绑定节点的请求使用当前舞台根。清除后，方向键、Tab、指针或显式交接重新选择控件，确认键沿页面输入处理。

按钮的 `focusable` 默认为 true。设为 false 后，方向导航、Tab 和显式焦点交接跳过该按钮；指针悬停、按压与点击沿用按钮交互。配合 `focus_on_pointer: false` 可在指针操作时保留其他节点的焦点。

`stage.input()` 返回只读可观察的最后输入方式与手柄按键布局。有效按键、指针移动和越过死区的手柄输入更新来源；连接、释放和导航重复保持当前来源。平台按设备标识提供可识别布局，未知设备使用通用布局，图标由作品选择。恢复存档后由当前宿主输入状态更新提示。

弹出层和系统菜单参与同一层序、焦点与模态路由。窗口外点击、触摸滚动和指针取消按事件终态处理。几何查询和捕获引用已呈现帧，保证显示位置与交互位置一致。

公共呈现协调器管理候选身份、SurfaceEpoch、接受记录、重试与曝光重绘。表面尺寸变化和恢复使用新的 epoch；设备重建还更新设备 generation。临时资源压力等待完成通知，永久拒绝等待状态或尺寸改变。

## 绘制、转场与 GPU

同一图片的连续精灵以共享资源、采样与外部变换加有序实例记录。实例保留位置、尺寸、旋转和透明度；帧编译计入拥有存储，两后端使用共用几何展开并保持原绘制位置、裁剪和组混合。

UI 记录有序 `VisualLayerPlan`，每段保留绘制者、变换、组、裁剪和资源。节点共享不可变绘制记录及其局部元数据，变换由片段携带；变换、子树合成和局部装饰分别使对应阶段失效。重绘建立新记录，已有候选继续持有原内容。`FrameBuild` 按命令、工作和字节额度生成拥有资源租约的不可变 `RenderFrame`。诊断指向实际命令和节点；取消释放尚未发布的候选。

帧构建按即将分配的结构与载荷扩展预算票据，完成后释放构建临时存储的额度。共享帧池计量已接受帧、在途帧与候选帧实际并存的容量；字体和图片通过租约共享各自的资源存储。

图片、路径和字形沿同一坐标与裁剪体系绘制。变换使用前向组合，输入查询在需要时求逆。几何外延包括描边、抗锯齿和效果扩张，未知或溢出外延由后端按实际输出区域裁限。

图片、路径与字形的几何按原绘制顺序写入共用缓冲，索引宽度按顶点范围选择。相邻绘制的纹理、采样、着色器参数和裁剪状态一致时合并索引范围；两个后端共用合批规则，目标切换和合成保留提交边界。

稳定绘制记录在资源依赖连续一致后缓存不可变几何，并持有相应字形租约。两后端按有序几何段复用已完成的缓冲，只更新变化区间；连续变化的记录仅保留依赖信息。缓存容量计入资源额度，帧准入出现压力时释放缓存并恢复完整上传。

离线图集按 `resources.toml` 的显式规则划分共同驻留组；每个原逻辑图片保留自身路径、尺寸与页内内容区域，同一页由一份物理纹理和像素所有者共享。页及视图在离线准备时原子发布；每页只含基础层，各项边缘复制 gutter 并独占压缩块，图像坐标、局部裁剪、重复、九宫格、遮罩和效果采样均限制在该视图。运行时按页的资源身份合并读取、恢复、上传和物理计量；取消一个视图不取消其他视图的请求。快照保持各视图身份并共享页。

图集成员的整图重复以视图为周期，线性过滤在接缝按对应轴首尾 texel 混合，最近邻过滤按视图坐标回绕。显式 `source_rect` 使用原区域重复与边缘填充语义。覆盖整张物理纹理的 identity 视图使用原硬件采样；普通图集完整视图窗口可复用区域固定着色器。

普通图片按整图或区域采样选择固定着色程序，两后端共用分类。区域采样保留片元阶段的半纹素边缘限制，覆盖图集裁切和纹理填充；程序分别保留 RGBA、BC1 和 BC3 的透明度语义。

纯色绘制直接输出线性预乘颜色。已证明输出完全不透明的纯色和普通图片使用覆盖写入；透明度、覆盖率和混合状态参与合批判断。图片注册保存有界的透明覆盖信息，绘制按过滤足迹裁减零输出区域，源纹理坐标沿用原变换。图片需求按来源、可见性与实际布局视口依赖失效，纯绘制更新复用需求与租约；资源完成和视口变化重新准备。

舞台投影共享挂载资源索引，来源、可见性及弹出层资格变化时更新。索引保存图片、遮罩和效果的路径与使用节点；布局和视口查询只选择需要的条目，资源服务增量更新订阅。隐藏节点保留挂载身份，已接受画面继续持有其资源租约。

默认 WGPU 后端使用图片与字形四边形、Lyon 路径网格和按相邻状态合批的提交。首次配置准备设备支持的通用管线；帧所需的遮罩管线在画面接受前准备。字形栅格复用 Swash；图集键包括字体、字号、字形、变体、描边和字形变换。图片、字形与管线缓存属于确定设备代际。

渲染准备收集本帧可见字形，复用已有栅格并在绘制前完成新增字形上传。字形的实际栅格位置、尺寸和变换提供合成外延；隐藏文字在进入可见绘制记录后准备。准备数据、图集区域和资源租约保持到最后一次 GPU 使用完成。

合成采用线性预乘颜色，输出时编码到表面。组先合成子内容，再应用一次组透明度和遮罩。`crossfade` 混合完整的前后画面；`subtract` 对线性预乘 RGB 计算 `max(dst - src, 0)`，保留目标 alpha。

只含一次矩形图片或纯色绘制的普通透明度组，可将透明度并入该次绘制。组内矩形裁剪在当前采样方式下可由 scissor 精确表达时一并折叠；重叠绘制、效果及保留转场或捕获边界保持原合成过程。GXM、WGPU 和目标准入共用这项规划。

纯裁剪覆盖且不携带效果、遮罩效果或延迟效果尾部时，独立目标只保存原覆盖通道；其他裁剪继续使用原颜色格式。WGPU 在格式支持渲染、过滤及所选采样数时，以 R8 UNORM 或 R16 浮点保持原颜色目标的通道精度；GXM 使用 U8 alpha 表面并以同值复制到 RGBA 的纹理视图供 alpha/red 消费。GXM 独立图片遮罩和转场表达式输出同样只保存标量覆盖。颜色与覆盖目标按独立物理类别规划与复用，格式不支持时沿用颜色目标。

`effect(function, params)` 将纯 Aside 函数编译为舞台效果。首个参数 `Fragment` 提供局部坐标、尺寸和子树采样；其余具名参数沿用绑定更新。float 结果作为覆盖率，四元组结果作为线性预乘颜色。效果作用于节点逻辑矩形，先处理子树结果，再应用组透明度、遮罩和混合。已物化的独立效果结果可在来源内容、效果参数和资源身份、采样网格、裁剪及输出格式均一致时复用；缓存持有原目标预算和在途租约，内存压力可以释放已缓存结果。同一效果节点与效果定义的结果新版本替换旧版本，串联效果通过来源家族延续替换；在途旧版本仍持有其原目标直至提交完成。直接合成到父目标的效果保持原有融合路径。WGPU 效果参数缓冲与绑定可按设备对齐容量复用，准备中的实例独占缓冲，提交完成后归还；取消及内存压力释放可回收所有者，缓冲和绑定引用的资源保留原预算与租约。编译产物随源码、ASB 和资源包传递；目标着色器由构建工具生成，运行时复用程序并更新参数。两个后端共用类型、坐标、颜色和资源生命周期，设备程序及其租约保持到在途使用结束。

普通组的颜色效果已声明不读取子树源时，共用准备计划跳过被完全替换的子绘制和原始源目标，图片、字形需求与两后端目标准入、执行共同消费该选择。效果自身的图片参数、数值、逻辑域和物理采样网格继续保留，输出沿用原有物化、量化与组透明度合成路径。标量覆盖率、源采样、裁剪、遮罩、滤镜、特殊组混合或反色继续准备原子树；含保留转场或捕获排除范围的绘图，以及捕获准备，保留完整依赖。消除只作用于绘制消费者，节点交互、更新和生命周期沿用舞台模型。

普通 source-over 命令段由共同计划逆序证明不透明覆盖，完全被后续内容覆盖的绘制同时退出图片需求、字形准备与两后端执行。覆盖集合有固定上限并保留矩形并集中的空洞；轴对齐或直角旋转的不透明矩形提供覆盖，分数边缘只提供保证全部采样点被覆盖的内部。精确矩形 scissor 可以参与证明；其他裁剪、隔离组、遮罩、效果、背景读取及保留或捕获边界截断证明。图片注册时保存完整 alpha 的证据，逐帧规划复用该元数据与既有不透明 RGB 格式契约。原坐标、混合、量化和交互生命周期保持原义；临时元数据额度不足时保留原绘制路径。

源码中可静态确定的纯遮罩构造使用同一效果 IR 和着色器产物。效果定义通过函数或遮罩模板绑定；模板以运算结构、采样方式和常量确定身份，图片路径与节点动态参数由实例提供。构造或修订时解析绑定，逐帧复用；运行时才能确定结构的遮罩沿用动态构图路径。

图像节点的 `sampling` 在 `linear` 与 `nearest` 间选择。过滤方式属于绘制状态，与解码、压缩纹理和驻留缓存的身份分离；两种方式沿用相同的缩放、图集窗口、分块 gutter 和打包透明度坐标。子树效果读取已按该方式绘制的源图，效果、遮罩、字形和内部合成各自保留既定采样方式。

效果函数的 `Texture` 参数接收 `texture(path)` 创建的图片来源。来源沿普通资源加载、平台覆盖和纹理转换路径解析，实例保存数值与图片绑定，编译定义保存静态运算和采样结构。图片采样返回线性预乘颜色；alpha 和灰度采样沿用遮罩通道语义。数值与图片使用各自的类型和绑定布局，资源就绪后发布候选画面。节点的 `mask` 可接受输出为 float 的效果，沿同一编译与资源准备路径生成覆盖率。

float 遮罩效果在完整局部域中一次生成子树颜色与覆盖率的乘积。后续仅需普通 source-over 时，投影直接写入父目标并应用一次组透明度与反色；裁剪、其他遮罩、背景读取和保留内容按各自依赖顺序处理。

普通绘制进入当前目标。独立组、遮罩和转场按实际需要使用离屏目标；目标池按尺寸、格式、采样数、resolve 和在途重叠计量。后端根据能力与预算选择质量档，目标在首次写入或读取前初始化。资源租约和预算保持到 GPU 使用结束。几何与上传缓冲在提交完成后进入复用池；退休图片在源租约及 GPU 读取者全部释放后，可按格式和存储尺寸复用。图片复用池按已接受提交更新闲置年龄，实际复用次数决定有界保留期。闲置容量继续计入资源额度，超出保留期或遇到压力时释放。

完整覆盖物理目标的替换合成可直接写入全部采样点，省去旧内容的初始化。共同规划核对视口、裁剪、存储尺寸和混合方式；GXM 选择不含裁剪丢弃的程序，WGPU 使用 `DontCare` 附件加载。完整物理目标上的独立效果可选择构建时生成的完整目标变体，将局部域外的丢弃改为透明输出；坐标计算保持相同，效果附件仍初始化后写入。局部覆盖、填充区域及未写入即读取的目标保持透明初始化。WGPU 的原生实例允许这项扩展；适配器中的单个 `unsafe` 授权点由完整覆盖证明约束。

几何批次保留有序片段，共享打包路径直接生成顶点和最终宽度的索引。WGPU 写入映射上传区，GXM 使用计入瞬时预算的 CPU 上传区；局部更新保持完整批次的顶点偏移与绘制顺序。

精灵的完整矩形输入可使用共同实例布局：每实例保留 CPU 按原精度计算的四个最终角点和颜色，批内共享 UV、采样窗口与四角索引。顶点程序只选择已有角点，片元、混合及实例顺序沿用普通绘制；相邻兼容实例段合并。分带支持、几何裁剪及特殊合成继续使用展开几何。实例与普通批的切换按实际上传成本和提交次数选择，小批保留合并机会；模板、实例、索引及上传存储计入原几何预算，并持有到最后一次 GPU 使用完成。

实例化首先用于独占普通绘制批的兼容连续精灵段：模板和索引摊销后上传字节至多为展开路径一半时选择实例。普通绘制在同批前后相接，或实例材质、采样模板及裁剪边界变化时，在准备后续几何前恢复原展开批，保留原 draw 与 render pass 合并机会；原批已达到字节或段数上限时仍可开始下一实例批。

几何完全位于裁剪区域内部时，两后端沿用视口裁剪并合并相邻绘制状态。GXM 在硬件 tile 与表面边界可精确裁剪时使用普通片段程序，其余区域使用精确裁剪程序；程序按实际使用创建并持有预算。

嵌套效果使用相同局部域和变换时，沿用已确定的采样网格。单一效果子组与隔离父组使用完全相同的源尺寸和采样坐标时，子组结果直接交给父组继续处理，连续效果交替复用临时目标。组透明度、混合、裁剪及保留转场或捕获边界仍参与规划。

单采样效果的末级透明度与 source-over 可直接写入父目标，源子树仍完整保留。独立 alpha 覆盖可并入末级合成；只包含一个效果组的独立外层裁剪也可使用这一方式，并保留效果输出、透明度写入两处量化。源与覆盖纹理持有到提交完成，源尺寸按轴不超过被替换的目标。反色、背景读取、多采样及保留边界继续使用独立步骤。转换器生成普通与覆盖两个着色器变体，运行时按公共规划选择。

普通 UNORM 合成，以及颜色分量已证明处于 `[0, 1]` 的纯色与普通图片绘制，可使用半精度颜色运算。坐标、任意作者效果与宽范围颜色保留单精度；WGPU 按设备的半精度能力选择程序。

两后端共用离屏布局，分别记录逻辑绘制尺寸、物理存储尺寸、源内容区域及父目标中的覆盖区域。普通组按已知物理外延平移到源目标，合成时在顶点阶段映射源纹理坐标，恢复父像素位置和采样网格；效果采样保留完整局部源域。已知输出外延完全位于裁剪范围外的组，在目标准入前跳过；保留转场和捕获边界继续参与依赖规划。读取背景的混合保留绘制顺序，有限区域的背景副本只复制对应的父像素，公共规划根据物理成本和存活区间选择存储容量。源与背景保持相同的整数像素网格，坐标映射适配各自存储尺寸。未知外延和保留转场按完整依赖范围准备。目标准入与绘制消费同一布局，尺寸复用同时保留有效内容范围和透明边。

共享规划按存活区间安排不同尺寸源的存储复用，采用能降低总分配峰值的组合。绘制保留原视口和采样网格，采样坐标及边缘约束对应有效内容区域；显存计量包含物理存储、格式和多重采样层。帧输出保持输出表面的尺寸。标量效果需要从更大的存储读取局部源时，共用几何沿源纹素边界分片，在顶点阶段完成边缘夹取，片段阶段保留直接采样。

离屏组的结构判定按命令与依赖边界缓存，透明度等数值变化复用结构结果。当前帧重新计算尺寸、采样网格和物理峰值；规划与两后端绘制共享同一判定，缓存存储计入瞬时额度并在压力下释放。

同一普通父作用域内，可有限裁切的普通 source-over 隔离组可穿过普通 source-over 父绘制，先完成至多八个源，再按原命令顺序交错执行源合成和父绘制。每个源包含其完整嵌套子图：内部隔离、裁剪、遮罩和颜色效果沿原依赖顺序完成，内部背景读取只消费该隔离域。共同计划保留各源的平衡命令范围，并从原命令流重放父操作，父绘制的坐标、裁剪和来源保持原样。共享规划按实际尺寸桶中同时存活的子目标、效果输入与延迟源选择有界窗口；预算紧时缩小窗口，保持质量档和合成语义。父作用域进出、父级裁剪与效果、外层背景依赖、外部绘制、保留转场及捕获排除范围界定依赖边界。这项窗口调度继续使用现有离屏图集及存活区间规划。

同批独立源可占用一张离屏图集的不同区域，各区域保留透明边和物理像素对齐。共享规划给出区域坐标、整张存储尺寸和最后一次使用；两后端按此绘制、采样和回收，预算计量整张图集。无法共同容纳的源沿各自的存储完成同批合成。

目标的初始化状态属于本次帧准备。首次写入清空目标，后续写入保留内容；读取尚未写入的源时先初始化为透明。复用存储开启新的使用期，空画面、保留内容和在途提交沿用同一所有权约定。

捕获的 GPU 结果完成后，主线程按公共字节工作额度逐行复制到一份最终像素缓冲；一次至少处理一整行，尚未完成时唤醒后续推进，取消释放读回和输出。捕获读取结果显式标记像素编码。WGPU 输出 sRGB，GXM 输出线性 RGBA8；捕获服务在现有后台 PNG worker 内原位转换为不透明 sRGB，再编码并交付同一请求。转换持有原始载荷及其预算、不另分配整图缓冲，分块检查取消；直接消费捕获像素的调用方按编码完成同一转换。

临时目标的相邻尺寸可共用容量档，单份存储的填充最多占原后端字节成本的八分之一，并受整帧物理峰值预算约束。预算紧时沿用精确尺寸。目标按已接受提交的复用次数保留 2–32 帧；分配压力按年龄逐个回收可独立释放的目标，当前计划需要的数量及外部读者继续持有存储。

字形上传按图集页和相邻矩形组织批次。只合并能完整覆盖同批字形分配区的矩形，保留其他在用字形及各字形透明边；两后端使用同一合并规划。每批最多保留 64 个字形、64 KiB 覆盖率数据，单个大字形独立提交。准备完成后发布图集条目，在途上传持有其区域与存储。

预处理纹理分别保存作者使用的逻辑尺寸、可见内容的纹素尺寸和含边缘填充的存储尺寸。资源以线性预乘颜色提交；BC1 保存不透明颜色，BC3 保存颜色与透明度。转换工具直接保存可上传的像素或 BC 块，发行归档通过独立块压缩这些字节。支持对应格式的后端直接上传压缩块，布局、裁剪与输入继续使用逻辑坐标。

纹理容器显式记录存储布局。Vita 转换在离线阶段排列 GXM BC 块，运行时直接复制到原生纹理存储；桌面转换保留线性块序。归档压缩继续作用于已转换的字节。WGPU 上传 Vita 资源时在有界条带内恢复线性块序。转换可显式生成完整 mip 链，逐级在线性预乘颜色中滤波，保留基级布局坐标；驻留与上传按全部层级的实际存储计量，纹理就绪后发布画面。

舞台转场冻结已接受内容，在普通脚本回调中构建目标。目标就绪并被后端接受后，以接受时刻为起点推进合成；存档保存恢复所需的画面描述和资源版本。粒子以批次配置、种子和时钟描述运动，绘制时采样；发射活动沿节点和作用域生命周期退休。

转场旧画面的 GPU 结果按冻结绘图、父画面依赖、坐标变换、裁剪、输出尺寸和质量档复用。首次准备按依赖分段提交；旧画面完成后保留结果纹理，释放临时目标，再准备新画面。准备期间保留已接受帧，GPU 完成信号继续推进候选帧。命中的旧画面仅要求结果纹理驻留；缓存与在途使用共同持有资源额度，依赖改变或使用结束后回收。

粒子的尺寸曲线以归一化年龄采样，节点 `size_scale` 默认为 1，以有限非负倍率缩放所有存活及后续粒子的当前尺寸。倍率可绑定或动画，保留粒子位置、速度和批次时钟。出生角度与径向速度使用独立随机序列，阻尼按连续时间计算。预热直接设置发射时间偏移，按当前存活区间采样。曲线数据按批次共享，暂停、跳时和恢复沿同一采样公式处理。

绘制消费者可复用粒子出生常量，缓存随当前存活区间滚动，每个节点最多占用 64 KiB CPU 输出预算。超出缓存的粒子直接采样，批次替换后重新建立缓存；快照继续保存配置、种子和时钟。

视频帧使用共享的平面 YUV420 或 NV12 存储，逐平面记录行距，在 GPU 采样时转换颜色。生产者保留存储所有权，上传读取有效行与色度布局。已接受帧和在途提交持有的纹理保持原内容，最终引用释放后复用存储。

共享帧可携带平台可导入的只读存储，普通后端仍读取相同平面。Vita 将 AvPlayer 输出复制到有界自有 NV12 池，封存后交给 GXM 映射采样；映射保持至片元完成，最后读者释放后复用块。物理容量和元数据由生产者的预算票据保持至对应存储释放。

视频播放器使用解码器工厂，在后台以资源流、CPU 预算和停止标志创建解码器。软件与平台解码器交付相同的帧、音频和内容时间，播放队列、定位、终态与混音消费时钟由共用播放器管理。软件解码依赖按功能选择。

视频工作线程按画面与 PCM 队列各自的剩余容量请求解码。单轨满载时继续供给另一轨；尚未发布完的 PCM 包持有预算并分批写入，全部发布后才通知音频流结束。解码器区分暂未就绪与全部结束，暂停与取消沿同一有界队列处理。

PCM 发布完成后，工作线程可将输出块及其预算票据归还解码器复用。暂未就绪的轮询、定位修剪和队列分批写入保持同一块；实时混音线程消费预分配队列。

图片和视频的 `alpha_layout` 默认为 `"native"`，保留资源透明度；`"top_bottom"` 将上半帧作为颜色、下半帧的编码红通道作为覆盖率，自然尺寸为原宽度与一半高度。`source_rect`、九宫格和平铺使用可见颜色区域的像素坐标。颜色沿原色彩空间解码后按覆盖率预乘；覆盖率直接使用编码通道值。GPU 复用原纹理采样两个区域，布局随节点属性和已保留画面保存。

绘制和设备接口见 [reel-ui](../crates/reel-ui/src/lib.rs) 与 [reel-render](../crates/reel-render/src/lib.rs)。

## 资源加载与媒体

资源通过 `AssetIo` 与后台工作服务读取，运行期间使用固定资源。散文件按来源路径确定标识，归档使用打包索引中的内容摘要；修改素材后重新启动游戏。准备结果按资源标识共享，各消费者释放自身租约，最后一个持有者释放后回收。解码前读取头部并预留输出与工作区；首个场景的字体和图片准备完成后显示，场景换源期间保留上一完整画面。

媒体解码线程通过 `AssetIo::background_reader` 独立提交和接收读取，同一适配器的读取端共享 IO 线程、请求身份与有界队列。完成结果由所属读取端消费；每条流在创建时预留一个可复用的完成槽。关闭主适配器取消在途工作，IO 线程结束后释放文件与索引。未实现后台读取的适配器在创建媒体流时报告能力缺失。

普通图片按需解码，GPU 上传按每次工作额度续传，等待期间保留已接受画面。[分块图片](../crates/reel-core/src/prepared_image.rs) 根据实际视口选择层级和瓦片。预取优先让位于必需资源；画面与在途加载各自持有实际租约。资源归档挂载读取索引，内容通过范围 IO 获取。归档条目保留逻辑长度与内容身份，原样数据直接读取，压缩数据按独立块定位和解压。块目录按需读取，解压工作区按固定容量预留并复用，取消在块间生效。

媒体读取使用实际解码缓冲时长发布软截止时间，同优先级按最早截止时间调度，实时与普通请求沿既有比例交替推进。暂停清除期限，恢复后根据新缓冲更新；共享期限与请求持有同一预算生命周期。归档可在现有编码工作区合并相邻压缩块，临近媒体期限时停止新预读，块间保留取消点。

资源 IO 按有界块续读，输出容量预留一次，块间释放文件锁。续传保留请求身份、完成槽和取消状态，归档游标与解压区计入后台工作预算。音视频流在队列和输入总额度内保留容量；输入准入从可容纳的流式请求中优先选择最早的消费期限，同期限按到达顺序处理。最早等待者被后续请求越过四次后，保留下一次足够的容量给它。IO 调度优先处理实时块，并定期推进普通资源，避免大型图片读取阻塞音视频补充。

`assets.read(path, owner: null)` 从同一资源根或归档异步读取数据，等待结果取得不可变 `Bytes`。请求沿现有后台队列、资源预算与所有者生命周期处理；完成数据按 VM 字节存储计量。存档保留已完成数据和在途请求的恢复状态，读取失败指向调用源码。

音频接口返回普通活动，统一管理播放、暂停、定位、循环、队列与音量。短声音预解码，长音轨使用有界 PCM 窗；作者按内容组织调用，宿主选择准备方式。音频队列在混音边界连接已准备片段，欠载时输出静音并保留内容位置。

音频活动以正数 `rate` 控制内容播放速率，音高随重采样共同变化；位置、循环端点与 cue 始终使用素材秒数。活动内的队列共享速率，暂停冻结速率渐变，快照保留当前速率和剩余渐变。

Ogg Opus 沿软件解码接口提供单声道与双声道内容，时间线扣除编码预跳过和尾部填充，并应用头部增益。定位包含解码预热，循环使用同一可听帧坐标。编码、容器解析与解码在工具侧或后台执行，复用有界缓冲并计入 CPU 预算。

`reel-media` 创建设备与混音供给。配置取得实际格式后构建 mixer；接受播放后，实时回调独占供给并使用预分配缓冲和有界队列。文件 IO、分配、线程等待和最终 PCM 释放由控制侧或后台服务完成。

停止与挂起先关闭供给入口并等待在途调用结束。挂起保留 mixer，恢复验证格式后继续；格式变化或设备失败报告实际状态。控制侧移交退休 Sound 及其预算票据，后台物理释放完成后归还额度。会话退出持续驱动退休工作，宿主最终关闭时 drain/join 清理服务。

音频完成表示混音器已消费内容。CPAL 后端的硬件呈现时钟精度为 `Unavailable`；字幕和演出使用媒体内容位置。有声视频跟随 PCM 消费，静音视频跟随会话时间。

接口与队列约束见 [reel-media](../crates/reel-media/src/lib.rs) 和 [reel-audio](../crates/reel-audio/src/lib.rs)。

## 对白、历史与阅读

对白在提交时建立完整行组并预留历史。推进先补全显现，再结束等待；选择保留由交互身份限定的业务 key。正文、富文本样式和历史内容通过只读模型交给作者组件。

`reading` 保持局部对白、选择、历史、自动阅读和暂停状态。切换 UI 保留上下文身份，嵌套阅读结束后恢复父上下文。历史按提交追加，清理可保留最近的实际行数和剩余行身份。

逐字显现按字素与句内时序推进。`ready` 表示正文及尾部停顿完成。已读身份根据剧情调用路径记录，译文切换沿用同一身份；正常推进完成后登记已读。

追加对白复用已解析的样式、注音和时序片段，只合并文本及调整后段偏移。字素边界保留已完成前缀，从原末尾字素重新分段；新增组合字符延伸已显示字素时，整个字素继续可见。新文本、边界及历史全部准备完成后一起发布。

自动阅读在全文实际呈现后等待延时，在选择处等待玩家。快进沿普通控制流推进，并完成其策略覆盖的有限活动。暂停、模态界面、挂起和失焦按阅读协议更新计时与模式。自定义 UI 读取这些状态，决定按钮、光标和历史页的外观。

## 保存、恢复与系统数据

执行快照保存代码身份、任务栈、继续执行位置、对象图、绑定、活动、当前交互、舞台和媒体描述。不可变代码与资源通过共享身份引用；可变值保持快照时的数据与别名关系。

宿主属性验证器使用带名称和版本的静态描述符；对象持有描述符引用，快照注册表按名称和版本恢复验证回调。

捕获固定会话状态，按对象、边和字节额度推进。需要改变会话的输入使当前捕获以 `CaptureBusy` 失败，原槽位保留；后台保存完成后原子发布。缩略图与快照属于同一次槽位发布。 列表逐项枚举逻辑存档并打开所选提交代次，解析与文件打开位于同一提交边界；已打开文件保持旧代次读取所有权，缩略图载荷按需读取。

恢复先在隔离候选中分配身份、连接图和重建宿主描述，验证完成后替换当前会话。代码或格式不匹配时报告错误。设备句柄由宿主重建，过期完成消息通过新会话身份失效。

`persistent` 独立保存业务数据，适合设置和解锁进度。读取返回普通数据副本；作者在启动和剧情恢复后应用当前系统数据。剧情槽位与系统数据各自原子发布。

Vita 存储通过不可变数据代际和提交记录实现逻辑文件发布，读取与枚举经过同一存储接口。完整提交后回收旧代际；中断写入保持上一份已提交内容。

快照与 ABI 格式保持 v1。内部结构变更同步当前编码、解码和验证路径；作品的执行存档使用匹配代码包。

## 项目、翻译与编辑器

`reel check` 检查实际导入图，`dev` 编译并运行，`build` 生成 ASB，`export` 组织完整作品。检查与源码运行复用已验证的编译结果，构建时按所选配置编码产物。源码位于 `src/`，资源位于 `resources/`，转换缓存位于 `build/resources/`，导出位于 `build/export/目标/配置/`。`reel clean --resources` 删除转换缓存，`reel clean` 删除整个 `build/`。CLI 与播放器共用宿主接口注册和类型信息。

资源路径相对公共 `resources/`。`resources/@目标/` 按相同相对路径覆盖公共资源，目标内独有的资源也参与选择；其他目标目录从结果中排除。开发读取与导出使用同一选择规则，发行包保存选定资源的普通逻辑路径。资源目标默认使用宿主平台名，工具允许显式选择资源目标以在当前播放器中预览另一平台的素材。人工维护的覆盖文件保留在源码工程，自动转换产物位于 `build/`。

可选的项目根 `resources.toml` 通过 `[[targets.目标]]` 定义有序转换规则。`match` 匹配逻辑路径，首个匹配规则的 `convert` 选择 `texture`、`tiles`、`opus`、`video`、`font` 或 `copy`；未匹配文件保持原内容。先选择平台覆盖，再转换选定来源。纹理缩放改变纹素密度并保留逻辑尺寸、裁剪与输入坐标。分块转换保留原逻辑路径，以内容头识别清单；`first_level` 指定首个存储层级，视口需求限制在已存储层级内。视频转换通过 PATH 中的 FFmpeg 和 FFprobe 生成 H.264/AAC MP4，保持帧率与音画时长，按 `size` 等比缩放；`alpha_layout = "top_bottom"` 保留上下排列的颜色与透明度区域。转换逐文件执行，视频子进程限制线程并检查工作内存估算，实际子进程内存由编解码器分配。

`reel prepare-resources` 显式准备，`dev`、`run` 与 `export` 在使用作者工程时准备所选目标。缓存由源内容、转换参数、对应转换实现与依赖版本共同确定；视频和字体还包含外部工具身份。完整结果原子发布。运行与导出通过逻辑路径映射读取准备结果，源码资源保持原位置。

字体默认保留原有字符覆盖。`convert = "font"` 显式选择裁剪，`unicode` 指定玩家输入等用途所需的字符区间，`text` 选择包含剧情及翻译的 UTF-8 文件；二者并集决定保留字符。转换通过 FontTools 保留字体族、样式、布局特性及集合中的全部字体。字体缓存同时依赖字符集合和工具身份，裁剪工作内存采用子进程估算。

`dev` 在 `build/dev/` 缓存带源码映射的编译结果与内嵌翻译。工具和源码内容共同确定缓存身份，源码文件的增删和修改均参与检查；资源继续从当前项目读取。

原文与译文写在同一个 `tr` 调用中，编译器生成内部消息身份和语言目录。原文插值按顺序各求值一次，译文引用这些值。语言切换准备精确语言及基础语言后更新可观察状态；失败保留原语言。

Debug 包保留源码与指令映射，源码按文件压缩编码，映射在磁盘与运行时共用带稀疏索引的紧凑差分数据；定位查询只解码所在短块。加载按展开后的源码字节数与实际映射容量准入，诊断继续提供文件与准确字节范围。Release 剥离调试数据。发布时正文放入文本包，资源归档按完整条目分卷；ASB 内嵌分发清单。格式见 [ASB](../crates/reel-package/FORMAT.md) 和 [字节码](../crates/aside-vm/src/bytecode/FORMAT.md)。

LSP 使用同一编译器和宿主元数据提供诊断、类型、补全、悬停及导航。Rust 声明旁的英文文档生成可跳转 Aside 声明。源码范围使用 UTF-8 字节；协议按协商编码转换位置。未保存的编辑内容参与项目分析。

已知类型和签名支持静态诊断，动态字段沿运行时语义处理。编辑分析按模块和依赖缓存，文档变化使相关结果失效。格式化器由 CLI 与编辑器共用。

## 验证与维护

行为检查按语言、会话、UI、渲染、媒体和工具职责组织。输入、等待、取消、恢复、所有权和资源释放通过实际执行路径验证。CPU 布局检查、离线媒体和原生设备检查分别记录运行环境。

性能测量选择当前热点，记录实际工作量、分配、驻留和帧时间。缓存稳定性和退休后的释放是持续交互的重要边界。源码、测试及必要输入进入版本库；构建、日志与测量输出位于忽略的 `target/reel-artifacts/`。

命令入口见 [reel-dev](../crates/reel-dev/README.md)。协作规则见 [AGENTS.md](../AGENTS.md)。平台移植复用公共会话、舞台和资源合同，设备支持以对应适配器的实际运行结果为准。
