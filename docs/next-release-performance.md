# 引擎性能验证

桌面上以正式发布包跑代表性的正文推进、换图、快进、历史滚动和设置切页。60 Hz 的活跃帧间隔预算为 16.67 ms，高刷对照用于定位节拍和渲染余量。冷态和重访分别记录。资源、字形和离屏目标的性能结论要同时说明驻留峰值。

## 复现

1. 用更新后的 CLI 运行 `reel export --release --resource-target windows --data-only`。同一组对照使用相同画布、窗口尺寸和资源，比较播放器改动时沿用同一个包。
2. 用开启 `reel-player/performance` 的发布构建运行 `reel run <game.asb>`。通过开发工具的采集配置选定独立存档和报告目录。把首次标题、连续动画、输入切页及重访分开标记。
3. 交替跑基线和候选，按帧间隔、有效 CPU 工作和交换链获取分别归因。查看采样覆盖和丢弃数。静止窗口只跟踪资源完成、定时任务和输入响应。 [开发工具命令](../crates/reel-dev/README.md)

## 判断开销

- `surface_acquire` 是取交换链图像的等待，提交间隔用于观察活跃动画。GPU 时间戳与实际显示节拍各用独立观测。
- 冷换图先分离 RPK 读取、解码、透明覆盖率、线性预乘和上传。重访时核对是否复用同一资源与在途租约。 [资源预测](visual-resource-prediction.md) · [资源准备](engine-architecture.md)
- 快进分别记录对白发布、VM 和历史采集，再检查停在未读台词、选项和受保护演出时画面是否完整。
- 改变颜色精度、图像插值、抗锯齿和效果分辨率时，比对透明边缘、遮罩、混合及转场画面。Vita 的渲染与驻留成本由目标设备采样。

本地结果保存在 `target/reel-artifacts/`。版本行为见 [CHANGELOG](../CHANGELOG.md)。
