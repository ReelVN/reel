# 引擎性能验证指南

[文档目录](README.md) · [引擎架构](engine-architecture.md) · [视觉资源预测](visual-resource-prediction.md) · [开发工具命令](../crates/reel-dev/README.md)

本文说明如何在桌面端与目标设备上做**可复现、可对照**的性能采集与归因，避免只凭体感或测试数量下结论。

## 验证目标与核心口径

- 桌面验证统一使用**正式发布包（`--release`）**，覆盖五类代表性场景：**正文推进、换图、快进、历史滚动、设置切页**。
- **60 Hz 活跃帧间隔预算为 `16.67 ms`**；需要查看节拍和渲染余量时，用高刷显示器或关闭垂直同步做对照。
- **冷态（首次进入）与重访（热缓存）必须分开记录**。
- 任何关于资源、字形或离屏目标的性能结论，都要同时附上**内存/显存驻留峰值**。

## 复现步骤

1. **导出可复用的对照包**
   用当前 CLI 运行：
   ```sh
   reel export --release --resource-target windows --data-only
   ```
   对比不同播放器提交时，必须保持**同一份导出包、同一逻辑画布、同一窗口尺寸和同一套素材**。
2. **用带采样特性的发布构建运行**
   编译开启 `reel-player/performance` 的发布版本并运行 `reel run <game.asb>`，通过 [`reel-dev`](../crates/reel-dev/README.md) 指定独立的存档目录与报告目录，并将“首次标题、连续动画、输入切页、重访”打上独立场景标签。
3. **交替跑基线与候选版本**
   交替运行 baseline / candidate 以消除机器温度与后台抖动，按**帧间隔、有效 CPU 工作、交换链取图等待**分别归因，同时核对采样覆盖率与丢弃样本数。静止窗口只跟踪资源完成、定时任务与输入响应。

## 各项开销怎么读

| 维度 | 重点观察什么 |
| :--- | :--- |
| **显示与交换链** | `surface_acquire` 反映等待交换链取图的时间，提交间隔用于观察活跃动画流畅度；GPU 时间戳与实际显示节拍分开观测。 |
| **主循环唤醒** | 桌面唤醒记录会标出选中的截止来源（对白、时钟活动、媒体、本地化、控件动画、维护任务）。对照整帧看真实唤醒延迟，把“脚本本来就在等待的时间”剥离出来。不限帧测试优先用较短的带标记流程，并报告丢弃样本数。 |
| **冷换图与重访** | 冷换图拆分 **RPK 读取 → 解码 → 透明覆盖率 → 线性预乘 → GPU 上传** 五段；重访时确认是否命中同一资源与在途租约（见[视觉资源预测](visual-resource-prediction.md)）。 |
| **快进路径** | 分别记录对白发布、VM 执行与历史检查点采集的耗时，并核对停在未读台词、选项和受保护演出时画面是否完整。 |
| **画质与掌机** | 改动颜色精度、采样插值、抗锯齿或 `effect_resolution_scale` 时，必须人工比对透明边缘、遮罩、混合模式与转场画面。PS Vita 的渲染与驻留成本以实机采样为准。 |

本地采集结果统一输出到忽略目录 `target/reel-artifacts/`；历史版本改动见 [CHANGELOG.md](../CHANGELOG.md)。
