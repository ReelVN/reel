# Aside 语言与 VM 规范

[文档目录](README.md) · [作者指南 中文](guide/zh-CN.md) · [Creator guide English](guide/en.md)

## 一 定位与实现范围

Aside 是以 Rust 实现的动态嵌入式语言，Reel 是首个宿主。它承担剧情、业务状态、自定义 UI、组件、回调、异步流程、扩展脚本与工具逻辑；语言、编译器和 VM 不依赖窗口、媒体或特定舞台。工作区使用 aside-vm、aside-compiler，源码扩展名 .aside。本文定义当前执行语义；实现范围在对应章节说明。

部分语言回归用例来自 Quirrel；原输入、输出和许可见 [fixtures](../crates/aside-compiler/tests/fixtures/quirrel/README.md)。Aside 的语法与执行语义以本文为准。

语言使用动态值与可选类型注解，提供函数、类、模块、异常、集合、可观察绑定、宿主等待和执行快照。脚本堆采用单线程协作执行，跨线程交换拥有数据和稳定身份。

源码解析、语义分析、IR、字节码编解码和 VM 共用执行模型。支持普通调用/缺省、初始化局部绑定与共享捕获 Cell、异常/finally、tuple/array/table 与集合展开、索引/成员及混合赋值、可选取值链、位置调用 spread/rest、array/tuple/Range/generator 的 for 和尾随 children 收集。通用 Host 支持稳定身份、共享属性表、被追踪的私有内容及退休；语言不依赖 Reel 节点类型。索引位置在右值前保存；可选链只在显式可选段检查 null，括号结束传播；rest 每次创建独立外层 array。

源码和 ASB 支持 class/super、静态成员、继承与绑定方法及同包执行快照。接口与执行准入见[编译接口](../crates/aside-compiler/src/lowering/mod.rs)与[VM](../crates/aside-vm/src/lib.rs)。Reel 对白和选项的容量由宿主资源配置决定。

宿主可通过 AnalysisOptions.hosts 提供外围名称环境，默认为空。作者模块声明、局部绑定和显式 use 导入优先于外围宿主名称；use 与别名仍遵循普通模块规则。Reel 的编译入口以此提供当前注册的 reel::prelude，而独立 Aside 不含这些名称。此配置不改写源码，语义分析、链接和运行诊断沿用作者原始位置；语言与 VM 不依赖 Reel。

宿主模块可声明只读的编译期标量常量。常量按解析后的声明身份取值，导入别名保留同一值，局部同名绑定沿普通作用域规则处理。普通 `if` 的条件由这些常量、字面量、相等比较及布尔运算确定时，编译器只生成选中分支的执行代码；两侧源码仍参与语法和语义检查。运行时输入决定的条件保留普通分支。

## 二 语法与求值顺序

没有普通参数时，`component { ... }` 等价于 `component() { ... }`；具名函数、局部函数值、成员和索引取得的函数均可使用。if/while/for/match 等头部仍保留后面的控制流块，确需尾随调用时用圆括号包住整个调用。该简写沿用同一调用与 children lowering。
尾随 children 块调用作为独立语句时，可以像控制语句块一样省略分号。例如 `column { text("标题"); }` 后可直接书写下一个组件。显式分号同样有效，且不会取消子节点收集。独立 children 调用后的换行结束该语句，下一行的括号不会被解析成继续调用；取值上下文仍可正常链接后续操作。其他普通调用、绑定和赋值仍使用分号。

普通函数写 fn，生成器写 gen fn；普通函数可 await，独立任务通过宿主 spawn 启动。绑定使用 let 与 let mut，闭包写 |x| expression 或 || { statements }，模块导入写 use。除上文的独立 children 调用外，普通语句必须以分号结束，不做换行自动插入；函数、类及作为语句的控制流块后不要求分号。块末无分号表达式为块值，否则为 null；return、break、continue 和 throw 以分号结束。

```aside
use reel::{character, narrator};

fn add(a: int, b: int = 1) -> int { a + b }

fn main() {
    let mio = character("Mio");
    mio("先别开灯。");
    narrator("雨水沿着玻璃滑落。");
}
```

标识符、源码、注释和文本使用 UTF-8；标识符采用固定 Unicode 版本的 XID 规则并允许 _，名称按实际字符序列区分。注释为 // 与 /* ... */，块注释可嵌套。字符串使用双引号，支持反斜线、双引号、n/r/t/0 及 u{十六进制标量} 转义，非法标量报错。f"音量：{volume}" 为插值，{{ 与 }} 表示字面花括号。三双引号包围多行文本，保留换行且不自动缩进裁剪；前缀 r 禁用转义，f 启用插值，二者不混用。数组为 [a, b]，对象为 {name: "Mio", [key]: value}，tuple 为 (a, b)。列表允许末尾逗号。

{} 在要求表达式的位置为对象，在 fn、if、循环、try 等要求块的位置为块。块内语句位置以 `{name:`、`{"key":`、`{[expression]:` 或 `{...` 开始时按对象表达式读取，因此 `if flag { {accept: value} } else { {back: value} }` 直接返回对应对象。标记循环的 `{label: while/for/loop ...}` 仍为块；独立空 `{}` 仍为空块，返回空对象写 `({})`。|| {...} 是闭包块，返回对象写 || ({name: "Mio"}) 或 || { {name: "Mio"} }。match 分支结果位置的最外层裸 {...} 同样是块，末尾表达式提供分支值；对象结果可写 _ => ({name: value}) 或 _ => { {name: value} }。闭包参数类型中的 union 使用括号，如 |x: (A|null)| body；参数列表最外层的 | 固定为结束符。if/while/for/match 头部及 class 的基类表达式最外层关闭尾随 children 调用，使其后的花括号属于控制流；确需尾随调用时用圆括号包住该表达式。对象/数组展开分别写 {...base, score: 1}、[...items, last]，均按源码顺序复制条目/元素，保留内部引用。对象展开只复制自有槽，不复制 delegate，后项覆盖前项。

if condition { ... } else { ... }、while condition { ... }、for pattern in values { ... } 是基本控制流；if 作为取值表达式必须有 else。loop { ... } 为无限循环。break/continue 默认指向最近循环，可通过 label: while ... 与 break label; / continue label; 指定外层循环。循环本身不产生隐式结果。for 每轮创建新绑定，闭包保留本轮值。a..b 不含终点，a..=b 含终点，均产生整数 Range，按单位步长递增；倒置区间为空，推进在整数溢出前终止。

一般表达式按源码从左到右求值一次；短路、条件和模式有各自明确规则。赋值先计算并保存目标对象与键的值，再计算右值并写入；右值随后重绑原对象或键的名称，不改变已经准备的位置；复合赋值先计算左值位置一次，再读取、求右值、计算和写入。赋值链 a = b = value; 作为一条语句，先从左到右确定所有目标位置，末尾 value 求值一次，再按从内到外的顺序写入。整条链无表达式结果；算术、参数、let 初值等取值位置使用赋值会诊断。每个解构目标按自身的原子准备/提交规则写入，整条链沿用普通副作用规则。求值错误不会自动撤销已经发生的普通副作用；有事务语义的宿主接口另行声明。

`a..b`、`a..=b` 产生惰性整数区间，`for` 直接读取迭代结果。字符串插值按书写顺序求值，接受 null、bool、int、float、string 和 CoreError 的错误说明。插值复用分块缓冲区，按字节计费与暂停，完成 UTF-8 验证后直接封存。

array/tuple/table 提供 `len()`，array 提供 `append(...values)`/`pop()`，table 提供 `has_own(key)`/`get(key, default: null)`。方法取值保留原接收者，表自己的同名字段优先；表中的普通闭包按其参数声明调用。空数组 pop 抛可捕获错误，append 按实参顺序追加并返回原数组。

紧邻声明的连续 `///` 行提供英文 Markdown 文档；空白行或普通注释结束文档组。编译器的 `documentation::declaration` 从无损语法树按需读取文档与源码范围，供编辑器查询；`documentation::examples` 提取其中的 `aside` 围栏供接口示例检查。宿主函数和属性的文档由声明宏提供，见 [host SDK](aside-host.md)。

## 三 值 绑定 相等与数值

当前值包括 null、bool、int64、float64、不可变 UTF-8 string、Bytes、tuple、array、table、class、instance、closure、weakref 及注册宿主值。可变缓冲、集合和宿主类型通过对应注册接口构造。

`Bytes.len()` 返回字节数，`bytes[index]` 读取从零开始的非负整数索引，结果为 0 到 255 的整数。越界读取报告 `OutOfBounds`；字节数据保持不可变。读取直接访问已有存储，复制值继续共享同一份数据。

let 只禁止重绑名称，不冻结对象；let mut 允许重绑。参数默认不可重绑，mut 参数允许重绑。词法作用域允许内层遮蔽；未声明或尚未初始化的名称读取报错。可变捕获由所有闭包和原作用域共享 CellId；不可变捕获可按值保存，所指对象身份继续共享。array/table/instance 等身份对象的赋值和传参不隐式复制。

```aside
let state = {score: 0};
state.score = 1;
let mut count = 0;
let next = || { count += 1; count };
```

标量按值相等，array/table/instance/closure 等身份对象按身份相等；tuple 按第五节递归规则相等。bool 不与数字相等。int/float 混合比较按精确数值关系，不能先把大 int 舍入成 float；+0.0、-0.0 与整数 0 相等。NaN 不自等，Infinity/NaN 是合法浮点值，具体 NaN 位型和对象内布局不是语言可观察身份。

条件、!、&&、|| 只接受 bool；逻辑运算短路并返回 bool。?? 仅在左值为 null 时计算右值。?.、?[...]、?(...) 只在接收者为 null 时短路，该段及其后同一可选链不求索引/实参；括号结束链传播。非 null 接收者的缺失字段仍报错，不能吞掉 metamethod 的异常。

`is` 对不可重绑的局部名称和参数提供分支类型细化：检查成立后，if/while 的分支、短路表达式的后续操作及分支内创建的闭包使用已确认类型；`!` 交换成立与不成立的路径，不成立时可从 union 排除已确认匹配的成员。离开该路径恢复声明类型。可重绑名称与对象字段按各次读取的声明类型检查。细化只影响静态检查与编辑器信息，执行仍使用原值、原捕获和原 `is` 判断。

int 加减乘、负号及整数除法溢出报错；MIN/-1 报错。int/int 的 / 向零截断；任一操作数为 float 则按 float64 运算。% 是与向零除法一致的 remainder。数字除零含浮点 ±0 均报错，其余 float 运算允许产生非有限值；宿主属性可另行要求有限值。+ 只接受数值对或字符串对，标量转成文本使用字符串插值。

编辑器从已绑定的表达式和返回路径推断函数结果、table 的已知字段及 array 元素类型，并保留字段的原始声明位置，供跨模块悬停、补全与定义跳转使用。显式类型注解仍决定运行时检查；可变值的类型无法确认时保持动态。

`std::math` 为宿主可安装的数学标准库，复用 Rust f64 数学函数，支持弧度三角函数、atan2、sqrt/hypot、pow、指数/对数、abs/floor/ceil/round 与 radians/degrees。这些函数允许 int 入参在调用边界按 float64 转换，结果为 float；其他类型在调用处报告错误。NaN/Infinity 遵循上述浮点值规则。

`std::math::to_int(value)` 保留整数原值，将浮点数向零截断后转为 int。NaN、Infinity 和超出 int64 范围的值在调用处报告 `Type` 错误。

`std::number::format(value, precision: 2, mode: "fixed")` 将 int 或 float 转成十进制 string。fixed 的 precision 为小数位数，范围 0..1024；scientific 的 precision 为有效数字总位数，范围 1..1024，输出小写 e、无正号或补零的十进制指数，例如 `1.000e12`。两种模式保留所请求的尾零，整数沿 int64 转换保留精度。舍入使用最接近值、中点取偶数；浮点转换直接针对当前二进制数值，因此两位小数的 `2.675` 为 `2.67`，一位小数的 `12.25` 为 `12.2`。负零保留负号，非有限值输出 `NaN`、`inf` 或 `-inf`。非法模式、非整数或越界精度、非数值输入在调用位置报告 Type。转换直接写入受 VM 文本额度约束的缓冲区；精度上界限制单次原生转换成本。源码、ASB 和 derive 使用同一接口。

`std::math::curve(keys)` 构造不可变标量曲线，`curve.sample(time)` 返回指定时间的 float64 值。keys 为非空 array/tuple，元素为 `{time, value, mode: "linear", in_tangent: 0, out_tangent: 0}`；time/value 必需，其余字段可省略。所有数值及采样时间须有限，时间允许负值并按非递减顺序提供。mode 描述从该关键帧出发的区间：linear 线性插值，step 保持左值，cubic 使用左帧 out_tangent 与右帧 in_tangent 作三次 Hermite 插值，切线单位为值/秒。重复时刻表示瞬时跳变，恰在该时刻取最后一帧；到达该时刻之前的区间以第一帧为右端。首尾以外保持端值，单帧曲线为常量。插值保留超出端值的结果；中间运算遵循 float64 规则。

构造按顺序复制关键帧数值，每个记录在一个构造步骤内读取；已复制记录随后改变不改写副本。构造期间外层数组内容变化报告 ConcurrentModification，部分结果随原生续体取消回收。构造与 sample 可在初始化和 derive 中调用；derive 追踪构造时实际读取的可观察数据及 sample 实参的读取。曲线本身只读，没有任务、节点 owner 或播放状态；保存恢复沿普通堆对象保留曲线和已取出的 sample 方法。记录只接受上述五个字段；非法形状、顺序、mode 和数值在相应原生调用位置报告。

位运算使用 64 位补码；移位量须为 0..63。>> 算术右移，左移按位截断。字面量支持十进制、0x、0o、0b 与分隔下划线；超出 int64 范围时报错，负最小值按整体常量处理。浮点比较、解析、舍入、格式化及常量折叠与运行时一致。优先级从高到低为：成员/索引/调用，前缀 await ! ~ + -，* / %，+ -，<< >>，&，^，|，< <= > >= 与 is，== !=，&&，||，??，.. / ..=，赋值。二元运算左结合，?? 与赋值右结合，比较与区间不允许无括号连用。is 只测试类型，不转换值；赋值无可用于运算的结果。parser 与非法类型测试直接依据此表。

显式 tuple 与 union 契约用于 `is`、绑定、共享捕获、参数和返回值；tuple 要求数量及逐项类型一致，union 接受任一分支。检查使用加载时计入容量的显式工作栈，执行前按类型 DAG 的工作上界计费，检查过程不分配临时容器。失败赋值不发布新值。
宿主注册的名义类型也可用于类型注解和 `is`。注册声明提供规范名称、版本及基类，Rust 在构造宿主值时赋予对应身份；类型检查接受该身份及其基类。编辑器与执行时读取同一份注册声明。
`Binding` 表示 `bind` 和 `derive` 返回的属性引用。引用保留来源的读写权限；节点属性读取返回当前值，接收绑定的构造参数和属性赋值同时接受值与 `Binding`。
CellContract 的 type_id 为 Option<TypeId>：语言绑定保存 Some(包内类型)，独立宿主 Cell 保存 None 并服从自身的 builtin 契约；不会把宿主 Cell 的占位索引误当成当前包的类型。

## 四 对象 集合与键

固定 array/tuple 的元素按源码从左到右各求值一次，再构造容器。固定 table 字面量的每个 key/value 同样按源码顺序各求值一次，全部表达式完成后才按有序字段描述建表；命名字段的 key 是对应字符串。不可散列键等建表错误发生在这一构造阶段，不提前跳过后续字段表达式，也不撤销此前已发生的普通副作用。重复键按字段顺序处理，后值覆盖，首次插入位置不变。编译器保留有序键值对，不因静态看似重复而删除表达式求值。

array 为可变有序序列，索引只接受非负 int，越界报错。标准操作包括 len、append、extend、insert、remove、pop、clear、slice、find、contains 与稳定 sort。slice 和数组展开创建新的外层序列，共享元素引用。

array/tuple 的 `find(value)` 返回首个按 `==` 相等元素的从零开始索引，未找到返回 null；`contains(value)` 返回是否存在相等元素。两者按顺序查找，使用相同的数值、文本、tuple 和对象身份相等规则。查找及嵌套比较按执行预算推进，不复制来源；数组在查找期间发生内容修改时报告 ConcurrentModification。方法可保存后调用，支持 `value:` 具名参数，derive 追踪来源的内容读取。

内置集合与字符串方法的参数、返回类型和英文说明由 VM 声明生成，供编译检查、补全、悬停和定义跳转共同使用。已知 array、tuple 和 string 的方法调用检查具名参数及类型；table 的自有字段优先于同名内置方法，其调用继续按实际字段值解析。

`array.sort(compare: null)`：稳定升序排序，成功后原子更新原数组并返回它，等序元素保留原有顺序。缺省比较接受 int/float 的精确混合数值顺序或字符串的 UTF-8 字节序；NaN 和无法相互排序的类型报 Type。自定义比较器 `compare(a, b)` 返回负数、零或正数 int，分别表示小于、相等或大于；它沿用普通函数、闭包、绑定方法及 native 调用，处于 NoWait 上下文。排序使用分片归并、线性额外工作空间及 O(n log n) 次比较/元素移动，长字符串比较同样分片。比较器异常、取消或来源数组被修改时不提交工作副本；比较器自身已发生的写入不会回滚。工作游标和正在执行的比较器随 VM 快照恢复，不重放已完成调用。

table 为保留插入顺序的动态关联对象；点访问等价于字符串键读取。读取检查自有槽。普通 table 的 = 总在自身插入或覆盖槽；覆盖不改变原位置，删除再插入移到末尾。remove 删除自有槽。

has_own 检查自有槽；get(key, default: null) 在缺键时返回默认值。derive 中的 has_own 命中时记录该字段依赖，其他已有字段的覆盖保留结果；缺键时记录集合依赖，后续插入、删除或清空会重新检查。

`table.get(key, default: null)`：沿普通表读取的键验证与可让出查找路径，找到时返回原值（包括 null、false、0），缺失时返回缺省。缺省是普通实参，按调用求值规则执行；方法取值绑定原表，自有同名字段优先。model 中缺失查找也记录依赖，后续插入能更新 derive。非法键与查找期间的结构修改照常报错。查找复用原预算，缺省值保留在调用帧的现有根中，暂停、取消和快照沿原路径处理。

普通 table、model 和宿主属性的单键读取、写入、has_own 与 bind 引用查找只校验结构版本。切片间覆盖已有字段保留键的位置，操作完成时读取或写入当前槽；相同字段与无关字段的覆盖均不使查找失败。增删或重排键使尚未完成的查找报告 ConcurrentModification。derive 在实际读取时记录该字段依赖；复制、展开和 remove 仍按既有完整内容版本校验，默认迭代器仍按结构版本推进。

`table.remove(key)`：删除自有键并返回原值，保留其余键的插入顺序及内部对象身份；缺键报 MissingKey，非法键沿普通索引的验证路径报错。方法可取值后调用，也接受 `key:` 具名参数；自有同名字段仍优先。删除再插入的键位于末尾。查找、工作副本及 model 字段位置映射按 VM 预算推进，成功提交时更新内容和结构版本；取消或来源内容在切片间改变时不发布副本。未完成删除的调用及映射进入 VM 快照，恢复继续原进度；源码示例见 [collections.aside](../examples/collections/src/main.aside)。

可散列键为 null、bool、int、除 NaN 外的 float、string、Bytes 及递归可散列 tuple。等值键必须同 hash，包括精确相等的 int/float 与正负零；可变对象及含它们的 tuple 作为键时报告错误，并指出元素路径。

array 的默认迭代器记录结构版本；增删或改变位置使下一次推进报 ConcurrentModification，覆盖已有位置的值保持结构版本，尚未访问位置可看到新值。需要固定外层序列时，先通过 slice 或展开建立副本。for 体等待时，其他任务的修改同样适用。容器 schema、顺序、结构版本和游标进入快照。

## 五 tuple 的值语义

(a,b) 是二元 tuple，(a,) 为一元，() 为零元，(a) 为分组。空 tuple 与 null 不同；普通函数无返回值仍返回 null。tuple 数量和位置是值结构，元素表达式从左到右求值一次，原动态类型不被数值统一化。其槽不可重写、增删或通过解构反向修改。

```aside
fn measure(node) { (node.width, node.height) }
let (width, height) = measure(view);
let items = [];
let pair = (items, items);
pair[0].append("shared");
```

tuple 是浅层不可变值，例中两项保持同一个 array。赋值、传参及返回不深复制元素。实现可以内联或共享不可变 tuple 存储，GC 和快照按值结构保存 tuple。tuple 可经由可变对象间接参与环，GC 和快照必须保留这些引用。

同长度 tuple 按顺序用元素普通 == 比较，嵌套 tuple 递归；可变容器/实例元素仍按身份。不同长度不等，tuple 与 array 不等，() != null。包含 NaN 的 tuple 可不自等，不能只因内部存储句柄相同就直接返回 true。相等使用受预算的显式栈，不依赖无限 Rust 递归。

所有元素递归可散列时 tuple 才可作为普通键；长度、顺序与元素 hash 共同参与。可缓存不可变内容的内部 hash，但不得将其当跨进程稳定身份。包含 array、table、instance、closure 或 NaN 时拒绝散列并给出路径。

t[i] 使用从零起的 int 索引，负数及越界报错；t.len() 返回固定长度；slice(range) 返回 tuple；遍历按位置顺序。所有读取和切片继续共享内部对象引用。

`tuple` 类型注解接受任意长度和元素类型的 tuple；`(int, string)` 等结构注解继续检查精确长度与逐项类型。两者都可用于参数、返回值、绑定及 `is`，`array | tuple` 表示接受两种序列。

let (a,b) = value 匹配精确数量的 tuple，支持嵌套 tuple、名称、_ 与类型标记。需可选值时显式返回 null，需可变长度时用 array。

多返回值始终是一个 tuple：return (a,b); 交付一个值。f(pair) 传一个参数，f(...pair) 才展开位置参数；不会隐式取首项或按表达式所在位置自动扩成多个结果。优化可用多寄存器传递，但动态调用、快照、异常和调试观察必须等价。

### 集合操作的共同约定

array/tuple 的 `slice(range)` 使用非负索引，保留原容器种类和元素引用；范围端点必须在容器边界内。array 提供 `insert(index, value)`、`remove(index)`、`resize(length, value: null)`、`reverse()`、`extend(items)`、`clear()`、`top()`、`swap(a, b)`。insert 允许在长度位置追加；remove 返回被移除的值，top 返回末项且空数组报越界；其余修改方法返回原数组。extend 接受 array/tuple，自身展开只捕获调用开始时的元素。table 提供 `keys()`、`values()`、`entries()`，按自有字段顺序返回新 array；entries 的元素为 `(key, value)` tuple；`clear()` 返回原表。

这些方法支持其声明的具名参数；绑定错误发生在全部实参求值后、任何修改前。批量编辑通过私有工作副本按元素推进，完成后一次提交；中途异常、取消或来源内容变化不发布半成品，内容变化报告 ConcurrentModification 并保留实际来源。工作副本与旧内容共享子对象，提交保持容器身份；旧存储交给增量 GC 回收，不在提交点线性析构。append/pop 保持已有逐项行为。

## 六 Unicode 文本和可变缓冲

string 保存不可变、有效的 UTF-8 文本，相等按原始文本序列比较。长度与切片接口明确使用字节或 Unicode 标量作为单位；具体签名和英文文档见[内置方法声明](../crates/aside-vm/src/builtin_methods.rs)。

文本基础方法：`byte_len()` 返回 UTF-8 字节数；`scalar_count()` 返回 Unicode 标量数，组合字符与 ZWJ 序列按各自标量计数。`slice_bytes(range)` 和 `slice_scalars(range)` 返回不可变 string，使用非负、从零开始的范围，不截断越界输入；倒置范围或非法 UTF-8 字节边界报 OutOfBounds。`starts_with(prefix)`、`ends_with(suffix)` 精确比较文本，空前后缀总是匹配，不做规范化。`separator.join(items)` 接受 string 的 array/tuple，只在相邻项之间插入 separator；空输入返回空 string，非 string 项报 Type，不隐式格式化。这些方法支持声明的具名参数。

to_ascii_lowercase()/to_ascii_uppercase() 返回新字符串，仅转换 ASCII 字母，保留其他 UTF-8 字节。实现复用 Rust 标准库字节切片转换与现有分片文本缓冲，按字节线性推进并计入工作/分配预算；空字符串也返回字符串。它们不执行 Unicode 或语言环境相关大小写折叠。

`trim()`、`trim_start()`、`trim_end()` 分别移除两端、开头、末尾连续的 Unicode 空白，空白定义复用 Rust `char::is_whitespace`；不移除正文内部空白、不规范化或转换大小写。方法无参数，返回普通 string；没有需移除的空白时共享原字符串。定位按 UTF-8 字节分片并使用现有解码状态，至多线性扫描；结果只复制保留范围一次，空白全串得到空字符串。游标和未发布结果沿普通 VM 帧的预算、取消和快照路径管理。

计数、切片和前后缀比较按字节分片；byte_len 为常数成本，scalar 切片单次前向扫描定位后复制。join 只向一个私有缓冲顺序追加，每个输出字节复制一次；空项也按元素计费。来源数组在执行片之间变化报告 ConcurrentModification；失败、取消不发布部分结果。UTF-8 解码与标量迭代复用 Rust 标准库，VM 仅管理分块游标、预算与根，不维护另一套 Unicode 解码规则。

`string.split(separator)` 返回 string array，按完整分隔字符串从左至右非重叠切分，保留开头、末尾和连续分隔产生的空项；空 separator 在 Unicode scalar 边界切分并保留首尾空项，与 Rust str::split 的字符串分隔语义一致。separator 必须是 string，支持具名实参与绑定方法。扫描与结果复制按工作量让出，使用线性匹配，不先复制整段输入；临时匹配状态和已产出的片段由 VM 根持有并参与 GC、取消和执行快照。

文本范围从零开始，端点规则与 Range 一致；字节切片端点须位于 UTF-8 边界。Reel 的逐字显现使用文字服务提供的字素和排版信息。

## 七 模式和分支

match 的可执行模式包括名称、`_`、字面值、分组、类型测试和 OR。类型测试写 `pattern is Type`，OR 写 `left | right`，is 结合更紧；类型测试中的 union 用括号表示，如 `value is (int|null)`。同一分支名称唯一，OR 各侧绑定相同名称。

```aside
let result = match event {
    "confirm" | "click" => advance(),
    "cancel" => close_panel(),
    _ => null,
};
```

match 的输入求值一次，按源码顺序匹配；guard 要求 bool，命中后执行该分支并取得其结果。guard 在 NoWait 上下文运行，已经发生的副作用保留。没有分支命中时抛出 MatchError。分支绑定每次进入时创建，闭包保留当次值。源码与 ASB 使用相同执行路径，示例见 [match_values](../examples/match_values/src/main.aside)。

`let (key, value) = entry` 和 `for (key, value) in entries` 已支持固定长度 tuple 解构，允许嵌套 tuple、名称、`_` 和类型标记。先检查结构并准备全部结果，再建立绑定；类型或长度不匹配抛出 PatternMismatch。每轮 for 为捕获的名称建立独立绑定。使用现有 Is、IndexGet 和 PatternRequire 指令，不复制 tuple。

## 八 函数 调用与类

类执行使用 Aside 字节码 `Class` 描述及共享调用栈；声明身份记录为模块、名称和内容版本。类布局在创建时建立，实例只保存自己的字段槽。构造、字段初始化和布局建立服从执行预算，字段值及绑定方法的接收者由同一 GC 追踪。类调用、方法和普通函数共用参数名、缺省、类型与效果检查。

块内 fn 声明先建立只读函数绑定，允许自递归和互相递归；捕获普通 let 的初始化状态仍受检查，不得把未初始化值视为 null。命名参数适用于脚本闭包和 native，使用同一签名描述与绑定器。位置参数在命名参数前；fn f(a,b=1,...rest) 支持每次调用新建外层 array 接收尾部位置参数，没有剩余项时也新建空 array。rest 注解约束整个 array 绑定，不隐含逐元素约束；确定与 array 不相容的注解给出诊断。rest 只接收位置实参。

callee、所有实参、展开和 children 按源码顺序各求值一次，然后绑定签名；重复名、未知名、多余或缺失参数报错。缺省在每次调用中按参数顺序求值，可引用前面参数，不可引用后面参数；不允许外部等待/yield。缺省的块表达式以块尾值产生参数结果；显式 return 的词法范围从普通函数体开始，缺省边界内的 return 给出 InvalidDefault 诊断，即使位于条件或短路分支也一样。缺省内定义的嵌套函数按自己的函数边界正常 return。break/continue 仅作用于缺省内部建立的循环，throw 沿参数准备规则传播。实际参数全部先求值，再运行缺省，children=[] 每次独立。

`f(...sequence)` 展开 array/tuple 为位置参数；`f(...options)` 展开 table 的自有条目为具名参数，键必须是 string，不读取 delegate 或调用用户代码。`f(...positional, ...named)` 直接支持函数值、脚本函数、宿主函数与绑定方法的完整转发，不另设 call 包装接口。浅捕获在展开处固定外层条目，内部对象引用仍共享；分片期间源被修改时报 ConcurrentModification。非法源、非字符串键、复制和额度错误发生在展开阶段；动态顺序错误、重复名、参数槽冲突、缺参和缺省处理发生在全部实际参数完成后的绑定阶段。具名参数之后不能出现位置参数，空展开不改变顺序；具名展开可以接在显式具名参数之后。覆盖样式先写 `{...defaults, ...style}`，同一次调用重复供给参数始终报错，不隐式覆盖。尾随 children 仍是最后一个具名参数。

class 使用单继承，命名声明写 class Child: Parent { ... }；匿名类表达式写 class { ... } 或 class: Parent { ... }。命名声明建立词法绑定，该绑定可直接作为类值使用；匿名类表达式创建并返回新的类对象。实例有声明字段，let/let mut 表示只读/可写；字段初始化每实例按基类到子类执行。未给初值的只读字段必须由构造过程赋值一次；结束时验证完整，实例状态为 Constructing、Ready 或 Failed，并记录已初始化字段。成功返回 Ready；异常结束标记 Failed。显式发布过的引用仍保持身份，但对 Failed 实例的普通操作报告 ConstructionFailed，诊断/status 查询保留可用；Constructing 中读取未初始化字段报告 UninitializedField。普通已经发生的副作用沿用语言规则，构造失败不伪装成外部事务回滚；快照保存构造状态、字段位图与执行帧。owner/Region 硬撤销或 invoke_sync 预算终止同样由 VM 清理把未完成实例标记 Failed；GC/快照只追踪已初始化槽。全部别名与既有绑定方法读取同一实例状态，方法调用也执行 Failed 检查。构造方法 fn init(self, ...) 显式首参 self；类调用创建实例并调用最近的有效 init，派生类未声明 init 时继承基类构造。声明派生 init 时只调用它，super.init(...) 显式初始化基类，禁止同一基类 init 重复执行。字段初始化不会因 super.init 重跑。

方法调用提供接收者一次；方法取值形成强保留接收者的绑定闭包，普通表中的闭包不自动注入 self，普通函数不继承调用者的隐式 this。super.method 固定从词法基类查找并保留同一个接收者。有界弱缓存可以复用仍存活的绑定闭包，缓存本身不延长接收者或声明的生命；每次取值也可以创建新闭包，事件注销依赖 Subscription token。static let/static let mut 与 static fn 属于类，static fn 无 self；只读 static 初始化一次。class 可作为值和局部声明，继承图不得成环，公开字段与方法反射不暴露内部布局。

类、实例和 super 可以用字符串索引访问成员，`object[name]` 与对应的点访问共享字段类型、读写权限、继承和接收者绑定。赋值与复合赋值的对象、键各求值一次。非字符串键报告 Type，缺失成员报告 MissingKey；固定布局保留，索引赋值不能增加字段。可观察实例的索引读取记录实际字段依赖，bind 固定创建时选中的字段。

已链接的 native 函数可以作为普通函数值保存、传递、返回和可选调用，也可以交给宿主的 CallScript 回调入口。Aside 字节码 FunctionKind::Native(NativeId)，编码为 tag 3 后接 u32 注册索引；签名必须与注册一致，不携带脚本指令、寄存器、绑定、捕获或异常区域，源码映射可在 PC 0 保存取值位置。普通调用、宿主启动和 CallScript 都直接建立同一种 NativeFrame，完整参数只绑定一次；缺省闭包与可变参数共享原来的 Cell，不经过脚本转发帧。aside-host 为每个合同预置一个 Native FunctionDef，供宿主绑定方法；编译器复用已有定义，仅在缺失且实际取值时新建。VM 在模块常量根区持有稳定函数值，MakeClosure 读取该常量而不分配对象，也不要求 ALLOCATE 效果。不添加作者全局变量。实际脚本调用处优先作为故障来源；宿主直接启动该函数值时使用定义中的取值位置（若有）。

## 九 对象扩展

table 按自有字段读写，类使用声明的继承关系查找字段和方法。宿主通过注册类型、属性和 callable 入口扩展对象，具体契约见第十六节。

## 十 模块 类型与反射

use reel::{stage,text}; 为分组导入，use game::ui::dialogue::dialogue_view; 为单项导入，use reel::prelude::*; 为公开名字通配导入。别名用 as，pub 控制导出，pub use 重导出；命名空间导入使用 use game::ui::dialogue as dialogue;，解析器依据模块/符号声明区分，若两者同名则要求显式分组选择符号。通配不能静默覆盖已有名字。

宿主为编译器提供源码模块和入口。Reel 项目固定以 src 为源码根，启动 src/main.aside 中的 main；game:: 后的模块段对应 src 中的目录和 .aside 文件，名称须合法标识符。共享源码复制到项目后沿普通 use 导入，同一实际文件只建立一个模块环境。main/game/reel/std 保留；reel 与 std 由宿主注册，不搜索同名源码目录。启动函数可以私有，这不使其余私有符号可被导入。use 在编译时解析，构建产物保存确定的模块集合。

编译器按导入关系分析多个源文件，并将普通函数和值模块编入 Aside 字节码。文件提供方按导入发现源码，模块别名归一到固定声明身份；同一文件只产生一份环境。导入读取与重导出共享原 cell，Aside 字节码的模块绑定编号依次包含自有全局和导入，验证时解析并缓存实际 cell 索引。物理来源独立保存在 SourceFile.path，运行故障保留对应文件与表达式范围。

先链接全部导入的函数/类型符号。仅在类型位置使用的导入参与链接与打包，初始化排序依据值依赖；未使用的导入和公开重导出保留模块依赖。SCC 凝聚图按依赖先于使用者的拓扑顺序初始化；同一 SCC 内及互不依赖的并列 SCC 用规范化模块路径稳定排序，再执行顶层表达式。链接不执行 class 字段初始化、extends 求值或任意表达式；未创建完成的 class 不可实例化。读取未初始化绑定报带实际链路的 ModuleInitializationCycle；可链接的函数互相引用不被 import 图的环一概禁止。模块初始化不得外部等待。

模块实例包含固定版本的导入绑定和私有全局。会话从确定代码集合创建模块环境；闭包与执行帧保留所属代码版本和绑定。代码加载与执行存档恢复共同验证这些身份。

类型注解支持 any、基础类别、class/native 名称、T|null/union、固定 tuple (T,U)、函数签名。函数类型写 fn(T,U) -> R，箭头右结合，返回类型可为 union；函数类型本身参与 union 写 (fn(T) -> R)|null。具有明确函数签名类型的值也满足不限定签名的 closure 类别。函数类型只描述位置参数和返回类型；通过该类型调用时按注解检查实参数量、每个实参和返回值，展开参数使用同一检查。已知函数签名在静态分析时检查兼容性，动态值在写入时检查可调用性，调用时检查实际值；函数身份与捕获保持不变。默认参数或剩余参数允许实现相应的位置调用，绑定方法隐去接收者，等待与取消沿用普通调用。() 为零元 tuple 类型，单类型圆括号作分组，含逗号为一元或多元 tuple 类型。注解不改变动态存储，在能确定时静态诊断，否则参数进入/返回及声明写入时验证。array/table 注解约束容器类别；元素仍按动态值保存。

脚本使用 `is` 检查类型。宿主声明通过同一注册元数据提供类型、字段、参数、默认值和效果，编译器与编辑器共享这些信息。

## 十一 children 与可观察绑定

尾随 children 块是通用调用语法：立即计算名为 children 的 array 参数，不是隐式闭包、不按帧重跑。块内独立表达式语句产生 Node 时按顺序收集，分号不取消收集；块末 Node 只收集一次。null 忽略，其他值报错。let 初始化与赋值不收集；if/for/while/match/普通语句块继承词法收集位置，控制流整体不再次收集末值。嵌套尾随块建立独立收集器，被调用函数不继承调用者收集器。显式 children 与尾随块不能共存，事件回调必须命名传入。

宿主可在外部符号上声明 `must_use_result`。语义分析对静态识别的调用检查结果去向：普通语句丢弃该结果时报告 `ASS016`，位置指向构造调用。Reel 的舞台节点构造器使用此声明，因此 `fn heading() { text("标题"); }` 会提示返回或使用节点；改为尾值 `text("标题")` 或 `return text("标题");` 即可。返回、绑定、参数和 children 收集都使用结果；`let _ = text("标题");` 表示显式丢弃。children 内的 `text("标题");` 仍收集节点，普通函数体、模块和场景入口沿各自的块值规则处理。取值子表达式中的普通语句独立检查，例如 children 内 `let x = if true { text("标题"); 1 } else { 0 };` 仍报告丢弃。

检查沿外部声明身份识别导入、重导出和不可变简单绑定别名；作者函数、可变函数值、动态成员和索引调用按现有动态合同执行。可选组件可显式返回 null，普通副作用调用可作为语句。

```aside
fn panel(title, children = []) {
    column(gap: 12) {
        text(title);
        for child in children { child; }
    }
}
let view = panel("声音") {
    slider(value: bind(settings.music), min: 0, max: 1);
    text(value: derive(|| f"音量：{settings.music}"));
};
```

children/构造不得外部等待，BudgetYield 时临时构造帧可保存。Node 返回时未挂载，单父和事务挂载由宿主验证。

bind(model.volume) 是编译器识别的可观察属性位置表达式，生成 Read 或 ReadWrite PropertyRef；对象与键只在创建时求值一次，后续固定该位置。宿主注册稳定属性身份、读取、可选写入与版本。尚未纳入 model 的普通 table 字段、临时值和 a+b 不可 bind；Reel model({...}) 与 observable collection 提供业务可观察状态。需要选择另一个位置时重建引用。

派生和组件计算读取另一个派生值时，先完成该来源的待重算，再继续原读取；范围判断和索引可安全组合到多层 derive，条件分支首次读取的新来源也使用当前批次的值。普通同步脚本段仍在结束后统一调度派生。刷新使用同一 VM 任务、native 续体和依赖捕获，取消、故障与中途保存恢复保留原读取位置。派生工作沿任务预算推进，循环依赖报告错误。

宿主属性绑定的执行合同：`bind(node.x)` 与 `bind(node[key])` 固定接收者和键；引用保留该位置的读取及写入权限。节点构造参数或属性赋值接受引用时建立连接，之后写入普通值沿连接写穿。`unbind(bind(node.x))` 断开该位置的连接，返回并保留当前值。连接成环、不可观察位置、失效来源和只读写入均报错。变更先验证受影响属性的完整候选值，再一次提交；校验失败不改变任何值或连接。显式销毁来源时，现有连接冻结最后有效值并断开；已有引用再使用时报告来源已销毁。来源只通过显式退休销毁，普通 GC 保留仍被引用的来源。动画按最终来源取得写入权，重绑定或解绑使依赖旧连接的活动停止。

宿主可将普通数据图包装为可观察状态；数据复制、业务类型与资源排除规则由该宿主声明。Reel 的 model、控件与 Reading 生命周期见[引擎架构](engine-architecture.md#舞台布局与文字)。

derive(|| expression) 创建只读 DerivedBinding，记录实际可观察读取，版本变化后重算并替换条件依赖集合。禁止修改外部对象、可观察状态、启动活动或等待；native 必须 DerivedSafe，传递调用中继续检查。内部临时分配/写入允许，不能把临时引用逃逸成外部可变影响。普通捕获值保持通常共享语义，不因读取自动响应。环报错，替换/销毁解除订阅。移除最后一个属性消费者时，沿派生输入解除无消费者的订阅；重新绑定保留引用会恢复更新，共享消费者不受影响。输入宿主退休导致的冻结不可恢复。可写控件不可接受只读派生，通知/事务提交由宿主负责。
派生结果沿用只读属性引用，可通过 `binding.value` 读取并继续派生。依赖变化合并到同步脚本段结束后的提交点，在下一次舞台发布或业务任务运行前稳定；不在每帧扫描所有绑定。宿主私有载荷更新保留 GC 写屏障，但不通知公开可观察属性；公开属性值的发布才使对应依赖失效。Reel 的连续时钟与对白揭示先完成当前派生批次再发布下一次采样；派生中的服务 getter 读取本批投影，首次创建时初始化。显式作者命令仍立即发布实际变化。首次计算沿原调用栈执行，后续计算保留闭包的源码位置。失败保留上次有效投影并报告脚本故障。
依赖捕获保留来源的强引用与稳定代际身份，按实际容量计入堆预算。提交、取消、回收和快照恢复共同维护依赖图。宿主在发布画面前核对派生及其上游是否有效；依赖图查询、订阅与解除的同步工作量随实际图规模变化。内部遍历与缓存见 [reactive](../crates/aside-vm/src/heap/reactive.rs)。

## 十二 Task Awaitable 与取消

执行器提供普通 Task、宿主 Awaitable、硬撤销和可恢复等待。Reel 使用 completion 和 spawn 组合这些接口。

普通 fn 在当前 Task 的可恢复调用栈执行，可 await；Reel 入口和 UI 回调由带明确 OwnerId 的任务运行。say 等可暂停 native 能挂起普通 helper 链。普通函数返回可等待对象时保留该对象，由调用者显式 await。没有任务上下文或位于受限边界时，动态尝试外部等待报错。

Reel 通过 `spawn(work, owner: null)` 启动零参数脚本工作，返回可 await、可 cancel 的宿主任务；节点所有权和取消遵循引擎的作者活动合同。它复用上述普通调用栈。VM 任务槽按同时活动数量增长并复用，默认没有固定任务数配额；宿主仍可通过 `VmLimits.max_tasks` 显式设限。每次启动逻辑任务都在宿主准入点检查连续执行空间，包括复用已结束槽位和重算派生值。准入沿 FrameSlots 的连续空闲段检查、整理和扩容，保留根身份，旧新缓冲重叠计入堆预算，并遵守宿主的容量上限。

await 接受 Awaitable，不接受普通标量。对不可等待值使用 await 报 NotAwaitable（core code 24），定位 await 并提示普通函数调用已经等待其返回值；不隐式接受标量或将其包装为任务。此诊断复用既有故障与源码栈，不增加分配或改变 Aside 字节码 指令格式。Reel Task、Activity、Completion 和 SaveRequest/LoadRequest/DeleteRequest 本身实现此协议，直接写 await activity 或 await request，不引入额外完成属性。即使已经完成也在下一调度步骤继续；完成一次后按登记顺序交付所有等待者。Fault 在 await 处建立消费者故障：当前 origin/stack 标出 await 调用链，AwaitedFault.source 保留生产者完整故障及原失败位置；活动 Stopped 是普通终态，Cancelled 抛取消错误。Awaitable 注册等待、解除订阅、结果状态与恢复描述必须显式定义，不能只用类型名称宣称可等待。

宿主 Awaitable 实现合同：VM 将可信宿主对象绑定到当前已准入包中的单参数 native（参数为对象本身，类型 any，无缺省或 rest；效果包含 WAIT）。绑定不是脚本可修改的字段。Await 指令检查动态 NoWait/效果边界，然后进入已有 NativeFrame，首次 HostCall 即调度边界；Ready 也不在响应调用内执行脚本。Pending、Continue、CallScript、代际 WaitId、根和取消全部复用普通宿主调用。转发生产者故障时，每次 await 建立独立消费者 envelope，保留原值/错误码，以 AwaitedFault 记录源故障与 activation；catch 原因同时保留。宿主按登记顺序维护订阅，以 wait_is_pending 查询取消/完成后的有效性，解除消费者订阅不能停止共享生产者；任务/owner 撤销后旧完成不得交付。当前宿主包的 native 身份和版本属于恢复描述。

当前宿主任务的 cancel 和 owner 退休为硬终止，停止其任务，不运行这些脚本 finally；宿主幂等释放拥有的订阅、资源和活动。取消不自动撤销已经写入的共享状态。必要资源清理依赖 Owner/ResourceToken；需要等待的 close 必须在 owner 仍有效时显式 await。

宿主一次性结果可按相同 Awaitable 协议实现。其声明须明确生产者的所有者、唯一终态、重复等待和订阅取消规则；等待者取消只解除自己的订阅。

Rust 宿主内部弱登记复用 `Heap::peek_weakref`，在不运行 GC 的事务内检查目标，不给当前标记周期保活；需跨事务持有值时使用 `upgrade_weakref`。属性订阅采用相同窄入口。

## 十三 迭代

`for` 支持 array、tuple、整数区间和生成器。每轮捕获的局部名称建立独立绑定。

`gen fn` 调用时按普通函数规则绑定参数和求值缺省值，返回生成器。第一次推进才执行正文；`yield value` 交付一个值并保留局部状态，下次推进从该处继续，`yield` 表达式的结果为 `null`。返回注解 `-> T` 约束最终返回值，逐项产出的类型由 `yield` 推断。生成器函数的 callable 返回类型为 `generator`。实例方法可以使用 `gen fn`，构造方法 `init` 使用普通 `fn`。

`next()` 返回 `(done, value)`：产出时为 `(false, value)`，结束时交付一次 `(true, 最终返回值)`，以后返回 `(true, null)`。`for` 只消费产出值，结束、`break`、`return` 或异常退出时关闭迭代器。`close()` 返回 `null`，执行已进入的 `finally` 并关闭生成器；尚未开始或已经结束的生成器直接关闭。

生成器恢复期间使用调用方的执行预算、效果和等待权限；正文及其调用链处于 `NoWait`。正在运行的生成器再次推进或关闭时报告 `InvalidState`。逃出正文的异常关闭生成器并在调用处传播。GC 和任务硬取消释放状态；显式关闭沿普通异常清理执行 `finally`。暂停状态、捕获和故障上下文参与同一 GC 与快照系统。

## 十四 异常 退出与资源

try {...} catch error {...} finally {...} 至少含 catch/finally 一个。throw 可以抛脚本值，运行时以 ErrorEnvelope 保存原值、稳定 code、源位置和栈；catch 能读取原值，`std::core::error_info()` 提供故障信息。throw; 只在 catch 中重新抛出当前 envelope，保留原始栈；throw value; 建立本次抛出位置与 cause。

正常结束、return、break/continue 和异常展开穿过 try 时先执行 finally。finally 不得 await、yield、return 或跳出其自身边界；可按预算让出。该词法限制覆盖条件与短路分支；内嵌函数按自己的函数边界分析，实际调用时继承调用者约束。普通 helper 调用可以同步返回，真正进入外部等待时由有效 NoWait 检查处理。finally 再抛出时替代原结果并保留原结果/异常为 cause。异常值、待 return 值及展开位置都是可恢复帧状态。

资源 close/dispose 必须幂等且可检查终态。文件/游标/订阅/native 资源由显式 token 与 owner 管理，GC 不执行用户脚本 finalizer；宿主低层释放同样有预算/队列。脚本清理无法保证硬终止时执行，底层资源释放必须独立保证。临时业务恢复若必须覆盖硬终止，应通过宿主事务/作用域恢复记录实现。原生崩溃和内部一致性破坏不伪装成可恢复脚本异常。

宿主可通过 `finish_host_callback(task, frame, value)` 结束一个仍活动的 native 回调区域。它与取消共用分片帧退休路径，跳过区域内脚本 finally，并在边界交付 CallbackReturned 与原 value；外层任务继续执行。返回值使用该 native frame 的既有结果根，随 GC 和执行快照保留。Reel 的 `scope.finish(value)` 使用此协议交回页面或交互结果。

不可外部等待的边界包括同步宿主重入、缺省参数、模块初始化、构造、派生求值、finally 和 children。静态可知时提前诊断，动态调用继续检查；“不可等待”不等于“不可按预算暂停”，invoke_sync 的特殊硬预算规则见下节。

## 十五 VM 与可恢复宿主调用

标准派生值的无参表达式在准入时证明后，使用一个普通脚本帧执行，并在尾部进入同一宿主提交续体。不可变 tuple 沿普通序列构造协议按预算分步完成。指令、源码位置、依赖读取、取消和快照沿用共同执行协议；完整故障保留逻辑宿主调用帧。复杂表达式与自定义观察者继续通过普通宿主回调执行。

VM 使用显式调用帧、共享代码/常量、驻留符号、可复用参数区及可恢复中间状态。默认 Value 采用 16 字节显式标签与 64 位载荷，int64/float64 完整内联，堆对象通过完整代际句柄访问。Value 为可复制内部值，复制时由当前执行帧或显式宿主根负责保活。表示隐藏在 VM 私有存储接口后，字节码和快照使用各自规定的编码。32/64 位目标分别检查大小、对齐、算术及句柄往返。密集数值数据使用连续类型缓冲，避免每个元素支付动态 Value 标签成本。

run_slice 接收指令、分配和时钟检查额度，返回 Returned、BudgetYield、HostCall、Waiting、Fault 或 ResourceBlocked。ResourceBlocked 表示建立完整故障记录所需的硬容量不足，其保留、恢复与取消规则见第二十三节。BudgetYield 不改变语言结果；全部临时根和继续位置都在 VM 状态中。HostCall 携带稳定函数符号、签名版本、TaskId、OwnerId、源位置和借用实参视图。宿主响应 HostCallResult 为 Ready(value)、Pending(wait_descriptor)、CallScript{callee,args,continuation}、Continue{continuation} 、Error(NewFault) 或 ForwardFault(fault_id)。Error 创建本次故障；ForwardFault 传播已保留的完整故障，具体契约见第二十三节。

Pending 必须先退出 native 调用栈，再保存操作描述、等待身份、返回槽和后继 PC。完成结果只恢复操作的后继阶段，不能重跑已经生效的调用。native 异步算法用分块状态机或后台拥有数据任务，不把 Rust Future/栈地址当持久续体。

CallScript 允许 native 算法调用可暂停脚本：宿主退出 Rust 栈，将版本化 continuation 作为显式 native frame 保存，VM 在同一 Task、同一 owner 和效果上下文压入 callback frame。脚本返回或抛出后，恢复该 continuation 并交付 ScriptExit::Returned/Fault；continuation 可继续返回 Ready/Pending/CallScript/Continue/Error/ForwardFault。callee 的模块版本、实参、算法阶段、临时对象与返回目的均可追踪和快照，原 native 入口不被重复执行。callback 的 Pending 由整条任务栈自然挂起，不需要新建无关任务。

Continue 保存版本化 native 算法状态，在同一 Task 下一预算片继续执行，无 WaitId、无外部等待，也不重新执行入口。它覆盖编码、hash、复制等无需脚本回调的分块算法，在允许 BudgetYield 的受限上下文同样适用。native frame 的临时根和游标进入快照。

CallScript 不提升权限或取消已有受限上下文；sort 的同步 comparator 仍不能等待，受限 derive 仍不能写外部状态。需要普通可暂停 callback 的宿主操作在签名中明确声明。native frame 的取消/释放由宿主 adapter 幂等完成；脚本 fault 未被 continuation 处理则按原调用链传播。continuation 按当前包和快照的 v1 schema 验证。

native continuation 的回调取消屏障由所属 TaskId 与原生 FrameId 标识；宿主取消后按预算释放内层执行帧，以 CallbackCancelled 恢复原续体，外层任务及其异常处理保留。VM 快照保存未完成的清理边界。Reel 可附加 owner 条件，不改变 Task 的主 owner。Reel scope(owner: node, body: callback) 通过它执行：节点先结束时只撤销该 region，取消其等待并丢弃到屏障为止的 callback 帧，内层脚本 catch/finally 不可阻止撤销；native adapter 幂等清理本区域资源后，在屏障外的原调用位置交付 ScopeCancelled，仍存活 Task 可继续。整个 Task 主 owner 撤销则按硬终止规则结束全部区域。区域层次、取消条件、临时资源及屏障 frame 一同保存；Task 主 owner 保持不变；执行上下文的默认资源 owner 为最内层活动 scope，否则为主 owner。spawn 启动的子任务和未指定 owner 的活动使用该默认资源 owner，显式 owner 表示明确转交生存范围。

invoke_sync 仅用于不可保留 native 栈的有界同步重入。它继承最外层同步调用的剩余指令/分配额度与截止时间，嵌套只可收紧并累计扣减，最终返回 Returned、Error 或明确的同步控制失败；完整调用在本次同步边界内结束。预算耗尽终止本次嵌套调用，向 native 返回 NonResumableBudgetExceeded，脚本 catch/finally 不可截获或延长此退出；已经发生的副作用不自动回滚。所有调用此路径的 native 必须能处理失败并释放借用。可变长度或可暂停回调使用 CallScript，不能循环 invoke_sync 绕过累计预算。

## 十六 宿主 ABI 能力与标准库

宿主可将一个已准入 native callable 的首参数绑定为接收者，产生普通可调用值。绑定值保留代码版本、模块和接收者身份，受既有 GC 跟踪；保存方法后调用仍使用原接收者。调用直接进入 NativeFrame，首参数预绑定，余下位置/具名/默认参数使用同一个 VM binder，显式重复指定首参数仍报重复绑定。脚本调用、宿主 start_closure 和 CallScript 回调使用相同协议，不建立合成脚本调用栈；诊断定位真实调用者。绑定不改变效果或等待许可，不保存 Rust 对象地址。

native 注册表包含稳定符号/版本、参数与命名调用描述、类型/返回值、允许效果、能力要求、Owner 规则、错误码和恢复 adapter。

可信链接包使用本次编译请求的 content_version；宿主 ABI 版本独立保持注册版本。一个调用同时匹配导入符号和名称使用节点时，各链接仍分别核对分析身份与签名；全部指向同一 NativeId 才视为同一注册，指向不同 NativeId 时给出 LinkContract，不能按匹配顺序选择。

宿主可为既有字段启用逐字段写入版本；成功的脚本赋值递增对应版本，包含同值写入，失败赋值保留版本。追踪数组由 GC 管理并计入堆预算，宿主内部发布与脚本写入分别标识。

宿主注册的字段和方法共享类型、默认值、读写权限与效果元数据。普通参数和动态 table 展开使用同一绑定器，未知参数、重复参数和类型冲突在调用处报告。

借用 Value/字节视图只能在当前 native 调用中使用；保留对象须申请代际 root handle，跨线程只传拥有数据、ID 或真正不可变缓冲。Rust panic 的处理范围限于 Rust 侧；native 实现违反接口约定时按扩展故障处理。能力检查在操作前完成，InitSafe/DerivedSafe 限制传递到 callback，注册标签不豁免效果检查。

每种可达资源声明 Serializable、Rebuildable、InterruptedOnRestore 或 Unsupported，并提供版本化状态/恢复/取消契约。Unsupported 引发带引用路径的保存失败，不能静默丢弃。设备、窗口和 GPU 句柄按描述重建；native 符号按版本重连，不能仅按相同名字替换旧 continuation。

标准库由独立的 aside-std 注册，提供数值、曲线、随机数、时间和故障查询。内置容器与文本方法由 VM 的统一声明提供。模块、类型与实际导出见[标准库源码](../crates/aside-std/src/lib.rs)，宿主根据作品需要安装对应能力。

可信宿主可用 `Vm::bind_callable(object, function)` 为 host 对象登记已准入 native 的调用入口。首个必需参数绑定对象自身；普通参数、默认值、具名/展开、效果权限和暂停继续走同一 native 调用准备，不递归执行脚本。登记不在公开字段中，脚本不能覆盖；对象字段和载荷继续按常规 GC 追踪。

标准库模块 `std::time` 使用普通 native 调用提供 now、parts 和 format。时间戳为 UTC Unix 秒 int，日期字段是普通 table，格式化结果为 string；时区名称为 string/null。调用声明 HOST 效果，parts/format 另声明 ALLOCATE；不会把现实时间读取放入纯 derive 或创建隐式刷新任务。具体接口见 [time](../crates/aside-std/src/time.rs) 的声明文档。

## 十七 预算 回收与分块算法

指令之外，还统计容器元素、比较/hash 工作、复制字节、回收边和分配字节。每 256 个工作单位检查让出条件为起始配置，实际目标由尾延迟测量调整。native 原语必须有界；长字符串、Unicode、tuple 相等/hash、模式、排序、数据解析与复制均使用可恢复 continuation 或严格输入界限，其工作量与分配计入调用预算。

字符串总长度不受单次复制额度限制。字节码常量按存储分块装入，字符串加法使用保留在执行帧中的构造状态，按工作与分配额度逐块复制；预算耗尽只让出，不把长文字变成资源错误。结果完成后一次发布为不可变 string，中间缓冲保持为根，异常或取消沿现有帧清理回收。每个块和临时缓冲仍计入真实堆预算；宿主单次读写的分块大小不成为文字总长上限。

分块操作必须规定中间状态可见性。sort 使用工作副本，记录来源的完整内容版本；comparator 或其他任务在准备期间修改来源任何位置，提交时报 ConcurrentModification 并保留当前来源，不覆盖并发写入。比较器须提供稳定一致顺序；运行时可诊断检测到的违约，但不会以任意脚本比较器为由破坏容器或内存安全。成功后一次提交排序，失败不写回副本。BudgetYield 时其他任务可运行，算法副本、游标、版本和 callback 状态进入根和快照；绝不重新执行已发生 callback 来恢复。对需要原子结果的其他操作采用同样的准备/提交模式。

对象身份复用固定版本 slotmap 1.1.1，使用独立 HeapKey 类型与完整 64 位不透明键；身份表只保存实体位置及槽位代数。对象实体紧凑分页保存，清扫移除至多移动一个实体并释放一个空尾页，位置更新不改变任何 Value 或根句柄；不会为每个对象单独分配 Box。身份表保留失效键所需的代数，实体页按存活对象释放。句柄只在所属堆内有效，宿主长期保留的对象登记 root handle，并携带 HeapId/SessionEpoch。快照使用独立对象编号，恢复时重新分配句柄。普通传递遵循 KeyData 的完整 u64 往返契约。

宿主可在一次堆共享借用中复用表读取视图，摊销连续字段读取的身份与种类检查。视图按原条目顺序读取分块存储，保留属性提案和边界错误语义；生命周期由堆借用约束。

脚本对象图采用单线程、稳定整数句柄的增量三色标记清扫。Value 复制和堆内强边由追踪管理，省去逐次引用计数。slotmap 提供槽位复用和代数验证；Aside 实现实体分页、根扫描、边遍历游标、写屏障、弱引用处理与清扫状态机。GC 的边与载荷字节预算不变，每次实体移除有界地移动一个对象并释放至多一个 32 对象页；GC 队列在对象准入前按存活需求预留。gc-arena 用作成熟算法参照，其 Gc 字段接口与整数句柄图不同。

外部根包括活任务 frame、活动会话、当前发布 ModuleSet 环境、待交付结果、native continuation 与宿主 root handle；分块算法的工作副本及 callback 状态同样属于根。对象字段、cell、集合元素和闭包捕获为堆内强边。旧模块缓存为弱索引；分配表及 GC 工作队列只作管理记录。不可变代码或资源可独立使用 Rust Rc/Arc，其计数与脚本对象图的可达性分开。

ModuleSet 的常量、符号、native 值和全局根在包加载时按实际数量预留，不套用单次执行窗口的长度额度。VmLimits.slots 声明执行工作集，模块根容量在加载时加入同一根池；执行帧和 continuation 仍使用操作窗口额度。两类根共用 GC 扫描和堆总内存计账，模块大小不挤占配置的执行工作集。

默认 HeapLimits 不设固定字节总额（max_bytes 为 u64::MAX）；宿主需要隔离预算时可显式设置。内存用量和峰值照常记录，真实分配失败仍报告错误。执行切片的工作和分配预算决定让出时机，内容容量由堆与资源额度决定。

对象身份表、宿主根与根区间描述符按需求几何增长，默认数量额度为代际句柄的可表示上限；配置的最大数量不作为启动预分配量。对象准入前按存活需求准备 GC、释放及响应式队列容量，写屏障和回收步骤不分配；根区间增长同步扩展 FrameSlots 映射，保持既有 token 和扫描游标。增长的新旧存储重叠计入峰值，失败不发布对象或根，已申请的可复用容量继续计账。宿主可显式收紧数量和字节额度。

GC 步在 VM 安全点执行。标记期间采用强边插入屏障：每次强边写入和根发布，在新值可见前把目标纳入标记；新对象的初始强边及 weakref 升级使用同一入口。根扫描有持久游标，已扫描根的更新也经过屏障。大型容器保存边游标；插入、删除或重排若移动尚未扫描的边，须修正游标或补充标记这些边。全部根、灰队列与屏障工作完成后，在同一安全点进入弱引用判定和清扫。自开始弱引用判定直到本轮清扫结束，weakref 仅可升级本轮已确认存活或本轮新分配的对象；这一阶段切换是统一的存活判定截止点，代际有效本身不足以允许升级。新分配对象标为本轮存活，并纳入下一轮扫描。

宿主自动回收按分配压力启动，不因执行了一个脚本切片就重新扫描活堆。堆累计新对象数与载荷分配字节，以最近完成回收后的存活规模确定下一轮阈值：默认对象阈值取 256 与存活对象数一半中的较大值，默认载荷阈值取 64 KiB 与存活载荷一半中的较大值；任一达到即请求回收。显式额度还按当前余量提前触发：对象阈值不超过剩余槽数的一半及剩余字节可容纳对象实体数的一半，载荷阈值不超过剩余字节的一半，最少为 1。这样无载荷的小对象也不会在实体页占满字节额度后才尝试回收。开始一轮时消费已有分配债，进行中的新分配继续累计，完成时不抹除。清空非空集合请求后续一轮回收，进行中的请求保留到下一轮，确保已经标记的旧图仍有回收机会。显式 begin_collection 和资源阻塞回收不受自动阈值限制。查询与请求为常数工作，实际回收继续使用原有根提供者、工作/字节预算和增量释放，不增加脚本参数或快照状态。

根、边、弱引用和清扫均按独立工作额度推进。清扫使用有界分配键队列，每轮记录待处理数量，分片检查并重新排入存活对象；本轮新增对象留给后续轮次，队列记录与对象身份对应，避免重复释放。对象先在逻辑上失效，再分片释放 payload；大型容器拆分释放，缓冲分配/释放记录最大不可分割耗时。标记队列、游标、待释放字节及退休槽位全部计入堆预算。标记入队容量不足时先维护或返回资源错误，保持屏障完整性。设备资源按 Owner 显式撤销，GC 仅处理底层拥有数据的释放；回收时刻与业务确定性分开。

slotmap 的完整版本仍有回绕边界。封装删除时，在完整代数耗尽的槽位保留 Retired 记录，访问拒绝该状态，批量清理保留退休槽位。固定版本的满幅退休阈值为占用版本 0xffffffff，即同一槽位最多 2^31 次生命周期。版本字段识别属于依赖适配代码，升级时核对源码与专项用例；普通句柄保持完整往返。退休槽位计入容量而非活对象数量。

## 十八 快照 恢复与版本

Reel 的原生 page_stack 保留页面节点及 key 身份，工厂与构造中的继续执行使用普通 Task、CallScript、GC 根和快照协议。ensure 的等待者共享生产结果，消费者退出等待不取消组件拥有的生产；组件退休按 owner 取消。tab_bar 的内容工厂处于无外部等待边界，允许正常的预算让出。选择与页面状态使用公共舞台绑定，组件不维护另一套脚本解释器。

当前 VM 快照格式为 1，使用独立于 Aside 字节码的带版本记录流；对象、根区间、帧和 payload 块分别记录，引用保留完整代际键并在隔离恢复时重新映射。捕获器借用被冻结的 VM，按工作额度推进；只遍历强可达图，弱边不参与追踪。标量记录使用 pinned Serde/Postcard 编码，长值按既有堆块拆分；后台接收无运行时句柄的字节记录。不持久化分配器容量、空槽或 GC 扫描状态。恢复重新走堆和帧存储的计账入口；宿主验证函数由版本化注册名重接，不记录地址。

已验证字节码通过不可变共享所有权复用于读档候选，无需复制或再次验证整个代码包；每个 VM 仍按完整代码成本执行自身配额检查。VM 保存完整可恢复执行状态和对象图，宿主协调请求、舞台/资源屏障及原子磁盘提交。snapshot_begin 在安全点固定根和逻辑状态，snapshot_step 按对象/边/字节预算复制到独立区；业务写入暂停，后台结果排队，长字符串/缓冲/容器也分块。绑定派生与写回在捕获中暂停，非持久原生控件反馈可继续。

当前快照包括代码/模块/native ABI 版本，全部 Task 的 PC、接收者、返回槽、异常处理/展开、寄存器和中间值，native continuation、CellId、模块环境、对象共享/环/弱边，宿主 Awaitable 的结算/等待队列、取消和待交付结果，tuple 内部引用、缓冲有效内容、集合顺序/结构版本/游标和 schema。绑定保存属性身份与派生闭包，不保存临时通知队列。真正不可变代码/文本/资源可共享，cell、活动属性和可变缓冲必须独立记录。

弱引用只在目标经强路径已进入快照时保存目标关系，否则恢复为已失效；不能因序列化弱边而把目标变强。IdentityMap 保留强键关系与恢复后的对象身份，不按旧原生地址重建。

缺少 native adapter、代码版本或 ABI 时报告精确对象路径/版本并使保存或恢复失败。restore 在隔离堆先分配身份，再连接引用、等待、订阅和 native 描述，完整验证后一次公开；失败保留当前会话。禁止以新代码 PC 猜测旧恢复点。SessionEpoch 在新游戏/加载/回滚更新，TaskId、WaitId 与 native 完成消息匹配 epoch 后至多交付一次，旧结果丢弃。

捕获与恢复提交互斥。发行存档使用匹配游戏包代码；开发存档嵌入无法由固定包取得的全部被引用版本。旧代码/模块/native/源码映射版本在最后强版本引用离开后释放；持有者包括帧、闭包、快照、故障栈/原因节点、FaultInfo/FaultRoot 和进行中的 FaultBuild。恢复要求代码版本匹配。

进程服务请求按 adapter 处理：仅当前正在持久提交的 SaveRequest，在该独立存档副本中记成功，活会话仍等待真实写盘，内存回滚快照不做此归一化。已结算请求恢复既有终态。其他未结算外部写请求只在精确进程/请求身份及完成记录匹配时重接，否则以 OperationInterrupted 结算；始终不盲目重放外部写入。

字节码文本存储：发布宿主可把 Utf8 常量外置为 Text{offset,len}，包内 TextPoolDescriptor 保存共享 UTF-8 池长度与摘要。验证器静态检查描述与范围；宿主通过 VerifiedProgram::bind_text_pool 绑定正文后才允许 VM 加载。Aside 不承担文件或资源包 IO。内嵌与外置字符串均在 LoadConst 时创建共享视图，弱常量句柄只复用仍存活对象；未使用正文不分配 GC 字符串对象。tuple 常量构造可按执行预算让出，保持值相等语义，不暴露对象身份。存档中的常量引用恢复到同一程序正文，动态字符串保存实际内容。字节码和快照使用当前 v1 格式，加载时验证格式与代码身份。

作者编译与 ASB/Aside 字节码 加载默认仅受格式索引宽度、可寻址内存与实际分配结果约束，不以预设作品字节数、累计记录数、模块数或指令数截断正常作品。Rust 宿主仍可显式设置各阶段 Limits 配额；解码长度、索引、结构与整数溢出检查保留。递归深度及诊断条数继续限制递归实现的栈与错误恢复，不冒充作品容量。

## 十九 编译包 构建与工具

Rust 扩展接入合同见 [Aside host SDK](aside-host.md)。共享宿主声明是编译签名、Aside 字节码默认参数与运行时准入的单一来源；绑定宏只生成声明及 Rust 调用包装，复用语言的参数绑定、NativeFrame、等待和 GC 协议。Aside 不依赖 Reel。

Rust 扩展现可声明可变参数：`#[aside(rest)]` 对应普通 array rest，接收剩余位置实参，支持位置展开。每次调用有独立的外层数组，元素按正常值语义共享；没有剩余参数时仍得到新空数组。rest 必须是最后一个脚本参数，不带默认值，也不能按 rest 名称传入。固定参数的具名/默认值、绑定接收者、函数值、宿主入口和 CallScript 共用原有绑定器；包装不复制参数到 Rust 集合。NativeContract.rest 在源码链接与运行时准入使用同一名称及 Array 类型，包声明不一致则拒绝加载。

编译器输出版本化模块包：语言/包/宿主 ABI 版本、导入导出、签名、指令、常量、源码映射、能力与元数据。磁盘数字宽度、端序和编码固定，加载内存布局可不同。执行前验证解码、索引/寄存器/跳转、声明额度、native 符号及能力；恶意包不可导致越界、无界解码或巨量预分配。

源码、字符串常量与符号按整体包预算准入。源码位置与各字符串长度仍须可由既有 u32 表示，编译和 Aside 字节码/ASB 编解码继续执行各自的整体内存、字节与工作预算。Aside 字节码默认工作预算由整体字节预算的两倍推导，覆盖完整包的预扫描与物化两遍读取；两遍工作累计计费，调用者仍可显式配置预算。源码路径及内容在 check/build/dev/run 中使用相同规则保留。

源码的平坦运算与后缀访问链按顺序处理。投影、分析和 lowering 使用显式链工作表，保留从左到右求值、短路、接收者一次求值、children 收集和源码位置。真正递归的括号、块与子表达式仍使用既有编译资源预算，默认深度为 128，宿主可显式配置深度预算；该深度衡量编译器嵌套语法，不等于画面节点层数。lowering 分开节点调度与具体操作，错误以 Box<Error> 返回，保留完整源码位置与预算统计，仅失败时分配错误载体。不能让无关分支的巨大局部栈帧使正常嵌套组件在默认主线程栈上崩溃。不可变语法树由独立的 aside-syntax crate 持有，最后引用通过原子操作认领后迭代释放子树，长链不依赖宿主调用栈析构。

reel-engine 直接依赖 aside-compiler；发布工具也接受已编译 ASB。编译功能由各 crate 的 Cargo features 决定。缓存按源码、依赖版本、语言和编译选项失效；成员和调用缓存同时核对布局或签名版本。

现有工具提供 check/build/run/export、格式化、源码诊断、类型与参数提示、补全和定义跳转。native 声明、文档、编辑器提示和 ABI 校验由同一注册元数据生成。

成员的源码声明身份供类型查询与定义跳转使用；普通对象成员仍通过成员访问及接收者绑定执行。命名空间导出与原生函数引用才参与静态链接。

静态成员访问使用接收者的已知成员合同：数组、tuple、字符串、完整声明的类和宿主类型访问不存在的成员时，在成员名处报告诊断。table、any、动态索引及成员合同未知的类型继续在运行时解析；普通记录的字段推断用于编辑提示，记录仍可添加字段。

`aside-lsp` 通过标准输入输出提供语言服务，复用编译器的无损语法树、符号身份、类型和模块解析。打开文档的内容覆盖磁盘版本；源码使用 UTF-8，编辑器位置按协议协商转换，诊断带文档版本。作用域补全、悬停、定义跳转和参数提示共享一次分析结果。项目宿主注入自己的默认环境与接口说明，Aside 后端保持独立。内置接口的定义视图从 Rust 声明生成，包含英文文档、具名参数、类型、默认值及属性读写权限；定义视图供阅读和导航，运行时仍调用原宿主实现。声明中的 `name?: type` 表示可省略且没有替代默认值的原生参数；显式传入的值仍须符合所列类型。

编辑器语义着色沿同一分析结果区分变量、参数、函数、类型、命名空间和成员，以 LSP 的标准 token 类型及修饰符返回全文名称范围；颜色由编辑器主题决定。悬停与导航定位到实际名称，导入名称使用其声明身份、类型和文档。补全包含当前语法位置适用的关键字，未完成的声明也能查询；成员位置提供接收者成员，字符串正文与注释保持各自的编辑上下文。

导入路径的模块前缀支持悬停与定义跳转：宿主模块打开同源生成声明，源码模块打开实际文件，目录前缀打开由当前一级模块发现结果生成的可导航只读索引；空白及未完成 use 的补全使用同一路径发现。

格式化由 aside-compiler 的同一无损语法树打印器提供：`format(&str)` 解析后格式化，`format_parsed(&Parse)` 复用现有解析结果。语法有效即可格式化，名称和宿主解析独立进行；语法错误返回原诊断。排版使用 4 个空格缩进、100 字符目标行宽，短调用保留一行，长调用在续行紧凑排列参数，长成员调用链按操作分行。代码块与 children 块按语法结构缩进；换行保留语句和 postfix 的解析关系。字符串、数字、注释内容及非空白词元的顺序保持原样，文档注释仍归属原声明。输出使用 LF，非空文件以一个 LF 结束，纯空白文件输出空串。连续格式化得到相同文本。

诊断含稳定 code、严重性、模块版本、主/相关源码范围、调用栈及可选修复。保留 UTF-8 字节范围与展示行列，中文不能错位；动态调用标出签名/实参，await/native continuation 标出等待点与原失败点。提供人读和结构化输出，不向作者泄露内部地址或 Rust panic。覆盖名称/类型/参数/模式、只读写、受限等待/效果、无效句柄、资源额度、代码/恢复缺失及坏包错误。

## 二十二 字节码与执行器的实现合同

公共格式位于 [aside-vm::bytecode](../crates/aside-vm/src/bytecode/FORMAT.md)，包含程序数据、验证和反汇编；aside-compiler 单向依赖它，格式模块不引用 Rowan、parser 或 Reel。下列合同规定编译结果与执行器的共同约束。

程序与验证
BytecodePackage 保存格式/语言/宿主 ABI 版本、内容版本、符号、常量、模块、函数、能力和源码映射。ModuleDef 包含规范化路径、固定导入/导出、全局绑定与初始化入口；FunctionDef 包含 Plain/Async/Generator/Native 类别、统一 Signature、捕获布局、寄存器数、代码和异常/清理区域。Generator 使用延迟正文和 Yield；Async 编码保留，lowering 与执行准入尚未接通。Signature 保存参数名称/顺序/类型/可变性、缺省、rest、返回契约和效果。ParameterDefault 区分 Constant(ConstId) 与 Function(FunctionId)：字面常量直接引用常量池，表达式入口继承被调用闭包的定义处词法捕获和 ModuleInstance，并接收前序参数。仅省略实参时求缺省值；捕获分析包含缺省表达式，数组和表构造保持逐次执行。
脚本和 native 共用常量物化及参数类型检查。常量缺省复用不可变值，聚合常量的分片构造、临时根、取消与恢复沿普通常量加载协议；常量缺省不建立函数帧或前序参数副本。
每次调用按参数顺序建立本次独立绑定，前序参数在后续缺省表达式开始前完成初始化。缺省表达式对前序参数的读写、其中产生的闭包与函数正文共享同一个词法绑定。需要共享可变身份的参数在这一步建立 Cell，正文入口复用它；捕获分析和 lowering 同时考虑缺省中的读写与闭包。已经初始化且身份无关的只读前缀可按值传递。全部调用实参仍先按源码顺序求值，再开始参数绑定。

缺省函数由参数描述中的 default 入口选择。编译器为表达式/块尾结果生成的 Return 结束该缺省入口；源码中的显式 return 继续受缺省词法边界约束。只有 VM 内部的缺省前缀调用路径可以传递前序参数 Cell 身份；普通 CallTarget/Arguments 始终传递作者值并建立新的调用绑定。同一个缺省 FunctionDef 作为普通函数调用时也遵守普通规则。验证器允许 Parameter(i) 使用 Value(Reg(i)) 或 Cell(Reg(i))，并逐对核对被调用函数与其缺省入口的前缀名称、类型、可变性、存储布局及捕获布局。内部前缀路径验证真实 Cell 的初始化、内容和契约，Cell 句柄保持内部表示。缺省入口与正文共享的是本次调用绑定，定义处捕获仍来自被调用闭包的词法环境。
脚本和 native 统一要求：出现在任何后续缺省前缀中的可变参数使用 Cell。NativeDef 复用现有 Signature；验证器按最后一个 Function 缺省入口的前缀推导规范布局，核对其余缺省入口的一致性。只读前缀可为 Value 或 Cell，所有相关入口采用同一选择；完全不属于缺省前缀的参数保持 Value。VerifiedProgram 以共享签名的紧凑只读布局保存结果，构建/核对先计工作量，持有容量进入包账本。每次调用读取这份结果，避免重新扫描全部缺省入口。native 缺省入口保持无脚本词法捕获的现有约束，前序参数的共享绑定通过内部前缀路径传递。

native 使用同一个顺序准备规则。只有全部缺省与类型检查成功后才公开 native Entry。共享 Cell 环境与宿主实参数组分开：ticket 对外暴露已经绑定的作者值，隐藏 Cell 句柄留在内部；CallScript 等后续阶段使相关 Cell 变化时，发布恢复 ticket 前重新投影连续实参视图。原始 native 入口只调用一次。无缺省的 native 保持 Value 快路径，避免为此功能分配额外 Cell 或环境窗口。

参数准备的 Cell 建立、类型检查、前缀转交、缺省结果写回与正文进入均有明确阶段；先发布目标根再清来源，预算暂停与 GC 保持身份。准备失败从原调用点传播，函数正文的 handler 此时尚未进入。逐阶段操作按工作与分配额度计费。
Const 使用完整 int64、float64 位编码、UTF-8、Bytes 与规定的不可变结构。磁盘格式使用小端整数和 u32 索引；PC 表示指令序号。指令编码为 u8 opcode 和已声明操作数的最短无符号 LEB128，操作数范围为 u32。解码后的执行指令为 16 字节，包含 u16 opcode、零值 flags 和三个 u32 操作数；复杂操作引用有类型的描述表。常量/符号/函数/模块/寄存器/PC 分别使用不同索引类型。编码器逐字段写入，运行时 Value、HeapId、root token 和 Rust 内存布局不进入包。
执行器只接收字段私有的 VerifiedProgram。解码/验证先核对长度与总量限制再分配，检查所有索引、窗口、跳转、捕获、签名/缺省入口、异常与清理区域、控制流及 native 版本/能力。未知 opcode 或缺少所需能力给出定位错误；动态类型、初始化状态、只读写和效果仍在运行时检查。包加载和不可变代码另有容量账本。
指令规格表统一规定操作数、读写寄存器、分支、可抛错/可暂停与描述表引用，并由 encoder、decoder、verifier、disassembler 和 dispatcher 共同引用。指令族覆盖值/绑定、cell/全局、数值与严格 bool 控制流、闭包/调用/返回、集合/类/成员、模式/迭代、异常/finally、yield/await 与任务；children 和属性引用按既定语义降为通用操作及描述。编译器和执行器使用同一份规格，禁止各自猜测编号和操作数含义。

连续帧与可扫描根区
热寄存器保存在 VM 拥有的连续 FrameSlots 窗口，按 base+Reg 访问；它们不进入 BTreeMap 集合，也不按每个寄存器分配对象或 RootToken。帧使用可复用且受容量约束的窗口；语言未初始化状态用独立 bitmap 表示，null 保持普通值含义。

每次脚本/native 入栈与 finally 保存异常值前，按该操作的整组窗口检查当前空闲段。共享池需要整理或增长时，原调用的预算预检同时计入根描述符与索引扩容、窗口映射与空闲表扩容、缓冲初始化、根值搬迁和全部新缓冲分配；预算不足保留原调用位置，让出后重新检查当时的共享池。成功准入发生在参数视图借用和窗口登记之前，随后沿原调用事务发布。默认参数、类初始化、排序比较器与 native 回调使用相同准入。旧新缓冲重叠遵守堆字节额度；宿主容量上限和每窗口上限照常生效。根 token、GC 扫描身份及快照布局保持稳定，取消仍释放该任务已登记的窗口。
Heap 为每个固定长度根区登记带 HeapId/SessionEpoch 和代际 RangeKey 的 RootRangeToken，只保存 owner/kind/长度和游标。每次 GC 步临时借用 VM 的 RootRanges 查询切片，Heap 不保存地址或长期借用。寄存器、实参、native 临时值、异常和交付结果均有根区。长期宿主保留继续使用单值根。
根区先建立全 null 的有效槽位，登记与 provider 映射在对 GC 可见前一起发布，随后逐项经插入屏障发布真实值。结束根区时先注销，再释放窗口。每次覆盖、移动、参数复制和结果交付均先屏障再写入；目标根先发布，来源根后清除。根扫描以描述符槽位、generation 和元素偏移推进，空洞/描述符/单个Value分别计工作量；槽位复用时重置旧游标。物理搬迁仅在安全点更新映射，保持逻辑身份、长度与顺序；短期借用结束后才能搬迁或重入。
仍有效根区缺失 provider 或长度不符是运行时一致性错误，不能按空根跳过。存在外部根区时，原有 gc_step 入口也须接入同一 provider，或明确拒绝缺失 provider 的调用。单值根、全部根区和灰队列处理完才进入统一弱引用截止点。窗口容量、bitmap、帧/续体元数据、描述符、空闲池、退休槽及搬迁双份驻留都计入总字节额度；实际释放后才退账，保留的池容量持续计费。相关接口保持 VM 内部封装，避免绕过屏障直接写槽。

恢复、调用与结果
一个会话的 Vm 共用 Heap、FrameSlots 和模块实例集，并持有有界的 Task 集合。每个 Task 保存自己的执行栈、异常展开、等待、交付、取消和分步操作状态。调度器在同一 Vm 内选择 Task 执行一片；某个 Task 外部等待时，其他 Task 仍能访问相同全局绑定、对象和闭包 cell。宿主 ticket、等待和交付身份包含 TaskId，结束或撤销任务只释放其自身状态。独立会话由独立 Vm 承载，所有任务元数据共用会话预算。
函数声明的 Context 给出该函数的限制；有效上下文累计调用链上的 NoWait、Init、Derived 条件，并收窄允许的 effects。任一调用层具有的限制持续生效，返回后恢复调用者上下文。宿主 ticket 携带完整有效约束，CallScript 和普通调用沿用同一规则。
ScriptFrame 保存 FrameId、固定 CodeRef/ModuleInstanceId、PC、窗口、闭包/接收者、参数绑定阶段、返回目标、效果、owner/region、异常展开与当前操作阶段；NativeFrame 保存版本化续体与其强引用槽。源码错误节点和未解决诊断不进入可执行 lowering。
函数声明的限制与实际调用链的有效限制分别表示。现有公开分析入口生成的声明上下文可由 Ordinary/NoWait/Init/Derived 表达；同时处于 Init 与 Derived 的执行限制由 VM 的累计标志保留，不能因某个声明标签而丢失。未来分析入口若产生新的合法声明组合，先扩展共享格式和所有消费者再开放该入口。
AnalyzedModule 保留分析入口上下文、各函数的种类/声明效果，以及稳定的符号和模块身份。lowering 从这些明确事实生成 FunctionDef Context 与签名；调用链的有效限制由运行时继续累计。导入与命名空间成员解析保留声明所属模块和导出身份，重导出另记其解析来源。宿主链接输入来自同一可信 native 注册元数据，提供稳定符号/版本、ABI、能力、效果和默认实现；语义层保存引用身份，包构建按链接输入核对并生成 NativeDef。缺少或冲突的链接信息给出定位诊断。
run_slice 接收指令、内部工作、分配和时钟额度，返回 Returned、BudgetYield、HostCall、Waiting、Fault 或 ResourceBlocked。ResourceBlocked 表示建立完整故障记录所需的硬容量不足，其保留、恢复与取消规则见第二十三节。长比较、展开、匹配等按明确阶段计费。普通函数使用统一调用绑定规则。
可信宿主注册可为纯 native 声明只读叶计算：只借用当前 Heap 与已绑定实参，返回标量，无分配、外部状态、回调或等待。VM 按声明的工作量计入当前 SliceBudget，参数准备成功后直接进入原 Commit/Release；计算拒绝输入时仍由普通 native 入口生成原错误。含接收者在内最多两个参数、固定绑定和内建类型检查的调用可在完整额度预检后作为一个有界操作直接借用调用者参数并写回结果，省去 NativeFrame；额度不足沿原参数准备阶段让出。只读尝试拒绝时保留原调用路径及其工作额度，允许重做纯计算以生成原错误。成功计算后重新检查截止时间。函数指针来自宿主注册，恢复时重新绑定；ASB 与快照格式沿用现有版本。

宿主注册可通过 `standard_derived_commit` 允许 VM 同步完成标准已存在派生值的提交。该提交沿用原子宿主操作的计费：入口与提交各一单位工作，依赖更新和分配继续服从 Heap 的硬额度；这不是逐边依赖工作量。VM 在操作前预留额度，操作后保存 Commit 或故障状态并检查截止时间，再沿原返回检查和释放阶段继续。注册未启用时保留 CallbackReturned ticket 及宿主重入机会；恢复时重新绑定注册，沿用现有 ASB 与快照版本。

HostCall 在暴露响应 ticket 前已登记状态和参数根。ticket 含调用序号、native 符号/签名版本、任务/owner 和源位置，响应消费一次；参数只通过短生命周期借用访问。Returned/Fault 的数据继续留在 VM 登记的交付根或拥有型宿主根中，直到转移到另一已登记根或拥有型根句柄，或显式放弃结果；领取裸 Value 本身保持原交付根，避免失去保活。
Ready 先发布结果再提交返回槽并进入后继；Pending 保存等待描述和后继阶段；CallScript 先保留 NativeFrame 再在同任务压入 callback；Continue 保存算法阶段在下一片继续；Error 从原调用点展开。发出、等待、提交、完成是可保存的不同阶段，恢复不得重跑已生效 native 入口。快照使用逻辑 ID 和代码版本，恢复时重新分配对象与根区，不序列化运行时 token。
捕获 cell 共用现有 Cell 对象种类。对象保存初始化状态、固定可变性和带代码/模块版本的类型契约。CellNew(binding) 根据绑定描述创建未初始化对象，并将句柄写入指定寄存器；BindInit 在类型检查与屏障后完成一次初始化。CellRead/BindRead 校验初始化，CellWrite/BindWrite 校验已初始化、可变性和类型。普通字段写入也服从这份契约。Cell 模式捕获句柄时保留共享状态，读取发生在函数真正执行时；前向只读捕获也可使用 Cell，确定已初始化的只读捕获可按值保存。null 是合法的已初始化内容。状态与契约随 GC、闭包和快照保留。
模块根声明与初始化入口中的词法局部量采用不同绑定身份。仅真正 Module 上下文的根声明进入 global 表；块、条件、循环和 catch 的局部量属于初始化入口，不能用 owner 为空推导 global。静态 BindingId 标识绑定位置，每次作用域进入用 CellNew 更新该位置的 Cell 句柄：同次进入的闭包共享它，旧闭包保留此前进入的 Cell。入口中的全部 CellNew/Clear 先于任何命名闭包构造；while 条件的 continue 回边经过对应入口，catch 绑定只由其专用入口初始化一次。缺省入口捕获定义处环境，不重新创建定义环境的局部 Cell。

外部 enclosing 词法绑定保留原身份和逐层捕获关系，不得视作当前入口新声明或普通 host 符号。若编译调用未提供实际外部 Value/Cell 链接，lowering 给出定位的 MissingLink，不能以新建未初始化槽伪装接通；既有可信直接 native 链接另循其合同。

绑定描述保存类型、可变性和初始化约束，共享 cell 写入遵守同一契约。Match 的输出仅在匹配成功时初始化。MemberGet 对类方法形成绑定接收者，表中的普通闭包保持普通函数。
调用展开的参数容器为当前调用私有。array 的分片浅捕获从开始至完成检查完整内容版本，包括元素覆盖、增删和重排；变化则以 ConcurrentModification 失败且不调用目标。tuple 外层不可变。捕获完成后，源容器后续修改不使已捕获外层序列失效；内部对象修改仍通过共享引用可见。游标、版本、部分捕获和待释放存储均计入容量与根，失败沿既有异常清理释放；不得把 BudgetYield 当作外部等待或丢失中间状态。

集合展开采用相同的分片浅捕获规则。`[...source]` 接受 array/tuple，`{...source}` 接受 table；null 或其他类型在展开位置报 Type。每个展开在其源码位置捕获完成，再执行后项表达式。表的显式键和值仍全部先求值，再按书写顺序构造并验证键；非法展开源则立即失败。后项覆盖已有键时保留键首次出现的顺序。构造结果在整条表达式完成后才发布，异常或取消释放未完成的容器。Aside 字节码 使用 ArrayPush/ArraySpread 和有序 TableSources 描述符；TableSpread 复制已验证自有槽，空目标直接线性复制，合并到非空目标仅比较目标原有条目，不重复扫描本次已追加的源条目。每片工作及实际分配计入既有预算，不另设集合长度上限。

赋值位置与实参保持源码求值顺序。全部实际参数完成求值后才按签名绑定；有序参数容器保留重复名称，最终绑定阶段报告冲突。无展开普通调用使用连续参数窗口；展开在其源码位置捕获元素，随后参数的副作用不能反向改变先前展开。可变捕获使用共享 cell，每轮循环的绑定独立；不会保存可移动窗口的地址作为 upvalue。

异常区域与清理
保护区、catch 和 finally 的普通控制流边均由验证器核对。Jump、Branch 与自然落空进入 handler 的包会被拒绝；正常离开保护区或 catch 使用 Leave，return/throw 由统一展开器执行清理。catch 内抛出的新异常交给外层处理器，finally 内的新异常继续向外展开；每个 EndFinally 与当前活动展开记录匹配。清理中的普通调用继承禁止等待上下文。

## 二十三 完整故障记录与生命周期

本节规定完整故障记录、传播与恢复合同。

### 作者可见的行为

catch 绑定原抛值。字符串、整数、null 和对象都保持原有值语义；对象继续指向原对象。throw; 在当前函数词法上最内层活动 catch 中重抛同一故障，保留身份、错误码、原位置和原始调用栈。throw value; 创建新的故障，即使 value 与先前抛值相同，也有新的位置和调用栈。

`std::core::error_info()` 返回当前调用链上最近活动 catch 的只读故障视图，无活动 catch 时返回 null。普通 helper 和同任务的 native callback 共享调用链；每个任务独立查询自己的上下文。catch 活动期从处理器入口到离开其范围，进入 finally 后退出。视图字段、调用栈和原因迭代见 [English source documentation](../crates/aside-std/src/core.rs)。

FaultInfo 是同一堆中的可追踪只读视图，保存它即可保留完整故障，普通变量释放后随对象图回收。视图公开 value、code、origin、stack 和带种类的 causes；value 所引用的作者对象仍遵守自身可变性。查询依赖当前执行上下文，声明为诊断读取效果，派生纯计算中给出效果诊断。运行时产生的语言错误使用 core.Error 值，含固定 code、message 和只读 details；作者可以抛任意值。Envelope 的稳定 code 来自版本化注册表，作者表中的同名字段保持普通数据。

宿主通过 `Vm::respond_language_error(ticket, kind, details)` 提供原生接口错误的具体原因；details 在原调用帧中保活，再由普通 FaultBuild 纳入 CoreError，沿用故障的预算、取消和快照路径。没有详情时传 null。CoreError 的字符串插值优先显示字符串 details，否则显示对应错误码的固定 message；不遍历任意对象图，也不调用脚本转换方法。

新故障默认关联同一实际调用链中最近活动 catch 的完整故障。native 显式提供 cause 时以它替代这条隐式 catch 关系；finally 替代退出产生的关系另行保留。跨 Task 的原因通过明确的任务/等待传播记录连接。

### 同一堆中的故障图

ErrorEnvelope、分块调用栈与原因节点使用现有 Heap 的私有对象种类。FaultId 封装完整 HeapHandle；通用字段写入与对象构造入口维护这些内部种类的封装。复制 ID 本身沿用普通句柄的保活规则，访问时核对堆、epoch、代际和对象种类。一个已登记的故障根能够保住原值、调用栈、原因及对应代码版本。

建立完成后，故障身份、原值、code、origin 和原始 stack 固定。原因关系由 VM 追加，已有节点保持原内容；FaultInfo 显示当前已追加的关系。关系具有明确种类：

- CaughtFault：建立新故障时关联的活动 catch。
- ExplicitCause：native 或显式包装关联的原故障。
- AwaitedFault：本次 await 交付关联的生产者完整故障与稳定等待 activation。
- ReplacedExit：finally 真正替代的退出，保存替代位置及 Throw(FaultId)、Return(Value)、Leave(CodeRef, target)。owner/region 的硬撤销遵循任务终止规则。

同一故障可以同时保留 catch 原因与被替代的 Return。原有原因始终保留。每次展开事件具有稳定身份，按预算暂停后继续只追加一次。重抛和显式转发可以形成共享引用或回边；诊断游标记录已访问身份并输出引用关系，GC、快照和诊断均以显式游标遍历。原始栈只捕获一次。失败的 await 为每个实际等待者建立独立 envelope：value/code 来自生产者故障，origin/stack 来自消费者的 await 位置和调用链，AwaitedFault 指向生产者完整故障。生产者记录保持原状，因此多个等待者拥有各自的传播链。稳定等待 activation、交付/FaultBuild 阶段与已建立的包装身份一起保存；生产者故障保留到完整包装根发布，分片或恢复后只建立一次；之后再次 await 使用新的 activation。若 await 位于活动 catch 内，其 catch 原因也按通用规则保留。包装使用同一 FaultBuild 和容量规则。

异常路由使用当前抛出/重抛/调用处的 PC 和已消费区域；原始故障位置用于诊断。finally 内被其内部 catch 处理的错误保持外层 pending exit。错误真正逃出 finally 时，先把完整旧退出发布到原因图，再清除旧展开根。

### native、交付与 catch 根

宿主响应明确区分 Error(NewFault { value, code, cause }) 与 ForwardFault(FaultId)。前者建立新故障；后者传播当前 native 持有的完整故障，从原调用位置展开。原值的位比较仅用于值语义，故障转发由显式身份决定。

NativeFrame 持有有界故障槽，与 continuation values 一起记账、扫描和保存。CallbackFault 先进入这些槽，再释放 callback 帧。Continue 和 Pending 默认保留故障槽；后续任何阶段都可读取它们。再次 CallScript 前，将仍需保留的故障移入明确的续体槽，或显式标记已处理。保留策略使用 Preserve 或 Replace(ids)，空集合表示已处理。Ready 在发布结果后释放剩余故障；Error/ForwardFault 先发布目标故障根，再释放来源。取消按同一分步清理规则释放全部槽。

delivery_value 读取原值时保留原交付。delivery_fault 返回完整视图。take_fault_delivery 将整个 envelope 转移到寿命独立于该 Task 的宿主根，成功后才释放交付和 Task 槽。返回的 FaultRoot 表示拥有的保留关系，必须显式释放。只复制原值的接口使用 copy_delivery_value_to_root，原故障交付保持到显式 discard。统一领取接口也可以返回带 Returned/Fault 标签的拥有型结果。

每个 catch 保留记录包含 FrameId、RegionId 与本次 activation。控制转移先发布重抛、cause 和 pending exit 所需的目标根，再删除实际退出的 catch 记录，最后提交 PC 或帧释放。仍包围目标位置的外层 catch 继续保留。普通 helper 调用维持父帧的活动 catch。作者已复制到变量或闭包的原值由正常对象图保活。容量按同时活动的 catch/展开记录计数，顺序执行独立 catch 可复用空间。

### 捕栈、预算与硬容量

FaultBuild 是 Task 的显式可恢复阶段。它先保留原值、原故障与 pending exit，再分块捕获版本化栈；对应帧在记录完成前继续保留。其他 Task 可以运行。完成后才向 catch、native 或交付公开完整故障。每条栈记录包含固定代码/模块/源码映射版本、函数、PC 和帧类别；记录持有真实的代码版本寿命，局部变量仍由原执行状态负责保活。

栈块、原因节点、游标、代码版本、native 槽、退休空间和释放队列均计入相应容量账本。根和边先经过屏障再发布，来源随后清除。捕栈、原因追加、扫描及释放均按工作额度分步。预算不足返回 BudgetYield 和所需工作量，恢复沿用阶段，已经生效的 throw/native 动作只执行一次。

普通资源错误在能够建立完整记录时成为可捕获的 core.Error。若建立故障本身遇到硬容量限制，返回 ResourceBlocked { task, resource, current, required } 给宿主；这项通知使用 Task 预留的控制状态，保留已有根、帧和构建游标。宿主可以执行回收/释放、在许可范围提高额度后恢复同一阶段，或取消该 Task。required 给出下一步推进所需的已知最低额度。故障尚未完整时维持阻塞状态，所有已产生副作用保持原状态。真实进程级分配失败仍服从平台分配失败策略。

invoke_sync 的累计硬预算规则保持原定义。该路径遇到 ResourceBlocked 时终止本次同步重入，向宿主报告资源失败，并按有界释放流程清理状态；它返回拥有型成功/故障或明确的控制失败，保留已发生的副作用。常规可恢复任务使用 run_slice。

### 故障保存

快照保存完整故障图及共享/回边、code 注册表版本、固定代码/源码映射/native 版本、活动 catch、pending exit 与路由 PC、消费区域和 finally 阶段、FaultBuild 游标、native 故障槽和未领取交付。每次追加的事件身份一并保存。恢复先建立新对象身份再连接图；旧 HeapId、FaultId 和根 token 继续失效。缺失所需版本时给出精确失败位置。

执行器与编译器共用同一字节码模型，已执行普通调用、类与继承、脚本模块、集合、索引/成员、调用展开和 rest。作者的具名 table 展开使用 ArgsSpread。owner 完整撤销由宿主协调，Vm::cancel(owner) 仅取消任务；独立宿主根通过其退休记录确认释放。单根与非任务 RootRange、任务状态及外部资源都完成有界清理后才能退休，细节见架构的 owner 撤销合同。

### 宿主属性的同步验证

宿主对象可以持有静态 HostPropertyValidator 描述符，其中包含稳定名称、版本和纯验证回调。回调接收候选属性图的只读 PropertyRead、接收者 Value、已定位的固定属性索引和新 Value，在现有属性赋值提交前返回结果。验证不进入脚本、不等待、不改堆；失败走原赋值点的语言错误路径，try/catch 可捕获且旧值保持。alloc_host 与 alloc_composable_host 显式传入可选验证器，元数据归对象所有，不建立额外能力注册。私有字段更新使用 set_host_payload 并经过统一 GC 写屏障；退休清除属性表和所有私有强边。宿主对象退休同时断开依赖它的派生计算，冻结最后成功值并清除排队重算；直接访问退休后的宿主对象返回明确的 RetiredHost，并在属性访问或宿主调用原位变为可捕获的 InvalidState；它与损坏、跨堆等无效句柄错误保持区分。

源码定位使用首尾有效语法 token，不把前导空白或注释作为错误位置；实际源码文件路径与逻辑模块身份分别保存。窗口显示源码路径、行列以及脚本抛出的字符串或标量值。

## 宿主接入

宿主通过注册的普通函数、可观察属性和 Awaitable 接入。函数参数、效果、等待权限、属性验证与恢复使用本文的共同协议；平台资源由宿主保存逻辑身份并在恢复时重新建立。

Rust 声明、类型、参数和英文文档通过 [host SDK](aside-host.md) 供编译器、VM 和编辑器共用。Reel 的舞台、对白、媒体和交互合同集中在[引擎架构](engine-architecture.md)，组合用法见[作者指南](guide/zh-CN.md)。
