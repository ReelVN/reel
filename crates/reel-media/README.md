# reel-media: AudioOutput / Kira bridge (contract 1.1)

Issue #10 implementation, integrated with the root workspace on Rust 1.96.0. The audio scope includes this crate, the approved minimal Kira fork in `third_party/kira`, manifest/lock wiring and Rust validation in `tools/reel-dev`. The integration owner maintains both creator guides.

## Review entry points

- `src/contracts.rs`: engine-owned AudioOutput, PcmFill, configuration, ordered channel map, status and clock snapshot types.
- `src/mixer.rs`: private Kira `Backend::setup((rate, signal, Renderer credit), buffer_size)` / `start(Renderer)` bridge. Fill calls the real Renderer through a whole deferred Drop shell, preserving linear `take_fill()`. `KiraMixer::new(format, limits, &service)` requires the host-owned cleanup service.
- `src/maintenance.rs`: `AudioReclaimService::new(ReclaimLimits, WakeSignal)`, status and explicit final-host `drain_and_join()`. It owns two preallocated rtrb queues and one non-RT worker; PCM touches only atomic flags. [Interface and credit proof](RECLAIM-DESIGN.md).
- `src/output.rs`: common lifecycle and callback used by OfflineOutput and CpalOutput. `DrivenOutput::start`, `Shared::enter/close_and_wait/open`, `CallGuard::drop`, and `DrivenOutput::stop` are the ownership review points.
- `src/desktop.rs`: actual `DeviceTrait::build_output_stream`, `StreamTrait::play/pause` calls and native error classification.
- `src/pcm.rs`: prezero, block splitting, finite sample sanitation, explicit mapping and integer saturation.

Kira **0.12.5** uses an approved path fork with default features disabled. Only two upstream production files change; [provenance, licenses and reversible patch](../../third_party/kira/REEL-FORK.md) are retained. Pinned ordinary registry dependencies include CPAL **0.18.1** (optional `cpal-output`, desktop targets, `realtime` promotion attempts), atomic-arena **0.1.2** (unchanged), rtrb **0.4.0**, triple_buffer **9.0.0**, atomic_refcell **0.1.13**, and sync_wrapper **1.0.2**. Realtime scheduling denial is counted and does not discard the mixer. No window, renderer, decoder or DSL dependency is introduced.

## Ownership and native API evidence

1. `configure` requires Stopped and negotiates a real format/layout pair. Mixer channels are always 2. Initialize Kira only after this returns the actual device sample rate.
2. `start` keeps the original PcmFill in its stack while verifying the device, building the native stream and calling native `play()`. The callback references an empty fixed FillSlot and a CLOSED entry gate. FillSlot uses AtomicRefCell<SyncWrapper<Option<PcmFill>>>; SyncWrapper permits only mutable access so PcmFill retains its original Send-only contract. Even a callback during build/play can only write silence. Any synchronous refusal returns the **same Box**, never invoked.
3. After native `play()` returns Ok, start inserts fill once in the control-owned slot, records ownership and opens entry. An asynchronous native error can instead latch FAULT; opening uses compare_exchange so it cannot clear that fault. The accepted fill remains owned until stop, even if never first invoked.
4. Only a successful 0→ACTIVE exchange permits a call. The callback then attempts one AtomicRefCell mutable borrow; it never retries, spins, or waits for that borrow. A conflict is a DeviceContract fault and whole-buffer silence. suspend/stop atomically add CLOSED and wait for ACTIVE to clear. The mutable slot borrow ends before CallGuard releases ACTIVE, when the entire native buffer finishes. This control-side wait is solely the required in-flight fence; the realtime thread never waits for the main thread, acquires a callback Mutex or participates in a command acknowledgement handshake.
5. Successful suspend waits for the active call, pauses the native stream and retains the same closure/Renderer. Kira's logical content position freezes because no Renderer calls occur. Resume verifies device identity, default format and support for the negotiated pair, then plays and reopens the same gate. Failure remains Failed with retained fill, until stop.
6. Stop closes entry, fences the active call and **takes/disposes the fill shell on its caller** before native pause/drop. Kira's shell moves its whole Option<Renderer> with a pre-reserved teardown credit; physical PCM destruction occurs on the service worker. Stopped means supply stopped, while tickets describe asynchronous residency. A pause failure still returns Stopped; native callback retention cannot recover the disposed fill. Native pause/stream Drop/in-flight fencing have no 0.5ms promise. Renderer ownership never relies on native callback destruction; device physical drain is also not guaranteed.
7. Each new native stream gets its own gate/fault latch. Late old-stream errors cannot close a replacement stream or change its epoch. Generic WakeSignal notification runs on a dedicated control notifier (2ms polling of a coalesced atomic flag), not in the realtime callback. Host code must acknowledge WakeSignal before draining as D01 specifies.

Official versioned sources used for the interface audit:

- [Kira Backend](https://docs.rs/crate/kira/0.12.5/source/src/backend.rs), [Renderer](https://docs.rs/crate/kira/0.12.5/source/src/backend/renderer.rs): owned Renderer and the real stereo process entry.
- [Kira resource storage](https://docs.rs/crate/kira/0.12.5/source/src/backend/resources.rs): the local guard checks producer credit **before DrainFilter.next()**; a full unused queue keeps finished Sound in its arena. Main-track play bypasses implicit bulk cleanup. New pure-move `try_take_unused_sound()` is called only after reserving an actual service queue chunk. `reclaim_unused(limit)` reports transferred_sounds; it runs no physical destructors. BudgetedSound delegates to real StaticSound and drops PCM before its ticket. Successful play also moves the original DecodedSound into an owned worker job; no accepted PCM alias can become a last reference on the preempted control caller. Rejection returns the unchanged unaccepted request.
- [CPAL traits](https://docs.rs/crate/cpal/0.18.1/source/src/traits.rs): build consumes a FnMut callback, returns a Stream, and play/pause return Result. There is no generic callback recovery API for a failed build and no public ordered speaker layout API.
- [CPAL ALSA](https://docs.rs/crate/cpal/0.18.1/source/src/host/alsa/mod.rs): `StreamTrait::play` releases its worker latch and can fail on ALSA start/unpause; `pause` can be unsupported or fail; `Stream::drop` wakes and joins the worker.
- [CPAL WASAPI stream](https://docs.rs/crate/cpal/0.18.1/source/src/host/wasapi/stream.rs): `play` **enqueues** PlayStream. Ok proves command acceptance, not that IAudioClient::Start already succeeded. Subsequent native startup failures are accepted-stream faults reported by AudioStatus, as the contract permits. The callback/queue handoff never treats this as synchronous rejection. Drop sends Terminate and joins.
- [CPAL WASAPI device](https://docs.rs/crate/cpal/0.18.1/source/src/host/wasapi/device.rs): generated WAVEFORMATEXTENSIBLE uses `KSAUDIO_SPEAKER_DIRECTOUT`. StreamConfig exposes channel count, rate and buffer size, not an ordered device speaker map. The default adapter therefore negotiates known mono/stereo; a multichannel-only device returns Unsupported. It does **not** infer Windows 7.1 order from the number 8.
- [AtomicRefCell source](https://docs.rs/crate/atomic_refcell/0.1.13/source/src/lib.rs): `AtomicBorrowRefMut::try_new` performs one compare_exchange, returning an error on conflict; no retry or blocking path. [SyncWrapper source](https://docs.rs/crate/sync_wrapper/1.0.2/source/src/lib.rs): Sync is sound without requiring the contained value to be Sync because access requires exclusive `&mut self`. Together they support the exact `FnMut + Send` contract without a callback Mutex or custom unsafe code.
- [CPAL CoreAudio lifecycle](https://docs.rs/crate/cpal/0.18.1/source/src/host/coreaudio/macos/mod.rs): native start/stop and an Arc<Mutex<StreamInner>> lifetime shared with device monitors. This is why outer Stream destruction alone is insufficient as a proof of synchronous fill disposal. The control-owned slot addresses it without changing the public contract. macOS source was audited but not built or run in this environment.

The explicit offline Surround71 order is FL, FR, Center, LFE, BackLeft, BackRight, SideLeft, SideRight. Only FL/FR receive L/R. This is a declared test layout, not a claim about an actual Windows device. Unknown hardware layouts require additional native layout discovery or known-layout renegotiation. The existing contract is preserved.

## PCM, timing and bounds

Each fill receives 1..=max_pull_frames complete, interleaved stereo frames. Each chunk is cleared first. Larger native buffers are split without growing the scratch buffer. Bad native length or sample type yields whole-buffer silence, DeviceContract failure and an invalidated epoch. Nonfinite L/R become zero; mono uses 0.5L+0.5R, other known channels remain silent. Integer output clamps; unsigned silence is 32768. Supported types are f32, f64, i16, u16 and i32; unsupported native types are excluded during negotiation.

Default pull bound: 512 frames (10.667ms at 48kHz); maximum 4096. Conversion scratch is 2×max_pull_frames×4 bytes (4096 by default); native buffers stay borrowed. Kira's three default 128-frame buffers total 3072 bytes plus fixed metadata. Sound capacity N defaults to 64, maximum 256; active/pending and unused each have N slots. Reclaim transfers at most min(limit,N), play runs no old-resource destructors, and volume/stop use independent coalesced command slots. Service limits default to G=4 generations and R=64 queued normal jobs (maximum G=64/R=256): R+1 queued/in-flight jobs, 2G reserved teardown credits and G live/old generations. Each job/owner retains its generation until complete. Conservative unique PCM bound is (2×256×G+R+1)×64MiB, before the caller's tighter real BudgetPools. All queue metadata is preallocated. No new IO pipeline is introduced.

DecodedSound requires an owned BudgetTicket covering input vector capacity plus converted Frame storage during construction; reserve before allocating input. Its conservative charge follows the Kira Sound into deferred retirement and is released once. A rejected play returns the original DecodedSound. Sound memory is capped at 8,388,608 stereo frames per input; the caller's pool may impose a smaller aggregate ceiling. For worker-produced PCM, bounded_pcm_queue accepts 1..=96,000 frames (8 bytes/frame); empty queue frames become silence and increment output shortage accounting. It consumes no content while empty. Device xruns count separately from the number of known missing frames; CPAL supplies no missing-frame count for its Xrun event. Counters reset on successful configure.

At every normal control tick, acknowledge the host wake before draining sources and call `reclaim_unused(limit)`. Before new decode allocation, `reserve_decode_budget` attempts transfer then immediately reserves or returns Busy; it never waits for budget. Inspect progress even on Busy. Full/contended destination leaves Sound in Kira; quota exhaustion requests another turn. Empty observation is not global residency completion. Worker job counts describe destruction of those jobs; accepted aliases may still retain PCM, so the real pool remains authoritative. Completion wakes the same scheduler after destruction, including while UI sleeps. Decoding/conversion is producer work outside the control transfer deadline.

The host service outlives mixers. Each generation reserves Renderer/Manager credits before construction; ordinary work cannot consume them, and unavailable generation credit returns Busy. Fill Drop only moves Renderer; Mixer Drop only moves Manager, including an untaken fill whose worker-side Drop submits its own Renderer credit. Neither joins. Final host exit drops all control owners then explicitly calls `drain_and_join`; outstanding control owners return Busy. Service Drop safely detaches a draining worker. The maximum 64MiB capability and 128MiB construction charge remain; physical PCM destruction runs on the worker. See [the ownership and measurement boundaries](BACKGROUND-RECLAIM.md).

Clock snapshots use triple_buffer, with a Mutex only around the **control-side reader**. The callback never touches it. `generated_frames` counts software-produced frames including silence, for diagnostics. CPAL declares Unavailable: its callback has no write acknowledgement, and ALSA writei Err(EAGAIN) with frames_written==0 silently drops the generated block; actual Ok(0) retries without progress. CPAL latency/timestamps stay diagnostic. Under any Unavailable precision, submitted/presented numeric zeros are invalid, and both `submitted_frames()` and `presented_frames()` return None. They cannot anchor MediaPTS.

The controlled offline sink declares Estimated capability and supports injected timing: it guarantees submission to its sink, then estimates presentation from prior blocks minus the injected latency. The new block is never equated with presentation. A future native driver can opt into that path only after proving the submission/timing guarantees. Suspend freezes observations. Native Xrun closes entry, makes the output Failed/ReconfigureRequired, invalidates OutputEpoch and software counts, and requires control-side stop/rebuild. Failed/Stopped observations are Unavailable; every epoch change invalidates retained observations and media mappings. Playback position describes content consumption, not hardware completion.

The failed native operations in those unit fixtures are simulated output failures, not hardware measurements. Both tests of immediate native rejection assert identity of the original uncalled Box. `audio-probe` builds the production crate in debug/release and selects its exact libraries from Cargo JSON. It compiles `tests/support/pcm_probe.rs` and `reclaim_probe.rs`; production code retains unsafe_code=forbid. The PCM probe runs the real Kira mixer continuously, including a finite Sound's deferred retirement, through the normal 8ch converter. The observer records allocation/reallocation/deallocation only on the calling PCM thread, excluding setup, teardown, control notification and unrelated threads. The reclaim probe observes actual System::dealloc on the service worker and asserts that the pool remains charged immediately before and after the physical free, then reaches zero after job completion. These checks cover this data path, not arbitrary effects or every native driver's internals.

## Logical audio activities (PR #53)

The draft adds AudioActivityService over the existing Kira bridge. Requests own a ResourceVersion, complete core Scope, MediaEpoch, group metadata and DecodedSound. Fixed ledger slots reserve terminal capacity before play; refusals return the owned request. QueueLimits charges slot storage and asset-key capacity, while existing tickets retain PCM charges. IDs are unique within a service lifetime; the host must allocate a fresh epoch when replacing that service. Group is metadata only, and looping follows the supplied DecodedSound.

play/stop/set_volume_db/snapshot operate on logical activity identities. Completed observes content consumption through Playback; it does not certify hardware presentation or released PCM. Stopped settles a control command; AudioOutput still owns the supply fence and the reclaim service still owns physical destruction. This low-level terminal must not silently become the final creator media-wait completion contract.

Before cancel_owner, revoke business waits and prevent new plays for that complete Scope. Continue its bounded cursor until finished. maintain/drain charge visited slots, including holes; caller output vectors do not grow. A full destination preserves deliverable records while still charging and advancing past them to release later cancelled/stale records. After a complete scan, consumer backpressure alone does not self-wake; the consumer calls drain again after capacity becomes available. Cancelled and records whose exact admitted (MediaId, MediaEpoch, Scope) no longer identify a live wait are disposed without business delivery. Delayed results require another live-wait check. Output failure never invalidates an already-settled logical result merely because the current admission epoch changed. Completed/Stopped/Failed retain their original identity; fail_output advances the admission epoch once and settles remaining activities as Failed under their original identities. It is not successful device reconstruction. The host fences/stops the output separately.

Share a WakeSignal across output, this ledger and AudioReclaimService. Acknowledge before draining all sources and recheck pending before sleeping. Partial scans request an immediate next turn. While unsettled activities remain, poll_after recommends a 10 ms control-only timer because Playback has no per-handle completion subscription. No unsettled activity means no periodic timer from this API. This polling does not request layout or presentation and does not guarantee completion latency under overload.
