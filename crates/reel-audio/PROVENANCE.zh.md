# Reel 音频库来源

[English](PROVENANCE.md)

实现来自 2026-10-08 从 crates.io 引入的 Kira 0.12.5，源自提交 `74b3ef0fd8bd15f90e3b469208ee741f04374a62` 的 `crates/kira` 目录。保留原有的 MIT 和 Apache-2.0 许可证及源码版权声明。[tesselode/kira](https://github.com/tesselode/kira)

Reel 将代码维护在工作区包 `reel-audio` 中。本地改动包括有界地移交已退出混音的声音、解码器的预留和取消检查点、发布等待执行的跳转、保留插值所需数据的 PCM 队列，以及由后台线程填充的音频帧窗口。原生设备输出和底层 PCM 的回收由 `reel-media` 管理。混音轨道在同一遍处理中累加并清除工作缓冲区中用到的帧。

静态音源在暂停或保持时会冻结播放速率的渐变。合并后的速率命令携带确认标识。现有的播放游标同步发布还包含当前速率、固定目标速率和剩余渐变量，用于恢复播放。这些改动新增固定大小的命令与原子状态，沿用重采样器和参数插值。音频回调保持零分配，PCM 存储量保持原样。

混音在每个处理块内复用恒定的增益与声像系数。变化的参数沿用原始的逐样本插值，应用声像时也保留原来的乘法顺序。重采样在游标位于整帧时直接读取当前 PCM 样本。排队音源的采样率发生变化时，才换算游标的小数部分。

宿主读取接口与编解码器无关。共享源时间轴、解码器工厂、静态源和窗口源的准备策略都由 `reel-media` 维护。Symphonia 数据包解码器保留预留和取消检查点。媒体适配器可以提供编解码器实例。Opus 跳转在发布可听的 PCM 前，按 RFC 7845 预解码 80 ms。数据包转换复用后台线程已有的 PCM 容量，扩容前会为新旧存储并存的时段预留空间。

`tests/fixtures/short-tone.mp3` 是原创合成的 660 Hz 音调，按此 crate 的许可证分发。它的开头预充和尾部填充数据包用于测试零帧解码和文件末尾。用 FFmpeg 9.0 与 libmp3lame 可重建此文件。

```sh
ffmpeg -f lavfi -i "sine=frequency=660:sample_rate=22050:duration=0.08" -ac 2 -c:a libmp3lame -b:a 64k -map_metadata -1 short-tone.mp3
```

使用 `cargo test --locked --offline -p reel-audio --features mp3 mp3_ --lib` 检查解码器覆盖的行为。

由后台线程准备的静态音源可以批量发布连续 PCM。每路声音保有固定的 64 帧缓存，播放位置发生不连续变化时清空。四点重采样、排队音源的所有权和数据欠载时的位置均由既有播放控制处理。默认每次从音源读取一帧，宿主负责统计固定缓存的开销。
