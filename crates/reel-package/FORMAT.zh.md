# Reel ASB v1

[English](FORMAT.md) · 简体中文

ASB 包含已验证的 Aside 代码、源码元数据和可选的发行配置。编码版本为 1.0。数据模型与验证见[程序包源码](src/lib.rs)。

整数均采用小端编码。72 字节文件头依次存放 `REELASB\0`、`major:u16`、`minor:u16`、`flags:u32`、`total_len:u64`、`index_offset:u64`、`index_len:u64` 和 32 字节 BLAKE3 索引摘要。文件头的标志位为零。每项索引记录长 56 字节，包含 `kind:u32`、`flags:u32`、`offset:u64`、`length:u64` 和 32 字节 BLAKE3 载荷摘要。偏移量以文件开头为基准。

| 类型 | 载荷 | 何时包含 |
| --- | --- | --- |
| 1 | 已验证的 Aside 字节码 | 必需 |
| 2 | UTF-8 JSON 代码元数据，模式版本为 1 | 必需 |
| 3 | UTF-8 JSON `Distribution` | 导出的项目 |
| 4 | 效果定义和已链接函数绑定 | 使用已编译效果的项目 |
| 5 | UTF-8 JSON 逻辑续接与 State 表，版本为 1 | 声明 State、Root 或稳定流程的项目 |
| 6 | 视觉资源准备计划 | 有视觉资源准备计划的项目 |

类型 1 至 5 设为 `flags=1`。视觉资源准备计划设为 `flags=0`，可省略。类型不得重复，各非空区段互不重叠，且位于文件头和索引之外。解码时遇到未知的必需区段会报错。完整解码校验所有载荷的摘要，包括未知的可选区段。

写入按文件头、字节码、元数据、可选发行配置、可选效果、可选逻辑续接、可选视觉资源准备计划、索引的顺序进行。容器写入器接收不可变的序列化字节码及对应的已验证程序，并根据该共享程序校验元数据。

`Distribution` 包含可选 `text`、有序的 `resources`、`catalogs` 和可选 `loose`。文件路径相对于 ASB 目录，在准入时验证。`catalogs` 将规范语言标签映射到文本归档的逻辑条目，有目录条目时必须提供 `text`。`loose` 可以是 `Project`，使用 ASB 周围的项目资源，也可以是 `Directory(path)`，相对于 ASB 解析。发行包引用 RTP 文本和 RPK 资源卷，开发导出使用散装资源。纯代码构建可省略该区段。代码及其原始文本池决定执行身份。JSON 模式见 [distribution.rs](src/distribution.rs)。

完整解码校验区段摘要、元数据和字节码。支持 seek 的发行配置读取器只检查文件头、索引和发行配置，沿用同样的索引、JSON、路径和限额验证。资源归档由各自的加载器读取。二进制编码见 [codec.rs](src/codec.rs)。

## 效果产物 v1

第 4 区段从 `definition_count:u32, binding_count:u32` 开始。其后按表顺序存放各效果定义，每项编码为 `blake3:[u8;32], length:u64, bytes:[u8;length]`。再按 `module:u32, function:u32, definition:u32` 存放各绑定。前两项是最终链接的字节码 ID，定义索引从零开始。区段不能有多余尾部数据。定义摘要和函数绑定均不得重复，每个定义都必须被引用。被绑定的函数须属于指定模块，类别为 Plain，且没有捕获。程序包检查长度、摘要和字节码关系，再返回不透明产物。沿用现有的元数据字节、记录和工作额度。引擎在运行时准入前校验带类型的定义，程序包本身不依赖 UI。

规范定义以 `REELFXD1` 开头，后接 Postcard 元组 `(parameters, nodes, output)`，采用共享 UI 效果声明中稳定的字段及变体顺序。参数记录名称、类型和有限的 f32 默认值。节点保留有限 f32 的位型及对前序节点的引用。摘要覆盖包括前缀在内的整份定义。定义不含源码路径、HIR 函数 ID、源码范围、原生句柄或当前实例的值。引擎解码器限制表的分配容量并重建经过验证的共享 EffectProgram。剥离调试信息或重新编码 ASB 后仍保留这些产物。目标 GPU 的产物单独准备，便携定义的身份独立保存。

## 逻辑续接与 State v1

第 5 区段存放 `aside_vm::resume::ResumeTable`。稳定的流程键和位置键映射到当前函数 ID、执行字 PC 和结果槽。每个位置从所属流程的共享 `layouts` 数组选取一项，索引从零开始。Point 使用 JSON 数组 `[key, prepare, call, after_call, result, layout]`，Return 使用 `[key, callee, call, after_call, result, layout]`。Return 的 `callee` 为所声明流程的当前函数 ID。保存的帧使用这个流程的稳定键。State 和 Root 声明通过稳定键定位当前的类和入口函数。准入前，VM 对照解码的当前程序验证各位置的布局。程序包保留已验证的表。绑定外部文本池时沿用验证结果，并与执行程序共享这个文本池。JSON 与续接验证使用程序包的元数据和工作额度。省略该区段代表当前版本的空表。

发行时剥离调试信息、提取外部文本或重新编码发行包，均保留续接元数据。该表描述当前代码，逻辑存档分别保存稳定键和数据。

## 视觉资源准备计划

程序包把第 6 区段作为不透明字节处理，载荷同时受 1 MiB 和配置的元数据字节上限限制。写入时省略空计划。

载荷以 `record_count:u32` 开始，随后是对应数量的 16 字节记录，末尾为 `u32` 字符串常量 ID 数组。记录按 `(function_id, word_pc)` 排序。每项记录为 `function_id:u32, word_pc:u32, first_id_index:u32, id_count:u32`，其中索引相对于尾部数组。数量为零表示普通返回，查询可以继续到调用方。引擎在绑定外部文本池后，对照已验证程序检查引用。

## 资源与文本归档 v1

RPK 和 RTP 使用相同的可 seek `REELPAK\0` v1 格式。32 字节头为 `magic:[u8;8], version:u32, kind:u32, index_offset:u64, entry_count:u64`。资源的类型为 1，文本的类型为 2。主索引一直写到文件结尾。各条目有序排列，格式为 `path_len:u32, offset:u64, logical_length:u64, blake3:[u8;32], stored_length:u64, directory_offset:u64, storage:u32`，后接 UTF-8 路径。偏移量以文件开头为基准。摘要覆盖逻辑输入字节。

存储方式 0 使用连续原始字节，存储长度和逻辑长度相同，目录偏移为零。存储方式 1 将逻辑内容分为独立的 64 KiB 块，末块可更短。目录位于各存储块载荷之后，每项长 16 字节，包含 `relative_offset:u64, stored_length:u32, codec:u32`。偏移量相对于条目载荷起点。编码方式 0 使用原始块，方式 1 使用裸 LZ4 块。通过条目长度推导各块的逻辑长度。压缩块必须小于原始块。目录紧随存储载荷，含 `ceil(logical_length / 65536)` 项。

挂载只读取文件头和主索引，并检查存储范围和目录大小。范围读取只取所需的目录记录和块，校验范围和编码方式，再用可复用的 128 KiB 工作区解码。在 I/O 分块和块处理之间检查取消。工作区的解码部分以逻辑内容摘要、长度和块索引标识最近一次解码成功的块，连续的小范围读取可以省去重复 I/O 和解码。解码覆盖工作区数据前撤销上一缓存身份，只有成功解码到准确长度才发布新的身份。

写入器接受长度未知的输入流，增量计算逻辑输入摘要，仅保留块记录和固定的载荷工作区。无法压缩得更小的块使用原始数据。没有压缩块的条目最终使用连续原始字节。调用者也可以指定已压缩的内容使用原始存储。
